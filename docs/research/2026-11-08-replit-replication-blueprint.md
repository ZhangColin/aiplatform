## 一、为什么写这份文档（动机与事实底账）

### 1.1 现实

- 优化前基线（锚案例 376467559906353574）：PRD 梳理 4min → 净生成 **1h50m**（13 片、并行度 2、
  10 flash/2 pro、77 张收尾卡零拒绝）。当时判定 1h50m 不可接受，立项提速。
- #416 批次（三闸＋观测地基＋基座健壮件＋路由修复）上线后，同 PRD 重触发
  （377362389304187109）：**全程 6h19m**——比基线慢 3.4 倍。
- 用户长期使用 Replit 的实证（多个项目含大型）：① 简单需求初始化，30-60min 出系统，
  界面美观、功能齐全；② 修改需求几分钟到十几分钟有结果；③ 产出是可用、真实的系统。
- 本平台多个产出被评「实现过于简单、功能不可用」——**验证花了几倍时间，质量没买来**。

### 1.2 同口径对照（本轮实测 vs 基线）

| 维度 | 基线 376467559906353574 | 2026-11-07 实测 |
|---|---|---|
| PRD 梳理 | 4min | 25s（PRD 现成，非平台能力） |
| 片数 | 13（含阶段0） | 11（更少更大） |
| 净生成（确认→全片收口） | 105m40s | ~4h56m |
| 一次过率 | 全部首试首过、零拒绝 | 4 次硬门拒绝＋1 次空转拒绝＋1 片失败转中断 |
| 合并冲突 | 全库 45 次 fork 合并 0 冲突 | ≥2 次（真冲突裁决长尾 2h20m、fork diff 缺失误处置重跑） |
| 实测并发 | 2（=理论宽度） | 1（wave 全 serial） |
| 档位 | 10 flash / 2 pro | 24 pro / 1 flash（1806:65 调用比） |
| 终验 | 无 | 1h20m（4 旅程＋1 修复轮） |
| 交付后质量 | 首触 redis 挂死＋返修 2 轮 | 终验全绿＋预览即开 |

### 1.3 教训（这轮改动为什么事与愿违）

1. **验证没有「重构」成终验，而是「叠加」**：基线 1h50m 里本就有 56.9min verify（#411 实测）；
   落地后片级 verify 照跑＋硬门拒轮重跑×5＋终验净新增 1h20m → 验证总时长翻倍。
2. **闸的安装姿势错误**：每个闸以「新增一个会失败的环节」接入，失败全靠整轮重跑消化
   （拒绝未喂回同 run，决策原文被落地背叛）。
3. **验证查的维度错了**：主径点得通 ≠ 业务做全、做得好看。**质量是生成时生产出来的，
   不是事后验出来的**；检测环节查不出深度。
4. **切片把质量所有权切碎了**：11 个互不知晓的执行体各对任务句交差，波宽实测只有 2-3、
   加速比 1.3x——用质量碎片换了一点并行。
5. **空窗重现**：锚案例教训「7h 感知的制造者是质量失败＋空窗＋平台挡道」，本轮片失败转
   中断后 25min+ 无人续跑，空窗原样重现。

## 二、Replit 机制全解（复刻对象）

> 完整证据见 #412 报告；此处只收机制要点与我们的判读。

### 2.1 架构四杠杆

1. **并行任务＝隔离副本**：任务跑在「当前项目的精确副本」里，Kanban 独立推进，主项目
   不被触碰，用户 review-then-apply。并发配额 Starter 0/Core 1/Pro 10/Enterprise 64。
   **冲突 90% AI 自动解、10% 上抛用户**。代价（口碑实证）：merge 互毁、审批疲劳、
   单位任务 token ~2x。
2. **「一个 agent」＝专用模型流水线**：exploration/testing/parallelism 各一个专用模型；
   多供应商（GPT-6 系/Claude 系/Kimi K3）＋ **Auto 智能路由**（按任务真实难度选模型）
   ＋ **Effort 档**（per-model 推理投入 Low→Max，最难任务成本上限 ~2x，简单任务几乎不加钱）。
3. **decision-time guidance**：轻量分类器**每个 agent 迭代**判定轨迹，注入微指令
   （并行工具调用 +15%/loop；静态塞系统提示词无此增益）。反 mock、反危险删除都是这类
   微指令。提醒超三四条收益递减。
4. **checkpoint 全状态快照**：代码＋数据库内容与 schema＋AI 会话上下文＋agent memory，
   双向回滚，按「一请求一 checkpoint」计费，每 checkpoint 对应一 git commit。

### 2.2 验证策略＝智能触发，不是终验门

- App Testing：真浏览器自测（输 mock 数据、自动分析修复、视频回放），官方明说
  「doesn't test after 100% of user messages, but intelligently determines when testing
  would be most valuable」。
- 自测工程底座（Agent 3 时代）：REPL code-use——**写 Playwright 代码跑浏览器而不是逐工具
  调用**（36 次翻页＝一次模型调用生成代码循环），notebook 持久化「context stays in code,
  not in tokens」，测试独立子代理隔离上下文，中位 $0.20/场。
- 安全面（Semgrep＋威胁建模）是用户触发件；**首版默认无鉴权/限流/密钥管理**（三来源一致）。
- 做对率口碑双峰：正评带「首版可用有小瑕疵」（错误首试自愈率 ~75% 一手）；负评带
  「缺大块功能/结构混乱/merge 互毁/循环卡死」。

### 2.3 时长分布（一手实测带，复刻的参照系）

| 场景 | 实测 |
|---|---|
| 简单（landing/小工具） | 3-15min |
| 中等（auth+DB+Stripe） | 30-50min |
| SaaS 级 | 2.5-4h 含显著人工调试 |
| 迭代段 | 小改动 10-30min 起步（Agent 3 时代同款 52s 的对照警示） |

**结构判读：首版快、迭代慢是 Agent 4 的形态**——并行＋隔离副本让首版齐头并进，但每次迭代
走「任务计划→隔离副本→审批 Apply」全环。它的快主要来自**没有切片采访仪式＋强模型＋
全托管预置环境**，并行是次要因子（Core 配额只有 1）。

### 2.4 基础设施

全托管预配置环境（标准 Agent 免配环境）；执行底座 Restate（durable steps、嵌套子代理
durable cancellation、guardrails 每步落账）；LangGraph 编排（单 trace 15k spans、主上下文
<100k tokens 无压缩）；Design 画廊设计模板（设计起点，非工程脚手架）；Skills 走 agentskills.io
开放标准；Steer/Queue（运行中插话注入当前 turn，一等能力）；Routines（定时知识工作，
确定性优先）；Connectors 生态。

## 三、Lovable 可借清单（#413 要点）

- **单消息 agent 循环**（非切片）＋ **frontend-first**（先假数据跑界面、需持久化才接库）：
  首版 5-15min（口径是前端原型）。
- **厚模板**：TanStack SSR＋Workers＋Vitest 预置＋规则注入＋Cloud 基座＝模型只写功能。
- **验证是点菜式**（only when you ask）不赌一次做对——**每切片自动冒烟＋终验是我方当时的
  差异化判断，本轮实测后该判断存疑**。
- 2026 年中有口碑恶化窗口（credits 30-35→100+）——**厚模板省 token 是成本线的一部分**。

## 四、复刻蓝图（目标形态）

### 4.1 核心形态一句话

**一个强模型 agent，在一份不切碎的上下文里，对整个产品的质量负全责，从骨架到全功能
单 run 建完；验证是生成时的自测（写代码跑浏览器、智能触发），不是事后的门；基础设施
让每个迭代都便宜（checkpoint/steer）。**

### 4.2 形态对照（现在 → 目标）

| 面 | 现在 | 目标 |
|---|---|---|
| 生成单元 | PRD→切片计划→11 片 fork/波/合并 | 单 run 全应用直建（大型构建才可选切片） |
| 质量责任 | 每片执行体对任务句负责 | 单 agent 对整个产品负责（协议写入） |
| 验证 | 三道硬闸＋整轨终验（事后检查） | 自测 code-use（生成时，智能触发）＋收尾自检清单 |
| 模型 | deepseek flash/pro，文件面路由 | 多供应商强模型池＋Auto 按任务难度路由＋Effort 档 |
| 效率件 | 静态系统提示词＋交接注入 | decision-time 微指令（每迭代） |
| 迭代 | 意见→主智能体轮→更新 run→切片 | Steer 注入活上下文，分钟级 |
| 状态 | git 版本流 | checkpoint 全状态（代码＋DB＋会话）双向回滚 |
| 环境 | 单容器全栈（app+pg+redis） | 保留（这恰好是优势：真实落库天然可得） |
| 脚手架 | 基座四件套 | 厚模板＋design token＋设计画廊（美观的第一来源） |

### 4.3 八项机制清单（复刻的「是什么」）

1. **Full-build 单 run**：读需求直接开工；增量提交（每完成一个用户旅程一 commit）；
   过程即预览（工作区活着，全程渐进可见）；run 预算大（迭代上限 1000+，单场 2h 可配）。
2. **质量协议（生成时生产质量）**：执行体身份＝全应用质量负责人；PRD 逐项变内嵌 checklist；
   反最薄实现（业务规则完整实现，不许只通主径）；反 mock 交差；外观消费设计 token。
3. **模型流水线**：三任务型（构建/修复/探索）分池；Auto 路由按真实难度；Effort＝轮次预算，
   超预算降档续跑而非作废。
4. **Decision-time 微指令**：每迭代轻量判定注入，首批四条：反 mock、反最薄、并行工具、
   大文件读后裁剪。
5. **浏览器自测 code-use**：agent 写 Playwright 脚本跑真浏览器（不逐工具调用），notebook
   式持久化；触发＝构建自然停顿/出错后/用户要求；结果＋录屏进收尾卡。
6. **Checkpoint 全状态**：按旅程里程碑自动打；双向回滚含 DB；断点续跑从最近 checkpoint。
7. **Steer/Queue**：运行中插话注入当前 turn 或排队；小改动分钟级回路。
8. **设计起点**：design token 全套＋高质量页面骨架画廊；模型只写功能，美观由模板保底。

### 4.4 分期实施（复刻的「怎么建」）

**Phase 1 单 agent 全应用直建（核心手术，1-2 周）**
停：切片强制化/波/fork/合并/三道硬闸（legacy 开关保留）。建：full-build 轨；run 预算调大
＋compaction 真实 token 计；强模型池接入＋Auto 路由＋Effort；decision-time 微指令；
checkpoint 补 DB 快照。
**验收：同 PRD 首版 ≤60min，预览全程可见；与 Replit 产出盲对比。**

**Phase 2 质量生产化（2 周）**
质量条进协议；浏览器自测 code-use 智能触发；全局打磨 run（首版后自动一场，预算 15-20min，
这是原终验预算的置换）；设计画廊。
**验收：连续 3 项目无「过于简单/不可用」级缺陷；自测成本落遥测。**

**Phase 3 迭代回路（2 周）**
Steer/Queue；迭代轨重写（进活上下文，目标 ≤15min）；checkpoint 回滚产品化。

**Phase 4 观测与终裁（持续）**
每项目落：首版时长/迭代均时/模型成本/自测触发率与检出/质量评分。3-5 项目后裁决：
切片轨退役与否、验证形态去留——**全用数据**。

### 4.5 明确不抄（反面教材，均有口碑证据）

- **Effort/按 checkpoint 计费**：$140/13min、$8k/月失控是头号抱怨；我方按 run 计量。
- **并行一切的默认**：merge 互毁投诉、审批疲劳；并行按用户档位给。
- **砍验证的极端化**：「智能跳过」滑成「Potemkin interface 靠用户发现」；我们的自测保留，
  只是从「门」变「生成时的动作」。
- **过程可见性倒退**（thinking trace 移除类）：与我们过程呈现产品观相悖。
- **首版无鉴权/密钥裸奔的默认**：安全件做成生成协议的默认条目，不做成触发件。

## 五、关键指标与对照带

- **首版带**：简单 3-15min / 中等 30-50min / SaaS 2.5-4h（Replit 一手带＝目标参照）。
- **迭代带**：小改动 ≤15min（我们要优于它的 10-30min 现状）。
- **质量带**：产出与 Replit 同 PRD 盲对比，美观/功能完整度/可用性三维评分。
- **成本带**：单项目模型成本落库可观测，Effort 预算封顶。
- 全部指标按项目落遥测，裁决只看分布不看单次。
