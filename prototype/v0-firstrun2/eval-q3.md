- **旧应用**：查看类功能（库存看板、首页预警、盘点差异表、报表）都完整可用，数据质量过关；但 **商品新建/编辑、入库新建、出库新建这 4 个表单页在浏览器里打不开**（页面对应的 JS 文件返回 HTTP 500，页面显示「页面加载失败」），所以「建档→入库→出库」这三步在界面上走不通，只能靠后台代码和已有数据推断。

## 六、缺陷与问题

### 旧应用

1. **严重：4 个表单页在浏览器里不可用。** `/products/new`、`/products/1/edit`、`/inbound/new`、`/outbound/new` 的页面 HTML 能返回，但页面依赖的 3 个 JS 文件（`2-jotapbcbp4r.js`、`26vrn4rmaqnu4.js`、`1fi68alcnu60v.js`）请求返回 **HTTP 500**，浏览器报 `ChunkLoadError`，整页被错误边界替换成「页面加载失败 / 可能是数据库连接抖动… / 重新加载」（截图 `02-products-new.png`、`05-inbound-new.png`、`08-outbound-new.png`）。原因（查进程和文件时间得出）：正在运行的 `next-server` 是 11-21 12:52:14 启动的，而 `.next` 构建产物是 12:55:01 又重新写了一遍（生成过程被截断前又跑了一次构建），运行中的服务还拿着旧构建的文件名，磁盘上已经是新构建的文件，所以对不上。重启服务大概率能修，但本次不允许重启，没有验证。它自己的 `docs/ACCEPTANCE.md` 写着「静态资源 17 个全部可加载」「建档/编辑均可用」，与现状不符（那份文档是 12:54 写的，在最后一次构建之前）。
