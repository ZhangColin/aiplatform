# 竞品生成器风格多样性与质量底线机制调研（#567）

- 日期：2026-11-21
- 服务对象：wayfinder 调研票 #567（地图 #564「机制取舍」）——竞品证据面三问：①风格多样性与一致性如何做到／是否需要避免千篇一律；②裸生成后有无平台级质量底线（build／探活／smoke 类校验由谁执行）；③典型首建时长。
- 背景：本平台四腿对照实验实证——自家堆叠的生成机制净贡献为负（37-62min），纯 LLM 直写（腿④ 18min，模型自主产出有设计感的深色科技风）反而更快更好。本报告为「机制取舍」决策提供竞品对照证据。
- 取证纪律：官方文档／changelog／官方博客／官方开源仓库源码＝**A 级**；官方团队成员公开发言＝**B 级**；社区多方一致＝**C 级**；社区孤证＝**D 级**。每条附来源 URL，调研日 2026-11-21，优先现行口径并注明功能变迁时间线。
- 覆盖产品：v0（Vercel）、Lovable、bolt.new（StackBlitz）、DSH（身份确认见 §0：判读＝DeepSeek Harness，附 DeepSite 备选取证）、同类补充 Replit Agent（Base44／Create.xyz 略查）。

## 结论速览

1. **风格面：头部竞品不靠「前置风格机制」保多样性，反而正在退出这类机制。** 三家（v0／Lovable／bolt）项目内一致性都靠**强默认栈**（React 系＋Tailwind＋shadcn 组件生态）天然成立；代价是跨项目趋同成为社区公认现象（「Lovable look」「AI web apps look the same」，C 级多方）。唯一做过「主题候选集」（首建前三方向预览）的 Lovable 已于 **2026-10-08 把首建前设计方向移除**（改为直接按描述构建），Themes 跨项目主题功能也在上线约 4 个月后（2026-03-16）以「low usage and performance issues」官方下线（A 级）——前置风格选择在头部竞品处是被试错淘汰的形态。多样性的主流答案是**模型自由发挥＋用户带资进组的可选强引导**（设计系统导入／Figma／主题定制），bolt 更是在 system prompt 里直接下反模板指令（"Avoid generic or templated aesthetics at all costs"，开源源码一手）。
2. **质量面：构建／探活类校验是商业产品标配且普遍平台强制；深层测试普遍按需或模型自主。** v0＝流中错误检查＋AutoFix 专任模型＋终态 linter＋预览跑 Vercel Sandbox 真实构建（官方工程博客 A 级）；Lovable＝每条消息平台构建、失败 build 锁死发布闸、Try to fix 模型修复、发布前自动安全扫描（A 级）；bolt＝WebContainers 内必须真实装依赖起 dev server 才有预览（执行级探活）；Replit＝免费自动依赖漏洞扫描＋Agent 真实浏览器自测（Agent 自主决定时机）。零校验纯单次生成只存在于开源玩具级形态（DeepSite）。Lovable 官方对深层验证的定位与本仓既有结论（[2026-11-06 Lovable 全能力面](2026-11-06-lovable-capability-deep-dive.md)）互证："Most verification tools run only when you ask for them"。
3. **时长面：官方口径普遍「分钟级」且刻意模糊，本平台腿④ 18min 落在竞品区间内。** v0 官方「Generate working applications in minutes」＋发布 30-60s；bolt 官方教程首建约 5 分钟；Lovable 无官方数字（社区 30s-3min，属前端优先原型口径）；Replit Lite 小改 10-60s、像样首版分钟到 30 分钟级；DSH 官方演示 5m24s、中文实测约 11 分钟。
4. **对机制取舍的直接启示：竞品证据与本平台实验同向。** 风格面不该建机制——竞品正退出前置风格机制，多样性靠模型自由＋可选引导，本平台风格方向库／规范三件套属被竞品证伪的形态；质量面值得把「能跑」做成平台级兜底——腿④里模型「自写 smoke→build→起服」的自主行为，恰是竞品用平台固化下来的那一层（成本远低于风格机制、收益有竞品共识背书）。

## 0. DSH 身份确认

**判读：DSH＝DeepSeek Harness（DeepSeek 官方开源 agent harness，CLI 命令 `dsh`，仓库 [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)，npm 包 `@deepseek-ai/dsh`），中等偏高置信。**

依据（A/C 级）：

- 字面与生态实证：「dsh」字面落在 DeepSeek Harness 的产品标识上（CLI／npm 包名）；社区大量实证把 DSH 用作其缩写（「awesome DeepSeek Harness (DSH) plugins」、DSH 插件市场等，C 级多方）。**未检索到任何把 DeepSite 缩写为 DSH 的实例**。
- 本仓地图 #564 的自家用法印证：「腿④无 DSH、无插件、无 skill」「DSH 对照＝纯 LLM 能力而非 harness 魔法」——语境（插件、skill、harness）与 DeepSeek Harness 的插件架构逐一吻合，与 DeepSite（单页网站生成器）不合。
- 时间线吻合：DeepSeek Harness 2026-08-13 开源（v0.1 developer preview，MIT），中文社区热度峰值期与竞品清单写作窗口重叠。

因无法排除清单作者另有所指，下文对备选读法 DeepSite（Hugging Face 生态开源网页生成器）一并按同框架取证——它恰好提供「零校验纯生成」的对照样本，两个读法都有证据价值。

## 1. v0（Vercel）

### 1.1 风格多样性与一致性

- **强默认栈＝一致性保证本身（A 级）**：官方文档明言 "v0 uses Shadcn/ui as its default component system to generate high-quality, customizable UIs"，且模型 "specifically trained on the default implementations of the shadcn/ui components and may struggle with any customizations"（对 shadcn 默认实现专门训练，定制反降质）。默认栈＝Next.js＋React＋TypeScript＋Tailwind＋shadcn/ui。来源：<https://v0.app/docs/design-systems>、<https://v0.app/docs/faqs>。
- **不做主题候选集／多方案风格引导**：现行产品无「一次出多版风格」形态（早期 v0.dev 生成三选一已淘汰，未见官方迁移声明，按现状呈现）。风格多样性入口只有：用户提示词、截图/Figma 导入、Design Mode 视觉微调、自定义设计系统。
- **风格引导分层（A 级）**：①无引导默认（shadcn 默认主题）；②主题定制通道——自定义 registry 改 `tokens.css` 色板变量与字体，官方直接推荐 ui.shadcn.com/themes 与第三方 tweakcn.com 选主题（<https://v0.app/docs/design-systems>）；③**Design Systems 2.0（现行主推）**——团队设计系统导入为 skill（npm 包／GitHub 仓库／Storybook／Figma 帧），导入时 "builds a starter app to verify it understands your system"，之后每个新 chat 从该 starter 起步，支持团队级默认（changelog 2026-06-08 重建、2026-07-07 团队默认；<https://v0.app/docs/design-systems-2>、<https://v0.app/changelog>）；④Figma 整文件导入（付费）；⑤Design Mode 预览点选微调。
- **跨项目趋同是默认栈的代价**：全部用户共享同一套 shadcn 默认审美，官方无「防趋同」机制；持续跟进 shadcn/Tailwind 生态（changelog：2025-10-03 新 shadcn 组件 Day-1 支持、2026-02-18 Tailwind 4.2、2026-03-09 新增 Nuxt 按需支持）而非自造风格系统（A 级，<https://v0.app/changelog>）。

### 1.2 质量底线——平台强制多层管道（本次调研最重口径）

- **流中检查＋AutoFix 专任模型＋终态 linter（A 级，官方工程博客）**：《The v0 Composite Model Family》（2025-06）——base model 流式输出期间持续检查 errors/inconsistencies/best-practice violations，AutoFix 模型（vercel-autofixer-01，RFT 训练）mid-stream 修复；流结束后 final pass 并**执行 linter** 修 style inconsistencies；Quick Edit 专任小模型处理小改动；配套 error-rate evals。来源：<https://vercel.com/blog/v0-composite-model-family>。这是「模型自检被平台管道化」的官方一手表述。
- **自动错误修复（A 级）**："When v0 detects errors in your project, it can diagnose and fix them automatically as part of the generation loop"，覆盖缺文件/依赖、语法格式、运行时错误、import/export 四类。来源：<https://v0.app/docs/agentic-features>。
- **预览＝真实构建（A 级）**：2026-02 起预览跑在 Vercel Sandbox（轻量 VM），"Previews now run your code exactly as it would in production"，内含 framework-aware dev server；官方 FAQ 自认因此变慢（"real builds… takes a bit more time than before"）。来源：<https://v0.app/docs/sandbox>、<https://v0.app/docs/faqs>。
- **部署面**：Fix with v0——部署报错时按钮触发自动诊断修复（付费计划每日免费额度）；GitHub 集成下可见 CI checks 并可被要求修复。来源：<https://v0.app/docs/agentic-features>、<https://v0.app/docs/github>。
- **安全面（A 级）**：changelog 2025-12-09——React2Shell CVE（CVE-2025-55182）当天自动扫描全部用户项目并自动提交修复 PR。来源：<https://v0.app/changelog>。
- Agent 可自开浏览器使用生成物："use them, critique designs, debug complex flows, and fix things proactively"（A 级，<https://v0.app/docs/agentic-features>）。

### 1.3 生成时长

- 官方首页："Generate working applications in minutes with AI. Publish as live websites in seconds."（A 级，<https://v0.app>）；Quickstart："Wait for publishing - usually 30-60 seconds"（A 级，<https://v0.app/docs/quickstart>）。
- 官方未公布「典型首建」精确数字；社区口径首版分钟级到 1 小时视复杂度（C 级）。性能投入佐证：changelog 2026-05-12 "Sandboxes start over 50% faster on new chats"（真实构建的成本面）。

### 1.4 存疑/未找到

- v0 "Checks" 独立功能（severity rating＋suggested fix）在官方 changelog 搜索摘要可见，但页面动态加载未能定位条目与日期——功能存在性可信、细节存疑，不作为结论依据。
- AutoFix/linter 管道 2025-06 博客之后的架构演进未见官方一手更新。

## 2. Lovable

### 2.1 风格多样性与一致性

- **默认栈（A 级）**：样式恒用 Tailwind；2026-05-13 起新项目用 TanStack Start（SSR），旧项目 React＋Vite；shadcn 组件库属模板既有事实（changelog 2024-12-03 shadcn sidebar 条目、第三方归纳 React+Vite+Tailwind+shadcn+Supabase，C 级）。来源：<https://docs.lovable.dev/introduction/faq>。
- **「主题候选集」的试错史（A 级，对机制取舍最有价值）**：
  - **Design guidance**（2026-05-18 上线）：视觉开放型 prompt 下先给 3 个轻量 HTML+Tailwind「design directions」预览供并排比较，或发起 design questions（字体按气质分组、色板按 mood 分组、布局线框选项）→选择后生成 design brief 作为构建规格；prompt 已明确视觉方向时直接构建。来源：<https://docs.lovable.dev/features/design-guidance>。
  - **2026-10-08 changelog："Removed: design directions before the first build——三个预设计方向已移除，Lovable 直接按描述构建外观"**，prompt 留白时仍会问 design questions。现行文档页与该移除条目存在张力（疑文档滞后），已如实标注。来源：<https://docs.lovable.dev/changelog>。
  - **Themes**（品牌级 colors/typography/spacing 跨项目套用）：2025-11-26 上线 → **2026-03-16 移除**，官方理由 "low usage and performance issues"（同上 changelog）。
- **现行最强引导＝Design systems（A 级）**：设计系统本身是一个 Lovable 项目（组件库＋tokens＋机器可读 schema），attach 后组件拷入、依赖合并；一致性两层强制——①attach/更新后自动 setup verification（"checks the wiring… and fixes anything missing"）；②"every generation is scanned for violations of the design system… Lovable automatically retries to correct them before finishing the generation"（裸色值／绕 token 一次性值／违规 inline style／重复造组件四类违规）。2026-08-19 起开放全部付费档。来源：<https://docs.lovable.dev/features/design-systems>。
- **「Lovable look」社区公认（C 级）**：r/lovable "How do you guys do to not have the standard lovable design? you know like the 6 rectangles?"（<https://www.reddit.com/r/lovable/comments/1m20yfk/>）；官方旁证：changelog 2025-12-10 自述 "Lovable's generated designs are now more creative and polished"（隐含此前偏套路，A 级）。
- 其他：Visual edits（2025-02-12）→ AI 化（2026-04-02）→ 被 preview toolbar 取代（2026-06-10）；Knowledge/Instructions、workspace knowledge、project memory（2026-10-30）承担项目内规则沉淀（A 级 changelog）。

### 2.2 质量底线——平台强制构建＋模型化修复（与既有报告互证）

- **平台每条消息构建＋采集运行时面（A 级）**：changelog 2026-08-06 官方自述 "Lovable still builds and tests your changes, and still sees runtime errors, console output, and network requests from the built preview"；agent-mode 文档 "Behind every message, Lovable's agent works in a loop: it gathers context…, takes action with tools, and checks the result before moving on"、"When using Build mode, Lovable does more than ensure code compiles"。来源：<https://docs.lovable.dev/changelog>、<https://docs.lovable.dev/features/agent-mode>、<https://docs.lovable.dev/features/projects/chat>。
- **错误检测平台浮出＋修复模型执行（A 级）**：构建错误出现时活动卡浮出 "Try to fix" 按钮，"Lovable scans the logs, finds the issue, and attempts a fix"；免费 10 次/24h 回滚制（2026-08-11 起）。**发布闸：失败 build 锁死发布**（"While the latest build fails, the Publish dialog also blocks publishing"）。来源：<https://docs.lovable.dev/features/projects/chat>。
- **深层测试点菜式（A 级）**：browser testing "selective, after trying faster verification methods first"；frontend tests（Vitest+RTL）/edge tests（Deno）"run only when requested"——与本仓 [2026-11-06 报告](2026-11-06-lovable-capability-deep-dive.md)结论 4（"verification does not run silently in the background"）一致。来源：<https://docs.lovable.dev/features/testing>。
- **例外：规则变更自动写测并先跑后报（A 级）**：changelog 2026-10-16——"adds a small test when you add or change a rule in your app… It runs the tests that cover the change before it reports the work as done"。
- **发布前安全扫描平台自动（A 级）**：Basic scan（RLS/权限/依赖漏洞）"runs automatically when you open the publish dialog"（2026-06-01）；auto-fix 为 opt-in。来源：<https://docs.lovable.dev/features/security>。
- 设计系统一致性校验也平台自动（每代扫描＋自动重试修正，见 2.1）。

### 2.3 生成时长

- 官方无量化承诺：FAQ 仅答 "It depends on complexity"；changelog 2026-05-18 旁证 "Project creation can take more than ten seconds"；单条 Build 消息上限 10 小时（2026-08-26 起；2026-02-05 曾为 15 分钟）。来源：<https://docs.lovable.dev/introduction/faq>、<https://docs.lovable.dev/changelog>。
- 社区多方一致（C 级）：首版 30s-3min（<https://kevinamayi.com/learn-how-to-build-an-app-with-lovable>、<https://tensoria.fr/en/tools/lovable-no-code-app-builder>）；注意口径差——此为前端优先原型（既有 11-06 报告结论 1 已确证「首版 5-15 分钟出的是前端优先原型」），到可用含迭代普遍另计 1-2 小时。

### 2.4 存疑/未找到

- 官方单句「每次生成后必跑 build」的直白声明未找到（由四点合围佐证：agent loop check／build 错误浮出／发布闸／关 live preview 仍构建测试）。
- design-guidance 文档页与 2026-10-08 移除条目的口径张力未能裁定。
- shadcn 是否仍为 2026-11 新模板默认组件库：现行文档不再明写（历史 changelog 确证曾内置于 React 模板）。

## 3. bolt.new（StackBlitz）

### 3.1 风格多样性与一致性

- **默认形态：prompt 级反模板指令推 bespoke 多样性，无强制样式栈（A 级源码）**：现行默认 system prompt（[bolt.diy 仓库 `app/lib/common/prompts/new-prompt.ts`](https://github.com/stackblitz-labs/bolt.diy/blob/main/app/lib/common/prompts/new-prompt.ts)，2026-11 抓取）无任何 Tailwind/shadcn 强制，代之以 `<design_instructions>`："Create breathtaking, immersive designs that feel like bespoke masterpieces, rivaling the polish of Apple, Stripe, or luxury brands"、"**Avoid generic or templated aesthetics at all costs; every design must have a unique, brand-specific visual signature**"；技术要求 3-5 个 evocative 色＋中性色、body 18px+／标题 40px+、现代无衬线配优雅衬线、8px 网格、WCAG 2.1 AA。
- **一致性靠用户侧可选注入（A 级源码）**：`DesignScheme { palette（11 个语义色角色）, features, font }` 可在设置面板持久化，prompt 末尾注入；未提供时指令模型自创 bespoke palette。
- **预载设计系统三选＋企业导入（A 级）**：聊天框可选 Chakra／Material UI／Shadcn 预载设计系统起项目；Teams 计划可导入自有组件库（Storybook 视图、按名引用、版本同步）——官方明说不用设计系统时产出是 "stand-in code"／"generic template"。来源：<https://support.bolt.new/design-system>。
- 官方模板体系约 24 个（10 类目，风格气质各异），"Fork one and make it yours"；另有 Figma／Google Stitch 导入通道。来源：<https://bolt.new/resources/templates>、<https://blog.stackblitz.com/posts/bolt-templates>（2025-07-24）。
- 取证边界：bolt.new 商业版已闭源（原官方开源仓库 stackblitz/bolt.new 2024-12-17 停更，GitHub API 实证），bolt.diy 为同源社区延续（2026-11 仍活跃）——一手源码但非商业版现行 prompt，已区分标注。

### 3.2 质量底线——执行级探活、无平台 lint/build 强制口径

- **WebContainers 真实运行＝唯一可证的平台级校验（A 级）**：生成物必须在浏览器内 Node 运行时真实装依赖、起 dev server 才有预览（prompt 规定 package.json 先行写全依赖、`start` action 恒为最后动作）——「预览能跑」本身就是执行级探活。来源：<https://support.bolt.new/get-started/intro-bolt>、<https://blog.stackblitz.com/posts/introducing-webcontainers>、new-prompt.ts。
- **未找到平台强制 build/type-check/lint 的任何公开口径**（帮助中心／博客／开源源码均无）——质量兜底＝dev server 实跑报错回灌＋模型自主修复，与 v0 的平台级管道形成对照。
- prompt 内置数据安全纪律（Supabase 场景）："DATA INTEGRITY IS HIGHEST PRIORITY"、禁 DROP/DELETE、每变更 migration+query 双动作、RLS 强制开（A 级源码）。

### 3.3 生成时长

- 官方 QuickStart："**Wait approximately five minutes while Bolt creates your app**"；整程预算 10-15 分钟；部署 "about a minute"。来源：<https://support.bolt.new/get-started/quickstart>（A 级）。
- 模板路径约 1 分钟上线（官方博客）；token 侧证：免费档每日约 300k tokens，quickstart 示例首建耗约 70k+。

### 3.4 存疑/未找到

- 商业闭源版现行 prompt 无法直接取证（见 3.1 边界声明）。
- 平台级 lint/build 强制：未见公开口径，按「未见」如实呈现。

## 4. DSH

### 4.1 主读法：DeepSeek Harness（通用 agent harness）

- **产品定位（A 级）**：官方产品页自我介绍为通用开源 harness（"Everything is a Plugin" 架构），能力面含 "Explore repos, fix bugs, build features, and run tests"；平台层**无风格引导／设计系统机制**，风格由所用模型＋插件生态决定（OpenDesign 集成、社区设计 Skill 共享设计系统＋Design Token，C 级）。来源：<https://www.deepseek.com/en/harness>、<https://github.com/deepseek-ai/deepseek-harness>。
- **质量底线：能力有、非平台强制管道**——agent 可跑 bash/typecheck/tests（模型自主行为），平台只提供权限边界（workspace-write 变更边界＋审批策略，B/C 级）。社区负面孤证存在（"3 次运行声称完成仅 1 页生效"，D 级）。来源：<https://www.deepseek.com/en/harness>。
- 这与地图 #564 定性二「DSH 对照＝纯 LLM 能力而非 harness 魔法」相互印证：DSH 的效果来自模型＋最小工具循环，harness 层不做质量管道。

### 4.2 备选读法：DeepSite（HF 生态开源网页生成器，零校验对照组）

- **风格（A 级源码）**：开源 Space 仓库 [enzostvs/deepsite](https://huggingface.co/spaces/enzostvs/deepsite) 的 `lib/prompts.ts` 对风格的全部指令仅 "always with a modern and clean design"＋强制 Tailwind＋Lucide——**无任何多样化机制、无主题选择、无设计系统**；跨项目风格天然趋同于 Tailwind 系「现代简洁」审美；项目内一致性靠增量编辑（FOLLOW_UP prompt 强制 SEARCH/REPLACE 局部修改）。作者在官方讨论区亲自确认风格一致性责任在用户侧（工作流＝用户把已生成 HTML 回插再要「同风格再出一页」，#173，2025-06）。来源：<https://huggingface.co/spaces/enzostvs/deepsite/raw/main/lib/prompts.ts>、<https://huggingface.co/spaces/enzostvs/deepsite/discussions/173>。
- **质量底线：零校验纯单次生成（A 级源码推断）**——输出协议只有新文件全文与 SEARCH/REPLACE 补丁两类，无任何 build/测试/lint 环节；生成物直接在预览 iframe 渲染，语法错误的兜底就是「预览呈现错误效果」。
- 价值：作为「无机制极端对照组」，DeepSite 证明了纯 prompt＋零校验的下限形态长什么样——商业产品无一如此（见 §6 对照表）。

### 4.3 生成时长

- DeepSeek Harness：官方产品页演示一个完整插件（写码→安装→验证）"**Took 5m 24s**"（A 级，<https://www.deepseek.com/en/harness>）；中文实测自定义 Agent 创建约 11 分钟（2026-08-14，C/D 级）。
- DeepSite：官网 "in minutes"（A 级，<https://deepsite.hf.co>）；无精确秒数口径。

### 4.4 存疑

- DSH＝DeepSeek Harness 为高概率判读而非实证闭环（缺清单原文对照）；两读法均已取证，结论对身份歧义鲁棒（两读法在「风格无平台机制」上一致，差异在质量面有无工具能力）。

## 7. 对本平台机制取舍的启示

### 7.1 风格面：不该建机制，竞品证据三条同向

1. **前置风格机制被头部竞品证伪**：Lovable 三方向预览（2026-05-18 上线→2026-10-08 首建前移除）与 Themes（2025-11-26→2026-03-16 下线，官方理由低使用率）是「主题候选集／跨项目主题」路线的直接试错记录。本平台风格方向库与规范三件套属同类形态（前置代物化选择），竞品先例支持砍。
2. **多样性靠「模型自由＋prompt 反模板＋可选强引导」**：bolt 的开源 prompt 用一句 "Avoid generic or templated aesthetics at all costs"＋具体质感要求（色数/字号/网格/无衬线×衬线搭配）推开默认审美——这是「一句话气质倾向」档的现成参照，零机制成本。本平台腿④模型自主配色（深色科技风）实证同一能力存在。
3. **项目内一致性的竞品答案＝技术栈约束（默认组件库＋tokens 主题机制），不是风格流程**；「一个项目一套风格」的增量手段（若裸写方差实验 #565 证明需要）应落在 bolt 式 prompt 气质倾向或 v0 式 starter/设计系统注入这类轻形态，且 Lovable 的教训是：设计系统强制只在用户显式带资进组时才该开（他们做成付费档可选项，而非默认机制）。

### 7.2 质量面：唯一值得平台化的机制层

- 商业产品共识底线＝**平台强制「能跑」**：真实构建／装依赖／起服务／探活（v0 Sandbox、Lovable 构建＋发布闸、bolt WebContainers）。腿④中模型「自写 smoke→build→起服」的自主行为，正是竞品用平台固化下来的那一层——砍风格机制后，把这一层做成平台级兜底（成本远低于被砍机制，收益有竞品共识背书），与本平台实验结论不冲突。
- 修复形态＝**检测平台化＋修复模型化**（Lovable Try to fix 扫日志自修、v0 AutoFix 专任模型）——平台只需保证错误可见与闸门，不需要自研修复逻辑。
- **不要建「生成后强制全量测试」**：Lovable 深层验证点菜式、Replit 浏览器自测由 Agent 自主决定时机——竞品没有一家把 e2e/全量测试做成生成后硬闸。
- 反面对照组：DeepSite 零校验纯生成存在于开源玩具，商业产品无一如此。

### 7.3 时长面：腿④ 18min 在竞品区间，无需为时长加机制

- 竞品官方口径：v0 minutes／bolt 约 5 分钟教程／DSH 5m24s 官方演示、实测 11min／Replit 首版分钟到 30 分钟。Lovable 社区 30s-3min 是前端优先原型口径（11-06 报告已确证口径差），与本平台全栈首版不可比。18min 与 DSH 同类同量级（地图定性二「18min≈竞品档」成立），慢于 bolt 官方示例但在「像样首版」区间内——竞品的速度投入点在预览基建（v0 沙箱提速、Lovable OJ、Replit Turbo），而非风格/流程机制。
