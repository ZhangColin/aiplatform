# 访谈轮收口硬契约与悬空接管

访谈期意见轮异常收口（savePrd 失败只存在于智能体叙述、轮被判死中断）后既无挂起问答也无 PRD，平台不感知、访谈状态机悬空；其后短确认输入（「OK」「可以」）被无状态入口三分类判 FALLBACK，回与项目状态无关的定型文案——用户感知「装忙复读」（issue #373，2026-11-02 本地实录）。

决定：把 CONTEXT.md 对主智能体「以每轮一问的追问梳理需求」的表述升格为硬契约——需求梳理期（未出 PRD）的意见轮与问答作答复跑轮，合法收口只有「再问一问（挂起问答）」或「产出 PRD（含修订）」两形（咨询轮豁免：答询零产物是另一车道常态）。轮落定观测点校验契约，命中即悬空：平台补一条如实状态消息（复用平台自述面与对话史落库，SSE 事件封闭集零新增；文案两形——有可观测失败点名「本轮被中断」／「刚才写 PRD 一步失败了」，无则泛形，恒带「继续」指路），其后输入绕过入口分类直达意见轮，至下一次合法收口解除（恢复轮再悬空则保持接管、再补如实状态）。语义正本见 CONTEXT.md「悬空」词条。

## Considered Options

- 平台事实级接管：收口不变量＋如实状态＋悬空期绕过分类（采纳：确定性、零 prompt 工程，「宁进意见链有主智能体把关」既有定向取舍的延伸）
- 分类器注入项目状态行（出局：分类器从无状态变有状态，模型判定悬空路由不如平台规则可靠）
- 悬空时自动再起一轮让智能体重试（出局：失败因若是环境问题（如工作区缺失）重试照样失败，循环烧 token）
- 平台重建挂起问答承接后续「继续」（出局：为一条文案新建平台发问答卡机制面，不值；问答卡语义绑 run 挂起，平台无 run 可挂）
- 兜底文案上下文化（原建议 3，退役：悬空输入被接管后 FALLBACK 只剩真寒暄，定型文案无上下文需求）

## Consequences

- 入口三分类在悬空标记期内被跳过——读派发代码会看到「有时不分类」，本 ADR 即解释。
- #371 判死收口（超时/活超时判死）同被不变量命中：判死也是无问无 PRD 收口，接管文案点名「本轮被中断」。
- 迭代期（PRD 已出）不引入不变量：该期轮收口无问是常态（受理即派），且有派发链与 run 留痕兜底；若迭代期出现类似悬空再另立票。
- 悬空判定依赖的三个事实（PRD 产出、挂起问答、轮内工具失败）均为平台既有可观测面，不新增模型自报结论的通道。
- 工作区置备失败（本地触发器）不在本决策内，另修另票。
