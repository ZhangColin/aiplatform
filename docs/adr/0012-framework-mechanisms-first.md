# 框架机制优先：AgentScope 内建能力显式采用，不自造

原则（用户拍板，适用于所有特性）：「agentscope-java 有的机制尽量用起来，不要自己创造一套，除非框架没有。」上下文管理是首个适用点：平台不自建压缩/摘要机制，主智能体访谈会话等长会话继续由框架压缩承担；但框架缺省值必须转为**平台显式配置**（触发阈值、保留量、压缩模型档位），压缩与记忆抽取的 token 消耗必须**纳入计量**（现状逃逸 `met_usage_events`）。不向用户呈现压缩事件（用户不关心），平台侧保证三点：信息不丢失、不狂烧 token、不拖速度。

## Context

调查（2026-09-07）发现：平台零上下文管理代码，AgentScope 2.0.1 HarnessAgent 压缩链（CompactionMiddleware + ToolResultEvictionMiddleware）以缺省值隐式生效——官方中文文档声称默认关闭，与发布的 2.0.1 构件字节码不符。「静默丢历史」与「显式报错」之间平台全无感知，这是本原则的出处：不是信不信框架的问题，是**框架在跑而平台不知道**的问题。

## Consequences

- 随附三个缺陷级修复（另开票，不在本 ADR 展开）：① 压缩/记忆抽取调用逃逸计量；② 框架 flush/offload/eviction 文件写入用户项目工作区（混进 git 成版，绕过「记忆不进包」意图）；③ `context_length_exceeded` 在 streamEvents 路径无恢复钩子、主智能体炸后下轮续炸无自愈。
- 后续评估任何智能体能力（记忆、计划、子智能体等）时，先查框架内建，再议自建。
