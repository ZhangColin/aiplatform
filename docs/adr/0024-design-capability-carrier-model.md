# 设计能力载体模型：终点属性、两轨显式切换与 PRD 双形态

设计能力线载体裁决（2026-10-03，#273，承 ADR-0023 定位、依据 docs/research/2026-10-03 四路快照——Replit Design 为同项目双终点同构正本）定案：**项目不分型、终点是属性**——单一项目实体带终点类型（设计 / 系统 / 系统＋设计，对齐订单交付物类型），入口选择定初值、下单前可变（转轨动作是对话之外类型变更的一等入口）、下单即冻结。**设计过程与构建 run 是两套产出逻辑**：设计过程独立成线（多稿探索、挑选、定稿），执行体为独立「设计执行体」槽位，不挂 run 词条第三型、不套编码五段循环；设计稿形态跟设计物类型走（平面/图案类＝位图、界面类＝可交互轻量实现，皆为正身、多格式导出）——修正 ADR-0023「正身＝可交互轻量实现、图为衍生」与「两票落地前一律 HTML 交付」：载体不预设形态先行，纯图片类的出图能力档位归 #275 裁。**触发律＝轨间显式、轨内无门**：设计过程唯一入口是用户显式动作——入口选做设计（即为项目主线）或系统中途手动切换（作用域：全部页面或具体页面，Replit 双入口/Build… 菜单同构）；对话区提设计想法不自动转轨、主智能体可建议切换（Replit 被动仅「加数据库提示转正」一处话术级 nudge）；轨内衔接自动——PRD 完成自动起设计、设计定稿自动起更新 run（系统在途）或开放下单/转系统开发（设计主线），转系统开发为显式动作、随后 PRD 重写系统形自动起首个构建 run。**PRD 双形态**：七章节不动，清单章按终点类型二形（系统形＝功能清单、设计形＝设计物清单——后者为设计主线计划对应物、对切片计划同构）；系统＋设计项目用系统形（设计硬约束入关键约束），定稿稿以规范源身份经起跑上下文（首个构建）或交接物稿引用位（中途更新）喂系统轨。其余：派发零改（车道不加、判定出口不加）；版本流统一（run 收口与设计定稿同一产物版本流，同一工作区 git 正本）；跨项目备胎备案不建结构（触发器＝真实跨项目复用需求出现）；知识库仍只沉淀 PRD（设计形 PRD 天然覆盖，设计稿入库备案）。

## Considered Options

- **项目显式分型（系统项目/设计项目两类实体、两条流程）**——拒绝：每层载体概念跟着开叉，正选场景（双终点项目）恰骑在叉上；属性与 ADR-0023「机制零改版只加维度」同一手感。
- **设计 run 挂 run 词条第三型、五段循环 1:1 映射**——拒绝：两套产出逻辑不同构（出图/写稿的探索循环 vs 编码五段循环），硬套是假同构；独立设计执行体槽位——工具面天然分家（出图/设计件 vs shell 编码件）。
- **设计稿钉死 HTML 正身、图为衍生**——拒绝（用户纠正）：纯图片设计（海报/logo/图案）无 HTML 什么事；形态跟设计物类型走，stitch 式多格式导出。
- **PRD 产出自动进设计轨（无门外推）/主智能体判定设计意见自动转轨**——拒绝：原链路运转良好不拦截；Replit 无此机制，转正全是显式动作。定稿后的对齐/起跑不设确认门——切换/定稿本身已是显式用户动作，紧跟的门是冗余门。
- **派发加设计车道或判定侧「进设计轨」出口**——拒绝：轨间只认显式切换后判定侧无出口可加；三分类、判定枚举零改。
- **设计稿独立版本流**——拒绝：双终点项目稿与系统互相牵动，分流出「回滚系统时稿是新稿」的错位；统一产物版本流零新机制。
- **跨项目桥建结构（设计稿跨项目引用机制）**——拒绝：保留能力不保留结构——设计稿自包含文件已是物理桥，编排机制等真实需求出现再裁。

## Consequences

- CONTEXT.md 随改：项目词条（加终点类型）、设计稿词条（形态句改写）、新增设计过程/定稿/设计物清单/设计执行体四词条、PRD/功能清单/确认下单/交接物/版本/run avoid/智能体运营配置（两座→三座）微扩。
- #277（一致性桥）输入口径已定：定稿稿经起跑上下文/交接物进入系统轨；「图片→结构化规范」提炼仍是该票核心决策点。
- #274（过程形态）承接：切换入口与页面级锚定的呈现、定稿动作与定稿后分叉（下单 vs 转系统开发）的呈现、设计执行体工具面与技能挂载接口（雾区「技能线接口」随其毕业）。
- 设计-only 的纯图片类设计物依赖 #275（出图档位）/#276（图片管道）两票裁决；界面类不依赖（写 HTML 零新增基建）。
- ADR-0023 的「两票落地前设计线产物以 HTML 形态交付」一句随本 ADR 修正（已在彼文标注）。
