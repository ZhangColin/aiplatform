## 4. 观察到的缺陷（按严重度）

1. **看板卡片被压扁、内容被裁掉，列不能滚动（最严重，六-2 判部分的原因）。** 1366×900 主管视角五列 25 张卡片全部被裁：已关闭列 7 张只剩 73px（只看得到工单号、优先级、客户名），处理中列 83–94px（催办红条、工程师、时间、电话都看不到），挂起列 3 张 185px 也轻微被裁。列容器 scrollTop 设多少都是 0。DOM 实测：卡片是带 overflow-hidden 的 flex 子项，在带 max-height(100vh−320px) 的列里被压缩；把 max-height 去掉后卡片恢复 194px、零裁切，说明不是数据问题而是布局写法问题。截图 n3-02、n3-02f。旧应用同一位置是正常的列内滚动。
2. **详情页全部有「hydration 不一致」控制台错误**（7 个详情页每次都报：服务端渲染 `2026-11-19 20:53`，浏览器 `2026-11-20 04:53`）。原因：时间用浏览器本地时区格式化而服务端是 UTC。开发模式下页面左下角出现 Next 红色「1 Issue」徽标（截图 n3-07、n3-09、n3-11）；按 React 的机制，生产构建下同样会报错并退回客户端重渲染（未实测生产构建）。旧应用显式固定 Asia/Shanghai 两端一致，各页面零控制台错误（只有访问不存在的页面时有一条资源 404）。
3. **统计页「本月每日录单量」柱状图空白**：30 根柱子计算高度全是 0px（style 写了 16.67%/33%/100%，但父级 `items-end` 的 flex 子项没有确定高度，百分比失效）。只看得到日期轴和「峰值 6 条/日」。这是四卡片之外的附加图，不影响四卡片判定。旧应用的「近 14 天录单趋势」同样 0px，属两边共同毛病。
4. **待派单状态不能挂起**（接口 409「仅处理中或待回访工单可以挂起」），与文档「任意节点可挂起」不符；旧应用可以。
5. **`/api/tickets?from=garbage` 返回 HTTP 500**（`invalid input syntax for type date`），日期参数没校验；正常界面走不到，但接口不健壮。
6. **日期筛选按 UTC 日界，列表显示按浏览器本地时间**：库里时区 UTC、`::date` 按 UTC 比较，而 3 号工单 UTC 11-21 20:53（北京 11-22 04:53）筛「11-22」查不到、筛「11-21」能查到，和列表里显示的「创建时间 2026-11-22 04:53」对不上。北京时间 0–8 点建的工单都会这样。
7. 工程师打开不归自己的工单详情，只显示「当前状态无可用操作」，没有说明是只读（代码里那段「你的角色可查看但不能流转」提示的显示条件永远为假，是死代码）。
8. 成员页没有「编辑已有成员姓名/电话」的界面入口（只有新增和停启用；接口其实支持）。
9. 404 页是 Next.js 默认英文页（「404 / This page could not be found.」）嵌在应用壳里，没做中文定制；旧应用有（「信号丢失 · 页面不存在」）。
10. `/favicon.ico` 404，登录页控制台有一条 404 报错（无功能影响）。
11. 新建工单页顶部提示「字段带 * 为必填」，但所有字段标签都没有 * 号。
12. 环境事实：应用以 `next dev` 开发模式运行（页面带 Next 开发工具徽标），不是生产构建。

## 7. 与旧应用对比结论（每点都在旧应用上实测过）

新应用更差的：
- 看板列内滚动与卡片完整性（缺陷 1）。
- 「任意节点可挂起」：旧应用待派单可挂起，新应用 409。
- 详情页控制台 hydration 错误：旧应用零错误。
- 成员资料编辑：旧应用有「编辑」，新应用界面没有。
- 404 页：旧应用中文定制，新应用 Next 默认英文页。

新应用更好的：
- 1366 宽度下五列完整可见，不用横向滚动；旧应用 1366 下最后一列被裁掉。
- 处理中、挂起状态可以「派单/改派」；旧应用只能在待派单时派。
- 列表多了「只看催办」一键筛选，详情页有 48 小时催办进度条。

持平的：登录落看板、四项导航、右上角用户；工程师默认只看自己的工单；48 小时标红；统计四卡片与列表口径一致；平均处理时长口径；日趋势图两边都空白。
