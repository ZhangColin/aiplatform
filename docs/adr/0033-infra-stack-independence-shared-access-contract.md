# 基础设施栈独立化：共享 infra 一键部署单元与多服务接入契约

部署把基础设施（nginx/pgsql/redis）与平台应用绑在同一条一键流水里：infra compose 混着平台专属的 embedding，nginx 网关是 compose 之外手工 `docker run` 的特例（还背着 bind-mount inode 坑），网络靠人工创建，redis 无密码，PG 只有超管一个账号多服务共用。这套基础设施即使不部署本平台也有用（后台前后端、app-registry 等其它服务都要用），但现状下外部服务无法安全接入：没有接入契约、一个服务的坏 nginx 配置可以弄挂所有人。本批决策（issue #381，实施 #382–#387）把基础设施拆成自包含一键部署单元，平台与所有外部服务按同一接入契约接入，semgravio-eu-1 存量服务器接管式迁移。

## Considered Options

- **部署单元形态：同仓自包含目录（采纳）** vs 独立基础设施仓库（出局：发布/版本对齐多一处远端耦合，infra 演进与接入契约变更要跨仓评审；而「整目录可拷走单独用」已经满足脱离平台独立使用，独立仓换来的只是物理隔离，不值）。
- **网络模型：双网隔离不变（采纳）**——`webnet`（共享接入网，infra 与所有接入服务）＋`previewnet`（平台沙箱网），共享 nginx 双挂两网、绑宿主 80/443，跨网路由唯一发生在 nginx 这一处。单网合并（出局：沙箱跑用户生成的不可信代码，单网下任一沙箱内代码都能经容器名 DNS 触达 pg/redis——凭据泄漏与数据破坏面，一张网的运维便利换不掉）。
- **服务清单：无集中 manifest、各服务全自建（采纳）**——infra 不收纳任何接入服务的信息（无注册表、无集中渲染）：入网靠 deploy.sh 幂等建网、库与账号靠 ensure-db-user.sh 幂等自建、nginx 配置靠 install-nginx-conf.sh 门禁安装。集中 manifest（出局：infra 必须感知每个服务的端口/域名/库名细节，任何接入方的变更都耦合回中心节点，违背「不部署平台也有用」的自包含性；且中心渲染反而让「一个服务的坏配置弄挂所有人」更容易）。
- **预览网关：动态路由并入共享 nginx、手工网关容器退役（采纳）**——ADR-0014 的预览子域动态路由改由平台自己的 `conf.d/aiplatform.conf`（＋资产目录）承载，经同一门禁安装；手工 `docker run` 的网关特例删除。保持独立网关容器（出局：compose 之外的部署特例、单文件 bind-mount 的 inode 坑（宿主文件被替换后容器内看到旧内容、reload 无效）、多占一个对外端口；共享 nginx 反正已经双挂 previewnet，独立容器没有独占任何资源）。
- **eu-1 切换路径：接管式迁移（采纳）**——停机窗口一次：停平台 → 旧 PG 数据卷文件级拷入新 external 卷＋校验、旧卷保留不删兜底 → infra 起栈（超管名/密码/既有库全延用）→ 平台按新契约重起 → 冒烟。全新起＋pg_dump/restore 导数据（出局：多一次数据搬运就多一次风险窗口，且大库 dump/restore 比文件级拷贝慢一个量级；超管凭据变动会波及 dbx 客户端等所有既有连接配置——接管式只是重组管理方式、不动数据本体，凭据全延用则所有客户端零感知）。

## Consequences

- **行为变化（有意）**：redis 启用 requirepass（此前无密码）——后端配置项同步落地（#383，`REDIS_PASSWORD` fail-fast 口径同 `REDIS_HOST`），迁移窗口随 infra 起栈生效。
- **凭据模型**：服务器上 infra 的 `.env` 为唯一凭据正本（不入 git）；接入服务只获分片凭据（自己的库账号＋redis 密码），PG 超管不下发。平台现网是**有意例外**——其库账号即该实例超管（历史专用形态，本批为保客户端零感知而凭据全延用）；平台降权为分片账号（经 `ensure-db-user.sh` 自建低权账号）不在本批范围，另票。镜像 pin 精确版本，「重跑无害」成立、升级是显式决策。
- **职责边界**：infra 仅 nginx＋pgsql＋redis，不预建服务库（各服务经 helper 自建，既有库延用）、embedding 归平台部署物（#386）、证书只定目录约定＋reload 钩子（申请/续期人工 certbot，自动化不进 v1）。
- **首个部署面测试 seam**：infra 自带 selftest.sh，本地 Docker 从零排演整份接入契约（起栈/幂等/建号低权限/门禁裁决），兼作 eu-1 停机迁移前的排演工具；eu-1 实际切换的执行不在本决策内（交付物＝脚本＋SOP＋排演，运维择期执行，SOP 见 `docs/deploy/eu1-migration-sop.md`）。
- **ADR-0014 注记**：预览网关的独立容器形态退役，其子域动态路由/注入机制本身不变（块文件单源共用）；「网关」一词此后指共享 nginx 下平台自己的 conf.d 配置。
- 部署术语不进根级 CONTEXT.md（业务域语言的家）；部署正本为 `deploy/部署文档.md`＋`deploy/infra/README.md`（接入契约）。
