# 入口分流呈现：混合形式、两档模式位与终点初值进载荷

设计能力线入口裁决（2026-10-04，#280，承 ADR-0023/0024/0025——入口有选择已定方向、终点类型「入口选择定初值」已定语义；现状事实：首页＝一句话 hero（主标「想做什么，直接说」＋发送框＋示例 chips＋模板卡），提交即建项目直进项目页、载荷只有 requirement；平台已有模式位壳 `PLATFORM_MODES`（做系统 live／做页面·写文档 disabled「敬请期待」）且 mode 不进任何载荷）定案：

**分流形式＝混合**：一句话输入仍是首页主视觉、默认走系统主线（主链路零新增摩擦，「生成无门口径」守恒——入口不设确认门）；输入框近旁挂**轻量显式「先做设计」次入口**（不点开就可见，保证设计线可发现）。**就地切换上下文**（不跳页不弹层）：主标/placeholder/示例 chips/模板卡随切换，再点切回。系统态维持现状文案；设计态主标「想要什么样子，直接说」、placeholder「一句话说说你想要的设计…（logo、海报、页面样式…）」＋设计向示例。

**两档**：做系统（默认）｜做设计。复合终点（系统＋设计）不设入口档——由中途切换（系统侧切设计作用域）或定稿后转系统开发（设计侧）达成；入口只回答「这次主要来做什么」。

**模式位收编**：`PLATFORM_MODES` 收编为两档 live；「做页面」「写文档」占位档删除（占位是结构不是能力，「上线新模式只改此一处」机制保留；「做页面」词面窄于设计线——设计含 logo/海报等平面类）。发送框类型下拉与侧栏「能做这些」组同步两档 live、状态同源；侧栏点「做设计」＝去首页并预设设计态。**mode 进载荷**：选「做设计」时 createProject 载荷带终点初值字段——「入口选择定初值」的机制落地。

**项目页不带模式切换**：模式位只在首页 hero 承担一次性分流（新建时的一次语义）；项目内唯一终点变更位＝设置 tab（守 ADR-0025 切换控件位）。

**回显＝项目卡弱标识**：文字级小标签（设计/系统/系统＋设计），覆盖列表页项目卡与首页「最近的项目」卡；不做颜色强调（不抢四态徽标视觉焦点）。列表不加终点类型过滤维度。

**入口带图＝轻量示意**：切换件以排版/色彩层次传达「这边是设计」，不做作品画廊、零示例内容维护——设计能力的可感知留给设计稿 tab 渐进长出，不做首屏营销图。

## Considered Options

- 硬双入口（首页两张并列大卡先选再输入，Replit Design/Build 同构）——拒绝：强迫选择违反「生成无门口径」；Replit 双 tab 是开发者语境（用户自带概念），本平台非技术用户入口期尚未形成设计/系统概念。
- 纯软分流（一句话照旧、终点初值恒系统、靠对话话术建议）——拒绝：设计主线 PRD 从设计物清单写起，纯软会让只要设计的用户先拿到功能清单形 PRD（转轨需重写）；且设计线不可发现。
- 入口三档（含「系统＋设计」复合档）——拒绝：复合档概念负担最重（要求用户理解两者关系），恰是入口最不该问的；两档经中途切换全覆盖三种终点。
- 占位档保留（「做页面/写文档」挂着维持预告感）——拒绝：保留能力不保留结构；「做页面」还与设计线撞概念（词面窄）。
- 首页带真实作品图（画廊式示例稿）——拒绝：示例内容维护成本＋喧宾夺主风险（设计侧是次视觉）。
- 项目页发送框也可切模式（第二变更入口）——拒绝：与设置 tab 并存双入口，状态与发现面翻倍，推翻 ADR-0025 单一位决议。
- 列表按终点类型过滤——拒绝：四态过滤已够用，打磨期无真实需求；备案（触发器＝设计项目多到列表难找）。

## Consequences

- CONTEXT.md 项目词条微扩：入口两档显式选择（做系统/做设计）定初值。
- 站点 title 修正对齐 ADR-0023 双交付物开篇（现「AI 开发平台／…定制交易平台」词面落后）；访谈提示语（STAGE_HINTS）设计主线变体、设计态文案集（chips/模板）归实施时文案清单。
- 实现落点归实施：hero 切换件形态（pill/卡片）、载荷终点初值字段、模式位两处呈现收编、两处项目卡弱标识。
- 无新雾毕业；#279 收尾票受制减至 1 张（#281）。
