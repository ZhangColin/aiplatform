# 迭代语义与版本时间线：两平面、活文档、跑前快照、回滚不倒带

> **改记（2026-11-25，阶段四施工定案，固化 2026-11-24 用户裁决；#624／#626–#630，本票 #631）**：
>
> - **修改交接与 PRD 形态改口**：迭代时 PRD 由内核维护成**完整文档**——本轮需求写进 `docs/PRD.md` 对应章节、不在文末堆积原始意见、不设固定「迭代节」末尾堆积节；平台不写 PRD、不追加原始意见。迭代任务提示要求内核完成改动后把本轮需求并入对应章节、保持完整文档（#624）。**为什么**：用户要求 PRD 始终是一份完整、内容在正确位置的文档，而不是随迭代变长的意见流水。下文的「落 `docs/PRD.md` 迭代节→触发一次生成」「迭代节按序记录」旧口径作废；修改指令仍由对话面蒸馏、交平台派发，落点改为内核把需求写进 PRD 对应章节。
> - **用户面版本＝git 版本提交**：自动成版落为工作区 git commit（trailer `Platform-Version: vN`＋`Run-Id:` 标识，主题＝用户那句话），版本序列＝按标记过滤的 git log、不新增表（#626）；「回到此版」＝平台侧异步回滚（restore tracked→停服→build→重启→探活→成 vN+1，#627）。开发面快照提交与用户面版本仍分立。
> - **旧双轴版本面退场、商业面改接**：旧 Demo/PRD 版本表、双轴版本记录抽屉、「查看当时」快照容器与预览网关快照子域路由整条拆除（#628／#630）；「确认此版本」改标记当前用户面版本，订单/合同冻结收敛为单个已确认用户面版本号（#629）。
> - 上文「旧概念出局：Run-Id trailer」指 Run-Id **单独作**成版成员判据的旧机制；现成员判据＝`Platform-Version`，`Run-Id` 只是随行标识。
> - 重启条件：无（PRD 完整文档是用户明确要求；版本＝git 提交与单轴时间线是施工落定形态）。若将来用户显形要求「按迭代保留原始意见流水」，再议是否单设留痕面——不改 PRD 正文。

一句话改动怎么分钟级落地的定案（承 从零重设总索引 #573；迭代语义决议见 #577，迭代实测＝#586，版本与回滚＝#582、库半边＝#591）。硬门槛（用户裁决 2026-11-21）：首次生成和每轮迭代都必须分钟级——小时级等待＝修改出错率上升＋每天能改的问题数骤减。

## 决策

**两平面结构，互不穿透**：

- **执行面＝生成内核**（ADR-0054）：每次修改＝在既有工作区上重跑内核——新上下文（无会话状态）、读 PRD＋工作区（文件树即唯一事实）、一轮不调工具即结束、build＋探活硬判据原样。首建与迭代同机制、异起点。
- **对话面＝平台界面侧轻会话**（便宜上下文），两职能：①访谈式澄清（提问给选项→用户选→下一问→模型觉得清楚即动手）；②纯答疑（只答不改、不触发一次生成）。工作区访问只读——密码类答案在 .env／seed 里，必须能看；**写通道唯一**：工作区一切变更只经生成内核，对话面永不写。
- 用户看的会话＝一根连续线程：首建请求→澄清／答疑→每次修改的过程呈现→看效果（服务常驻刷预览网址，零成本）。生成内核永不读聊天记录；人的关联靠线程连续，内核的关联靠 PRD 迭代流水＋工作区现态。

**修改交接**：定型意见由对话面蒸馏为**自足指令**（原文＋讨论要点——「还是不行」类指代词须解析成完整句）落 `docs/PRD.md` 迭代节→触发一次生成；拿不准宁可追问不误发（软确认）。判定从平台机制移进模型能力；不分大小改动档。

**PRD＝活文档**：迭代节按序记录、生成内核自行整合改写（实证：内核主动把已落实意见并入正文＋迭代记录节标注「历史留痕」），PRD 恒为最新需求真相。在途意见＝追加即排队、天然合并（下一轮读整份 PRD），当前生成不打断，界面轻提示「已记下，下一轮生效」。风格保持零机制——PRD 风格词为准，三组迭代实测零漂移。

**跑前快照（开发面提交）**：平台界面侧工作区 git init（ignore 权威集四件：`node_modules/`、`.next/`、`.pnpm-store/`、`data/`）＋每轮生成开始前自动 commit（实测首次全量 104–156ms、增量 121ms，本地毫秒级）。坏迭代回滚＝reset 到跑前快照＋重启服务（主退路），按 PRD 全量重建降为核选项。内核不知道 git；实证模型把 git 当自查工具用（`git diff` 两个快照理解上一轮改动）、零分心反向受益。开发面提交与用户面版本分立：一次用户面修改背后可 N 个快照。

**用户面版本（重建成采用，#582）**：界面自动成版——每轮生成探活通过（＝一次完整交付）后，界面自动把当时工作区 commit 记录为用户面版本，零用户动作、零确认门。版本序号 v1/v2/v3 保留，记录语义＝用户面交付点。呈现＝界面内**单轴时间线**：每版＝时间＋用户那句话（本轮修改原文）＋预览入口＋「回到此版」。旧概念出局：Run-Id trailer、Demo 版本序绑 PRD 构建基准（无消费者：切片机出局、PRD 是活文档）。

**回滚＝代码整回、库不倒带（#591 落锤）**：用户面「回到此版」＝工作区代码整回该版快照＋重启服务＋成新版本 vN+1（单线前滚不叉枝）；**活库（schema＋数据）保持最新、不倒带**。机理：git 快照 ignore 集含 `data/`（活 PGDATA 不可快照）；置备链幂等自愈全带库走；内核把 `scripts/schema.sql` 维护成幂等追加式全量 DDL（`if not exists`），追加式变更对旧代码兼容（超集 schema）；真实产品的版本语义同形——发版回退从不回滚数据。兜底：回滚后照走探活门；破坏性 schema 变更（改名／删列／改类型）导致旧版起不来＝明确展示＋建议回最新版或提一句修改意见（失败语义原样套用）。重启条件：回滚后探活失败成为常态，或用户显形要「回到那时候的数据」→ 升级「每版 pg_dump 双份存档＋回滚重放」。失败生成打进活库的半成品 schema 变更不清理——reset 只回代码面，重跑对着活库现状自然修齐（实测）。施工注意：回滚重启须带 build 或统一开发服务器形态，不得拿旧构建产物（.next 残留）冒充回滚结果。

**新失败语义**：失败＝明确展示＋重跑即恢复，**不自动重跑**（通道级归 failover 供给链，内核级已重试关停，不造第三层）。

**成本口径**：零新机制、不设钱门（60M prompt 兜底即失控兜底）；收尾卡不加成本显示，运营面成本切片可见。实数（deepseek-flash 峰时价：输入 ¥2/M、输出 ¥8/M、缓存读 ¥0.04/M）：单轮迭代 3.1–4.6M prompt，最坏口径 ¥6–9／轮，缓存读主导、实际个位数元以内；首建 ¥1.3–2.1（ADR-0054，#590 定稿配置实测）。重启条件：单轮成本异常放大实测出现，或商业面要按成本定价／限额。

## Considered Options

- **会话续聊／增量补丁式迭代**——否决（#577）：一致性对冲＝工作区即状态＋PRD 即需求真相＋build／探活硬判据；实测重跑形态小改 7.3min、中改 5.0min，分钟级门成立、执行形态不回庭。
- **分大小改动档**——否决：改多深由模型读句自判；实证未显形「小改太慢」。
- **回滚数据倒带（每版 pg_dump 双份存档／出厂态清库重放）**——否决（#591）：机制成本真实、数据倒带价值不足——演示库内容＝种子＋预览试录，倒带会把访客录的数据也倒掉。
- **时间旅行预览独立机制**——不设：回滚已覆盖（想看 v3＝回滚过去看，不满意再回）。重启条件：用户显形「想对照两版」高频且回滚覆盖不足。
- **差异摘要（savePrd summary）**——出局：无呈现消费者——变更呈现＝收尾卡变更清单含单文件 diff；PRD＝迭代流水活文档；时间线每版摘要＝用户那句话原文。

## Consequences

- 旧迭代受理链／派发／交接物／续跑机器出局（ADR-0055）；版本词条、迭代词条、新词条（对话面／执行面／修改指令／迭代节／跑前快照）随本文落 CONTEXT.md。
- 施工面：对话面引擎（轻会话＋蒸馏＋软确认＋只读工具）、PRD 完整文档维护（内核把需求并入对应章节，改记 2026-11-25）、跑前快照链、自动成版与时间线、回滚动作（重启带 build 或统一 dev 形态）。见施工交接清单。
- 实证边界：迭代分钟级证据＝三腿真跑（#586）＋三处追加修改（#590，5.2／5.2／2.3 分钟、8 件事全改好）；样本小，作为观察点继续看。
