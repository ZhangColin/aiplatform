# 裸生成内核：从零重设的生成内核定案

平台生成能力从零重设的定案（承 从零重设总索引 #573「从零重设·总索引」，决议见 #575（原题「内核正本」，即内核定案）；循环语义、工具四件、输出上限等生成机制以 #590「首建实证·二轮」最终修订判决与重跑实测为准，2026-11-23；机制去留总表见 ADR-0055，逐项判决与实验数据见各 issue 决议评论）。核心立场（用户裁决，继承 #564）：生成内核＝裸模型形态，默认不带任何旧机制；平台价值＝内核＋新增机制，每项新增必须实验证明严格更好才准进（准入标准），否则平台只是裸内核外面套层界面——这个结论照实写。速度硬性门槛：首次生成和每轮迭代都必须分钟级。

## 决策

**内核＝裸模型形态**。一段提示词＋工具四件＋一个循环，无执行协议、无切片、无收口机器、无会话状态预设、无过程解说义务。「裸」指机制裸，非起点为空：起点 substrate＝dev 镜像内模板工程（Next.js App Router＋React 19＋Tailwind 4＋shadcn，node_modules 已装、PG/Redis 已起、连接串在 .env），需求文本统一落盘 `docs/PRD.md`。

**提示词＝七行级权威版本，住代码**：角色＋环境描述＋任务（建表、后端 API、全部页面、演示数据）＋长文件拆分提示＋完成判据＋全程中文，外加完成纪律三句与工具使用说明三句（照 DeepSeek Harness 等成熟方案原文，只换工具名）。新内核提示词＝代码权威版本，不开放后台直改——改提示词＝改内核＝开 issue（后台直改是绕过准入标准的后门）。旧 13 条执行协议全部出局（所指条款均已有归宿，见 ADR-0055）。

**工具四件**：`write_file`（覆盖全量写、自动建父目录）／`read_file`（带行号、可分段）／`edit_file`（局部替换）／`bash`（180s 超时）。实测：`edit_file` 首建基本不用（0–6 次）、追加修改用得多（11／12／2 次）——它是齐全性件，不是提速手段。

**循环语义照成熟方案的默认做法**（2026-11-23 对照 DeepSeek Harness 循环源码逐项改齐后实测，取代 #575 原判的「做完后催促」写法）：

- **结束条件＝一轮不调工具即结束，不做「做完了再继续催」**（首建、迭代同一条规则）。最终实测三轮全部第一次说「做完了」就停。第一版到达时间新旧做法相近（10 分钟上下），省掉的是旧「催促继续」提示句逼出的尾巴（占 53–73% 轮次）。重新考虑的条件：上线后「第一次停下时漏做、要用户再提一句」多到影响体验时，优先原样采用现成可选件（DeepSeek Harness 目标轮、bolt.diy 完成闸），不自己写催促继续的提示句。
- **到护栏上限不掐断**：关工具、让模型如实汇报（OpenCode 原文口径）。
- **重复调用同一工具同样参数：第 3／5／8 次只提醒、绝不拦截**（DeepSeek Harness 原文两段提醒句照抄）。
- **输出截断与空回复＝轮次结束**，收尾如实告知原因（用户说「继续」接着跑）；输出上限是每次请求的配置开关（默认 32768，可调）——从成因上消截断。
- **开发服务器由平台起、常驻，模型不杀不起**；完成判据＝`pnpm build` 过＋`curl 0.0.0.0:8081` 有响应（「服务常驻」从判据中撤出）。

**输入＝一份需求文本**（一句话～PRD 全文连续谱），平台统一落 `docs/PRD.md`，内核不区分形态、不做预处理。**输出＝探活通过的常驻服务＋工作区完整文件树**，即「跑着的预览网址」。

**质量评价六项＝人眼验收**：速度、配色、布局、组件质感、完成度、信息丰富度——不进机器判据、不进提示词。机器面唯一硬判据＝build 过＋探活有响应（收口判据唯一化见 ADR-0055，#579）。

**速度与成本基准（首建，deepseek-flash 实测，以 #590 定稿配置＝输出上限 32768 为准）**：10.6–16.5 分钟（基准档 10–17 分钟；旧做法 19–33 分钟）；轮次 89–146；输入 8.3–18.9M、输出 107–149K tokens；实算 ¥1.30–2.07／次（旧做法 ¥2.4–4.4）。完成度最终一轮逐条核对 47 完成／0 部分／0 未做——四轮中首次零「部分」，不低于旧做法。输出上限调大前有中间轮实测 6.8–10.7 分钟、¥0.8–1.4（上限 8192）：上限调大后单轮写文件更长，慢约 2–6 分钟，如实记账——上限因此做成开关（默认 32768），用速度换完成度时可调低。迭代侧分钟级：小改 7.3 分钟、中改 5.0 分钟（#586）；#590 同循环追加修改 5.2／5.2／2.3 分钟、8 件事全改好（#586 的「做完后追加确认」方案已被「不催促」取代，其分钟级数据仍成立）。硬伤不靠机制兜：普通使用会碰到的硬伤靠用户提修改意见修掉（质量容忍标准：应用活着＋可迭代＝可接受；红线＝长时间不好／无提高／更差）。

**运营护栏（非工作语义）**：300 轮／45 分钟／60M prompt——防挂死与成本失控的兜底，数值远离实测分布（定稿配置实测最长 146 轮／16.5 分钟／18.9M），不重新标定。

**内核演进规则**：①准入标准——内核面任何改动（提示词／工具／底座）须实验证明严格更好才进（#576/#590 跑道为对照基线）；②底座强化授权——判据＝提高速度与生成效果、不妨碍模型发挥，在此判据内做深不限；③照成熟方案——平台各种处理定案前先查 DeepSeek Harness 的实现方案（源码级），人家没有的机制不臆想。

**必配能力清单（方向已定、优先级低、逐件过准入标准）**：联网搜索／网页抓取、附件／外部资料上传、生图、多模态理解。既有实现不拆、留待优化复用。

## Considered Options

- **「做完了再继续催」提示句（旧做法与 #586 方案 B）**——出局：13 家编码智能体无一使用；实测尾巴占 53–73% 轮次全由催促逼出，方案 B 未与「不催促」对照、成熟方案里也没有。重新考虑的条件见上。
- **「连续 2 轮无工具调用＋中间一次催促」（#575 原判第 4 条）**——被 #590 取代，理由同上。
- **到上限直接掐断／三道自动保护（截断续写、空回复提醒、重复调用拦截）**——出局：照各家默认与 DSH 源码改齐（截断与空回复即轮次结束、重复只提醒）。
- **「杀服务→构建→起服务」现成命令**——不进：成熟方案全是开发服务器平台起常驻；实测九次杀服务、起服务均为 0 次，且旧仓库应用 4 个表单页打不开的成因正是模型自己构建没重启。
- **内置「做完了再核一遍」机制（核对模型／目标轮）**——不进：各家均为默认不开启的可选件。重新考虑的条件同结束条件。
- **模型路由／自动换档提速**——出局（ADR-0055 组⑤，#583）。

## Consequences

- 生成链上旧机制全部出局或重建（完整清单与逐项判决见 ADR-0055）；供给链、沙箱宿主、计量原样保留（接线警示：重接生成链不得绕开供给链——每次模型调用照旧经「模型配置→候选队列→通道行」解析、用量事件照旧落账）。
- 施工面：内核提示词与工具权威版本落代码；旧执行体装配原样保留为发动机（接线点），subagent 半边随委派机制闲置；开发服务器平台常驻的形态落地；护栏数值接线。详见施工交接清单（docs/agents/从零重设施工交接清单.md）。
- 执行体装配（agentscope 装配点、会话状态存储、(userId,sessionId) 串行、内核重试关停、上下文压缩）原样保留——底座权威记录，演进走「底座强化授权」（#580-8）。
- 质量容忍与验收口径：审查与验收按「活着＋可迭代＝可接受；长时间不好／无提高／更差＝红线」判（用户裁决 2026-11-22）。
