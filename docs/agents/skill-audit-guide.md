# 技能审核指引

后台技能安装、更新、指派与候选经验人审的审核正本（条目化）。分层纪律正本在 [ADR-0021](../adr/0021-agent-operational-config-persisted-skill-snapshot-install.md) 与根级 `CONTEXT.md` 技能词条——内建工作协议只载身份/编排/约束/技能指路，方法论一律住技能层；本指引是其在审核动作上的执行面（#245 核验后，ADR-0021 过渡期的「软性暂缓方法论包指派」口径解除，本指引即现行正常口径）。

**改记（2026-11-23，从零重设收尾 #588/ADR-0058）**：智能体自荐技能、技能草稿与晋升机制**出局**（§五旧文「自产草稿审核」随之作废，由本节新的「候选经验审核」取代）；技能指派预检**出局**——把关靠人工审核。安装审核（§一–§三）与内置技能核验表（§四，历史留档）保留。审核材料：技能详情端点（frontmatter／正文／scripts 全文可读，所见即运行时注入面）＋候选经验审核面（§五，[ADR-0058](../adr/0058-data-flywheel-post-extraction-review.md)）。

## 一、双向边界判断

边界判断是双向的（Replit 铁律反用）：

- **技能内容是通用开发规范**（与平台机制有结构性挂点、换方法论流派不变的做事方式）→ 该进内建工作协议，不该作为技能装载；
- **内建工作协议出现方法论**（特定流派的做事方式，换流派即变）→ 该迁出成技能，内建只留身份/编排/约束/技能指路。

判据同 #245 核验用的尺：机制挂点/换流派不变 → 留内建；否则属方法论 → 住技能层。

## 二、安装审核清单（条目化）

安装与显式更新重拉时逐项过（更新翻新的是内容面，同尺重审）：

1. **注入面**——逐件读完再下结论，不看摘要：
   - frontmatter 全量（解析态键值）；
   - 正文全文（frontmatter 剥离后的 SKILL.md body）；
   - scripts/ 全文（脚本是注入面，#253——只对带 shell 的槽位发放，主智能体结构性拿不到）。
2. **方法论重叠面**——对照该技能将指派槽位的生效工作协议（智能体运营配置生效值：库值优先、缺省回落）＋同槽位已指派启用技能。把关靠人工审核（指派双头预检已随从零重设出局，#588）。
3. **description 三要素**——技能路由质量在装时把关：
   - trigger（何时用）缺失 → **拒**；
   - scope（管什么）缺失 → **拒**；
   - 否定边界（什么时候不用）缺失 → 要求补，或明示豁免（软门槛——前两要素硬拒，此要素不自动拒）。

## 三、重叠处置分界

同类冲突的处置保持一致：

- **scope 含糊、改 description/scope 可消解** → 暂缓＋要求改（改后重审）；
- **职能正面相撞、不可消解** → 拒版本（拒的是该版本，可改后重提）。

## 五、候选经验审核（ADR-0058，2026-11-23 起取代自产草稿审核）

候选经验＝事后提炼的产物：每出一个用户面版本，后台便宜模型读「自上次提炼以来新增的修改意见」提出（每次上限 3 条），落 `knw_sediment_drafts` 待审，不经静态扫描以外的自动通道。人审后生效，三键照旧（激活／拒绝／改类别，复用「数据标注」审核面），审核三问（平移自旧自产四要素中的三条）：

1. **真伪**——是不是真经验：候选应能从来源材料里找到依据（哪个项目、哪句原话、哪次修改后变好的），不是通用最佳实践拼凑或想象。判法＝来源回溯：点开来源看原句与修改效果是否相称。
2. **重叠**——与库内既有素材是否重复：语义重叠才是审核对象（同名有两道结构性闸兜底：写入口查重＋激活事务撞名复查）；重复即拒绝或改标签归并（改类别在途内调整）。
3. **来源可回溯**——来源三件必查：项目、版本、原句。审核面必须能一键点开来源（施工项：补来源回溯视图）。

处置口径：激活＝升格知识素材（kind 照旧三类：需求案例／功能模块／业务规则）、原样不改稿（审核者代改是职责越界）、操作者留痕；拒绝＝终态留档、理由必填；改类别＝在途内调整（占目标类别在途序号最低空位）。**不平移旧自产的「description 三要素」**——那是技能路由专用，候选经验走知识命中不走技能路由。

**与技能通道的边界**：候选经验被激活、被用到几次后**不自动变技能**（自动通道不进，#588-7）——「知识总结成技能」由人做：提问方法指南由人从验证过的知识里整理、走 §一–§三安装审核与指派；固化进平台的东西（底座修正／必配工具／模板件）开 issue 实现。
