# 充值余额制商业主轨：双池单源扣减、段间硬门与负余额软模型

商业化改版一期计费域的域模型定档（承 wayfinder 地图 #510 锁定共识、决议正本＝#513；竞品失败计费取证：`docs/research/2026-11-15-competitor-failure-billing-513.md`）。订单/合同/付款域逻辑搁置（UI 不动、代码与数据保留，见 #510）；真支付对接出界（ADR-0002「平台边界止于支付」不推翻——充值是平台内人民币元记账，渠道真接另图）。与 ADR-0039（去 PRD 确认门）无冲突：付费轨确认门恢复是 #515 的票面，不在本 ADR 范围。

## 决策

**双池单源（扣减源一次性选定）**：账户余额（账户名下、跨项目）＋项目余额（项目专属）两池；每项目一个**扣减源**标识——后台向项目池入账＝动作即选择（源=项目，前台零呈现），项目池从未入账则由用户在确认扣减卡上选一次（「本项目」→为本项目充值；「我的账户」→先登录绑定）；选定后不可自助更改、后台运营可调整（留痕）。只从源池扣、**负余额落源池**（两池皆可负）；收银台只充当前上下文的源池（向非源池充值＝死钱，不呈现该选项）。

**付费状态（项目级、不可逆、计费边界）**：新项目一律试用开局；翻转两门任一——岔路口选「继续讨论」（登录＋源池余额>0）或试用中意见拦截卡确认扣减（后台已充项目池的项目免登录直接确认）。**计费边界＝翻转时间点、不看活动类型**：翻转前一切智能体调用＝平台获客成本、零扣减（五问访谈、PRD 产出、首个构建基准整场生成、咨询、判定全在内）；翻转后一切智能体调用走扣减（对话轮、判定轮、run、联网搜索等固定单价项）；沙箱资源（容器/带宽）不进用户账、只进平台成本观测。

**试用拦截面＝平台结构闸**：入口车道判定之后、受理之前——意见与兜底两道拦（宁严勿漏）、咨询放行（零产物短路天然免费）、下单意图维持旧轨（订单域搁置）；被拦输入不丢失，拦截卡上确认扣减（显源池）或走充值引导。车道误判偏差面主动声明：咨询误判成意见＝多弹一次卡（可改口），意见误判成咨询＝漏一次费（demo 阶段容忍）。

**段间硬门＋段中自由（负余额软模型的精确语义）**：结算段＝主智能体一轮／一场 run／一场设计会话（设计会话段随设计线整条退役退场，#610），段收口即结算（实耗折算一次入账）。**段内绝不检查余额、绝不中断**（多轮 LLM 往返、工具调用、扣成负数照跑——用户的不可中断契约）；余额检查只发生在**段边界**：源池余额>0 放行下一段，≤0 则弹充值要求、回正才继续（余额提醒的挂点）。负余额因此**有上界≈一段实耗**，用户不充值＝平台最多亏尾段。「绝不中断进行中操作」由段边界硬门与段内自由共同保证。

**失败也扣、停止也扣；退款两条线**：失败/中止/重试照实扣（四竞品无一例外、行业基线，成本已实耗）；退款分界＝平台判定自身故障的扣减→人工发起返还（后台余额调整留痕承载，不建自动机制）；生成质量不达预期→一律不退。配套非机制约束：失败原因收尾卡透明标注（失败留账先例既有）；自动重试照扣、重试上限既有机制封顶（不新增无上限烧钱面）。

**计价与账本**：token 项＝成本单价（既有单价表，`met_price_entries`）×**全局折算率**（运营面可调、初始 1、保持弹性——固定单价项〔博查搜索〕单列小价目，计量面新增固定单价档、顺带把博查成本补进平台成本观测）；扣减行落金额＋用量＋单价**快照**（历史不随调参漂移，与单价表同律）。这**有意**建立「平台成本→用户扣减」的推导关系——CONTEXT.md 既有「成本与报价无推导关系」说的是订单报价面，两个面在词条里分开说清（「计费」仍不入用户面正名）。账本分立：成本账＝`met_usage_events`＋读侧现算（metering 零商业概念不动）；用户账＝新 business.billing BC、`bil_` 表前缀、流水 append-only；存储 Long 分、CNY（订单域同型）；**获客成本/用户费用按付费状态翻转时间戳切片分桶**呈现于成本观测面。用户账设计保持可分离（未来独立账户服务的缝：billing BC 弱引用 account/project、不 FK 平台域表）。

**入账与产品面**：前台充值＝**模拟收银台**（准入码〔固定码起步，控制谁能自助充值——销售/活动发码，无码引导联系平台〕→金额→模拟通道确认页〔「模拟支付」徽标〕→即时到账＋流水），须先登录；真渠道接入后只换通道、流程形态不变。对公转账＋后台财务确认录入保留（仿凭证核验留痕）；赠送默认入账户池、可指定项目池；后台「账户运营」（赠送/手动充值/余额调整，append-only 操作者留痕、机机签名）；用户面「我的账户」（双池余额＋流水＋项目充值入口）。

## Considered Options

- **两池兜底级联（项目优先、账户兜底，项目池永不负）**——否决：用户裁决单源制（选定一次、另一池有余额也不动）；级联引入跨池负余额归属歧义。
- **仅产出段计费（交互轮免费）**——否决：用户裁决计费边界＝付费状态翻转点、翻转后一切调用归用户；交互/产出分界让「访谈轮免费、判定轮免费」成为漏损面与解释负担。
- **失败免单（失败 run 不扣）**——否决：四竞品无一例外照扣（行业基线）；免单制造「判失败」争议面。改配退款两条线＋透明标注。
- **无下限软到底（付费后余额≤0 也只提醒不拦）**——否决：段间硬门让负余额有界（≈一段实耗），平台损失封顶；「只要余额大于 0 都可以」的字面义。
- **中止渐进结算／修复型免费额度／消费暂停线（竞品三件缓冲）**——不进本期：demo 阶段从简（#513 Q14），随转化数据再议（#510 雾区）；v0 教训（免费承诺与扣费不一致的伤害＞从不承诺）留档为未来若做的设计约束。
- **真支付对接**——出界（#510 Out of scope）：模拟收银台＋后台手动充值承载，另图。
- **独立账户服务拆分（identity 先例）**——出界（#510）：账本保持可分离（BC 弱引用）即可。

## Consequences

- CONTEXT.md 新词条随本票入册：充值、账户余额、项目余额、扣减、扣减源、结算段、付费状态、余额提醒、模拟收银台、准入码（业务语言）＋获客成本（平台内部语言）；「后台」词条面清单补账户运营。
- 实施切片（决议正本 #513）：billing 域落库与计价结算 → 拦截闸与确认卡／段边界检查与余额提醒／模拟收银台与我的账户／后台账户运营端点（admin 对接票惯例）／成本观测切片分桶，后五者依赖前者。
- 运营数值（折算率、搜索定价、准入码形态与发放）属运营面调参（#510 雾区），不进本 ADR。
- 博查固定单价项进计量面意味着 `met_usage_events` 语义扩一档（固定单价、token 五档为零）——metering「零商业概念」边界保持（仍只记用量与件数、不记金额）。
- 付费状态翻转是「体验提示熄灭」的判定数据源（#519 注入机制已定、等本字段接数据；体验提示面已随 2026-11-26 用户指示拆除——判定单读点 `trackOf` 照旧承载拦截/额度/构建门等其余消费面）。
