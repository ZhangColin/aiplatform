# 模型路由：可观测信号选档、路由判定优先人工覆盖兜底、策略配置化与决策留档

生成体系升级·模型路由裁决（2026-10-20，#354，spec #320 实施序⑦末件——#314 速度目标三杠杆之三；承 ADR-0021 智能体运营配置机制〔模型档位配置态初档，#341：Demo 阶段模型档＝run 执行体的模型档，缺省快档〕）。现状事实：模型档位经运营配置面人工定档（库值优先、缺省回落枚举默认，换档不发版）；「简单活快模型、难活强模型」的自动选档零机制。定案：

**路由判定在位**：run 执行体（仅此座——主智能体对话侧、设计执行体设计线另配，不参与）每次尝试的命令构建（起跑时读档口径，进行中 run 不定格）按任务特征可观测信号选档——**信号三件，任一越阈即升强档，否则回落人工档**：

1. **历史失败**（直接事实，非预测）：同段重试（第 N 次尝试）与回滚重跑（#353 首轮重试耗尽）——快档干不动的活即难活；
2. **文件面大小**：工作区已跟踪文件数（段起点工作区处于收口 commit 上、跟踪≈全量；非 git 工作区判无此信号——管道尾 wc 恒 0 会吞 git 失败，前置 rev-parse 判定）——代码面越大改动一致性越难；采集失败降级无此信号（不升档、不断流）；
3. **片复杂度**：切片描述字数（主智能体「宁粗勿碎」切片计划，长描述即粗片）——唯一片级信号，轨道层拼装传入。

**协同口径＝路由判定优先、人工覆盖兜底**：路由开（缺省）＝信号升强档优先，无信号回落<b>人工档兜底</b>（`modelId` 覆盖 → 枚举缺省——覆盖即<b>基础档</b>，快档位可经覆盖配置、不关路由）；路由关＝<b>钉死位</b>（显式关断即钉死，人工档恒生效——对账/对比场景的定档通道）。取舍：钉死不因「人工改档」隐式触发（改 modelId 只是换兜底基础档）——路由的开关是唯一显式钉死位，运营换档不会静默关掉路由。

**策略配置化（可调不发版）**：开关／强模型档／两阈值四件进智能体运营配置面（prj_agent_configs 扩展列，PUT /api/backoffice/agent-configs/executor 同一通道，留痕同机制）；缺省＝开、deepseek-v4-pro、60 文件、20 字；null 清空回落代码缺省。档位名不做白名单校验（同 modelId 口径）；阈值同口径不校验（0＝恒升强档是合法运营选择，错配经留痕写回可回滚）。

**决策可观测（哪段用了哪档、为什么——留档可查）**：收尾卡 `closing.modelTier`（收口尝试的档位＋来源 routed/pinned/default＋升档理由＋判定依据快照——随对话史落库；快档/兜底/钉死判定不携理由，只记为什么升）＋ `durationBreakdown.attempts[].modelId`（逐尝试档位，失败尝试同携——重试升档可归因）＋每次判定结构化日志；失败段（无收尾卡）以日志为留档面。前端不渲染（平台分析口径，同 durationBreakdown 先例）。

## Considered Options

- **模型档位按片预测式分类（长描述→强档启发式单信号）**——拒绝：单信号预测不可靠（历史失败才是难活的直接证据）；三信号 OR 组合零预测层（不训不猜），每个信号都是平台可观测事实。
- **权重评分制（信号加权打分超阈升档）**——拒绝：阈值三件已够，权重是伪精度（无校准数据）；先例同「收敛度不搞百分比」的缺乏依据即不做。
- **人工覆盖即钉死（覆盖在场路由让位）**——拒绝：钉死被「人工改档」隐式触发——运营按既有改档 SOP 换档即静默关掉路由（陷阱面），且快档位与「开路由」互斥（换快档必须覆盖＝钉死）。取「覆盖＝兜底基础档、钉死＝显式关路由」：路由判定优先（issue 原文首选形），改档不改变路由状态。
- **路由决策独立落表（新表存每次判定）**——拒绝：收尾卡载荷已随对话史落库（可查面在位），再立表属双写面投机；触发器＝需跨项目聚合分析路由决策（如运营看板）时再立。
- **路由默认关（保守翻转，稳定后再手动开）**——拒绝：无信号触发时行为与现状全同（缺省快档），唯一默认行为差异＝失败重试升强档——正是本机制的核心收益（难活强模型）；「缺省开＋显式关断钉死」比「缺省关＋手动开」少一次全平台操作。
- **强档固定 deepseek-v4-pro 不可配**——拒绝：换模型不发版是本面既成目的（modelId 无白名单先例），强档同口径可配。
- **文件面用 find 全量计数（含 node_modules/未跟踪件）**——拒绝：段起点工作区在收口 commit 上、git 跟踪≈全量，find 计数连依赖目录一起数反而失真；git 不可用（采集失败）降级无信号已覆盖。

## Consequences

- 智能体运营配置值面八件（原四件＋路由四件），留痕与读面同扩；admin 仓配置页随 API 增量对齐（跨仓交接口径）。
- CONTEXT.md 新词条「模型路由」（与「智能体路由」词面分家：模型路由是模型档位判定、非智能体指派）。
- 快档缺省 + 路由升档后，Demo 阶段速度目标（#314 40 分钟量级带）的推算依赖活体对比（路由开/关/钉死三轮同任务各一轮，时长·质量·token·判定分布留档——demo-stage-model-tier.md §六，实施期活体归 spec 收口票 #357）。
- 文件面计数每尝试一次 exec（沙箱内 git 秒级），失败静默降级；钉死路径（路由关）零采集（判定先于采集，exec 不白跑）。
