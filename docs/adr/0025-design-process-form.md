# 设计过程形态：会话结构、候选与版本分家、画面渐进呈现与设计先行序

设计能力线过程形态裁决（2026-10-03，#274，承 ADR-0023 定位、ADR-0024 载体，依据 docs/research/2026-10-03 四路快照——Stitch 为过程形态正本、Replit Design 为双终点同构）定案：**会话结构＝每设计物一个设计会话、按清单序串行**（PRD 完自动起、清单序即执行序、改序＝改 PRD），**改稿同会话继续**——run 每轮换会话是因为编码交接物可物化，审美上下文物化不了（「刚才那稿的颜色再亮一点」靠会话连续性）；内部切分对用户透明，用户感知＝stitch 式连续对话。**过程呈现同构复用**：设计执行体也呈现为直播卡（计划区＝设计物清单对偶切片清单、活性行＝出稿动作、解说坍缩），事件封闭集零新增、run-start.agent 加 designer 值——「不挂 run 词条」是域模型口径（两套产出逻辑），事件总线是平台公共设施不必分家。**多稿**：一次默认 3 稿、数量 1–5 经对话调，v1 零参数面（stitch 式数量×发散度×五轴控件是独立工具形态的产物——无对话通道才需要控件；备案触发器＝用户真实表达不出发散度时再 UI 化）。**候选与版本两套语义、不打通**：候选集＝设计过程内的横向工作集（改稿产新代、每代不覆盖前代、旧代全部保留——stitch 空间并置原则），版本流＝纵向定稿点序列（只有定稿动作成版、git commit）——回滚回不到中间候选不是缺口（定稿前用户在候选集直接挑旧代，无回滚需要），落选稿永不入交付物包（#272 已定）。**渐进呈现（stitch 参照、用户拍板硬要求——效果对标「看着画面一点点画出来」，实现有困难再沟通、不预设降级）**：主感知面＝成果区设计稿 tab——界面类稿复用预览全套渐进机制（可访问前步骤占位「正在绘制首页稿」、可访问后随编码逐步显现），平面类位图＝出图占位→图一次到达（模型 API 一次返回的物理限制，非降级），多稿逐张到达不等齐；**对话区零新 part 型**——直播卡照常（活性行「正在出第 2 稿」）、稿到达以解说播报、设计会话收口走收尾卡（复用 closing 扩载、带本轮稿清单与去向）；稿卡嵌对话流为增强备案（触发器＝用户在对话流找不到稿的真实抱怨）。**设计稿范式（tab 簇新范式注册项）**：分组稿卡阵列——按设计物分组、代际排列并置，点开预览（界面类可交互、平面类大图），挑选＝点选稿卡为作用域（后续改稿作用于它）、定稿＝稿卡上的显式动作；不做自由拖拽画布（stitch 画布是工具主体形态，我们是 tab 级呈现面；备案触发器＝稿多到网格阵列不够组织）；设计过程启动时自动挂载（对偶订单范式先例）。**在途插话**：同构迭代排队——设计执行体在途的新意见排队、当前稿代收口后受理；实时 steer 打断为备案（触发器＝单稿生成时长长到排队成为真实痛点，agentscope 真中断机制为前置）。**切换与分叉呈现**：终点类型控件长在设置 tab（低频重大动作归属性之家），切换受理时选作用域（全部页面 / 从功能清单勾选——页面级锚定从功能清单来）；转系统开发的出口长在定稿收尾卡（与常驻确认下单并列），设置面同控件可达；对话提设计仍只建议不动手（ADR-0024）。**设计执行体无 shell**：工具面＝写文件件（界面类稿落工作区）＋出图工具件（引入与否随 #275 档位裁），技能 scripts 结构性不发放（a-only，同主智能体口径）；技能指派进设计执行体槽位（智能体运营配置三座已立）——雾区「技能线接口」毕业。**系统＋设计项目＝设计先行**：PRD 完自动起设计（与设计主线同触发律），设计范围＝功能清单页面集（不另立设计物清单正本、防两处正本——「设计物清单」章只在设计主线 PRD 存在），全部页面逐件推进，定稿自动起首个构建（起跑上下文带稿、无门——定稿已是显式动作）；「系统在途→定稿起更新 run 对齐」留给中途切换路径；设计主线转系统开发＝PRD 重写系统形后同序（ADR-0024）。体验手感（稿卡视觉、代际呈现、「长出来」的实际效果）归 #278 原型票验证——本票收语义与形态方向，stitch 参照的实现困难在原型票现形再回来沟通。

## Considered Options

- **整程一个长会话（所有设计物混做）**——拒绝：上下文越滚越重、探索史互相污染；每设计物一会话＋清单序串行才有计划对应物。
- **每轮改稿新会话带交接（run 严格同构）**——拒绝：交接物承载不了审美上下文，探索就断了；改稿同会话继续。
- **新开设计事件族（design-start/design-finish）**——拒绝：假隔离——域模型不挂 run 词条 ≠ 公共事件总线分家；封闭集零新增、agent 枚举扩值即达。
- **stitch 全参数面（数量×三档发散度×五轴做 UI 控件）**——拒绝：投机性复杂度——参数面是独立工具形态（无对话通道）的产物，对话区是更宽通道（自然语言即可表达「更奔放」「换配色方向」）。
- **候选稿自动成版（每稿进版本流）**——拒绝：版本流被候选灌满、定稿点淹没在探索里；**候选即版本（稿卡＝版本锚、挑选即回滚）**——拒绝：混淆探索与定稿点两套语义。
- **对话流嵌稿卡部件（新 part 型）**——拒绝（v1）：过程归对话区、产物归成果区（stitch「streams to canvas、对话管意图」同构）；备案触发器＝对话流找不到稿的真实抱怨。
- **自由拖拽无限画布**——拒绝：stitch 画布是工具主体形态（独立工具入口已出局，ADR-0023/#267 口径），我们是 tab 级呈现面；分组稿卡阵列是空间并置原则的最小落法。
- **设计执行体带 shell**——拒绝：写 HTML 落工作区无需命令执行；a-only 收窄信任面（同主智能体），技能 scripts 结构性拿不到。
- **系统＋设计系统先行（PRD 完起构建、设计只经中途切换）**——拒绝：一致性硬要求（走了设计路线做不出选的稿不如没有）下，系统先行再按稿改是双倍功；设计先行让系统从稿长出。中途切换路径保留给真正系统先行的用户。
- **实时 steer（在途插话打断执行体改向）**——拒绝（v1）：新机制且 stitch 协议未公开（#268 结论 4）；排队语义已验证、降级满足「可转向」承诺。

## Consequences

- CONTEXT.md 随改：设计过程（清单序逐件串行＋系统＋设计设计先行＋stitch 式感知句）、设计执行体（默认 3 稿＋无 shell＋工具面＋改稿产新代）、对话区（受理三职能体直播卡＋设计收尾卡带稿清单、稿本体不入对话流部件）、成果区（设计稿范式＋启动自动挂载）、技能（a-only 扩至设计执行体）、智能体工具面（槽位列举加 designer）。
- #277（一致性桥）随本票关闭解锁：定稿稿经起跑上下文/交接物的输入口径已定，「图片→结构化规范」提炼仍是核心决策点。
- #278（原型票）解锁：多稿＋挑选＋渐进呈现的可交互验证——stitch 参照的实现困难在此现形。
- 稿 HTML 伺服通道（设计稿 tab 的可交互预览）与文件区图片预览基建归 #276 图片管道票一起裁；截图渲染（HTML→PNG 衍生图）归 #275 出图档位裁——本票只定形态要求（点开可交互预览、多格式导出）不预设通道。
- 设计稿 tab 自动挂载对偶订单范式先例（范式注册表加项、启动即亮）。
