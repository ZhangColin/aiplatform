# 平台边界至生产承接：b 档重对位

> 本 ADR 改写自「平台止于支付完成」（#1/#4/#7 落定）——旧口径「支付完成即业务边界终点、交付/施工不在平台内」由 #308（商业终点 b 档）重对位，spec #320 实施序④落地（#336 合同、#337 付款、#338 生产承接）。旧决议 Consequences 末条「将来若把交付纳入平台，另起 effort 重开本决议」——触发器即本决定。

平台主链扩为「一句话需求 → 需求分析 → PRD 确认 → Demo 生成与迭代 → Demo 确认 → 签约付款 → 生产承接」。**平台边界从「止于支付」扩到「生产承接状态面」**：交付过程的前台承接页进平台——生产承接记录（挂项目、只建一次、两态后台人工推进留痕）＋前台六态纯推导视图（订单＋合同＋付款＋承接四源、不存储）；**已支付重定义＝开工条件满足**（合同签署完成 && 开工门节点全部到账，与生产承接触发同一判定）；**归档转后台人工终局**（交付完成、尾款核验后，不再自动）。平台内生产机制设计不做——生产承接是状态承接页，不是平台内生产（能力到位前不做）。

## Consequences

- 订单四态骨架不动、语义重对位：待报价＝确认 Demo 下单起；已报价＝后台落定报价＋范围文本后；已支付＝开工条件满足；已归档＝后台人工终局。
- mock 支付闭环退役（#337）——支付语义并入付款计划节点凭证核验路径（v1 只走线下转账＋凭证上传＋后台核验）；渠道真接留接口位（节点渠道类型枚举＋渠道流水号可空字段，端口不加宽）。
- 签约载体全立：合同六态全部后台人工推进、每次动作 append-only 留痕；签署与到账由后台人工承接，电子签/支付渠道真接是后续演化。
- 后台承接动作集扩展（跨仓 semgravio-admin#100，平台侧接口为正本）：合同状态推进/撤回/作废＋草稿重录、到账核验录入、生产承接更新、报价＋范围文本录入、付款计划节点录入与开工门设定。
- 用户在交付后的新需求 = 新项目新订单重新进入，归档项目不续用（维持）。
- 订单知识沉淀触发维持订单归档时、取版改合同冻结的 PRD 确认版本（无合同异常路径回退最新确认版）。

依据：#308（商业终点 b 档决议）、#317（合同·付款·生产承接对象设计）、#336/#337/#338（落地）。
