# 技能审核指引

后台技能安装、更新与指派的审核正本（条目化）。分层纪律正本在 [ADR-0021](../adr/0021-agent-operational-config-persisted-skill-snapshot-install.md) 与根级 `CONTEXT.md` 技能词条——内建工作协议只载身份/编排/约束/技能指路，方法论一律住技能层；本指引是其在审核动作上的执行面（#245 核验后，ADR-0021 过渡期的「软性暂缓方法论包指派」口径解除，本指引即现行正常口径）。审核材料：技能详情端点（frontmatter／正文／scripts 全文可读，所见即运行时注入面）＋指派双头预检端点（#255，非阻断提示）。

## 一、双向边界判断

边界判断是双向的（Replit 铁律反用）：

- **技能内容是通用开发规范**（与平台机制有结构性挂点、换方法论流派不变的做事方式）→ 该进内建工作协议，不该作为技能装载；
- **内建工作协议出现方法论**（特定流派的做事方式，换流派即变）→ 该迁出成技能，内建只留身份/编排/约束/技能指路。

判据同 #245 核验用的尺：机制挂点/换流派不变 → 留内建；否则属方法论 → 住技能层。

## 二、安装审核清单（条目化）

安装与显式更新重拉时逐项过（更新翻新的是内容面，同尺重审）：

1. **注入面**——逐件读完再下结论，不看摘要：
   - frontmatter 全量（解析态键值）；
   - 正文全文（frontmatter 剥离后的 SKILL.md body）；
   - scripts/ 全文（脚本是注入面，#253——只对带 shell 的槽位发放，主智能体结构性拿不到）。
2. **方法论重叠面**——对照该技能将指派槽位的生效工作协议（智能体运营配置生效值：库值优先、缺省回落）＋同槽位已指派启用技能。指派确认前跑指派双头预检（非阻断提示，判定权留管理员；预检「未执行」≠「确认无重叠」）。
3. **description 三要素**——技能路由质量在装时把关：
   - trigger（何时用）缺失 → **拒**；
   - scope（管什么）缺失 → **拒**；
   - 否定边界（什么时候不用）缺失 → 要求补，或明示豁免（软门槛——前两要素硬拒，此要素不自动拒）。

## 三、重叠处置分界

同类冲突的处置保持一致：

- **scope 含糊、改 description/scope 可消解** → 暂缓＋要求改（改后重审）；
- **职能正面相撞、不可消解** → 拒版本（拒的是该版本，可改后重提）。
