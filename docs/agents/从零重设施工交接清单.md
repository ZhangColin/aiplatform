# 从零重设施工交接清单

从零重设（总索引 #573）的全部决策票已闭（#574–#591）。本文把决议翻译成常规施工 issue 的口径与顺序——施工票走普通 triage，不再走 wayfinder。权威定案见 ADR-0054–0058；逐项判决、实验数据与重新考虑的条件见各 issue 决议评论。凡本文与 ADR 不一致处，以 ADR 与各 issue 决议为准。

决议语言纪律（全程适用）：每项改动记「进／不进＋什么条件下重新考虑」，不写版本路线；新增机制一律过准入标准（实验证明严格更好才进）；质量红线＝应用活着＋可迭代即可接受，长时间不好／无提高／更差才是问题。

## 施工总顺序

1. **阶段一 生成内核接线**——一切的前提，先把新链跑通。
2. **阶段二 旧栈清场**——新链接管后拆旧机制与死旋钮（可与阶段一同一批 issue，发布在新链上线后）。
3. **阶段三 生成过程呈现**——工具动作流＋收尾卡＋预览跟随。
4. **阶段四 对话面·迭代·版本**——两平面、跑前快照、自动成版与回滚。
5. **阶段五 底座修复**——日志审计出的模板／镜像／提示词修复点。
6. **阶段六 数据飞轮与技能清场**。
7. **阶段七 实测与验证**——唤醒耗时、live 回归、飞轮走查。

## 阶段一：生成内核接线（ADR-0054；#575 定案、#590 修订后实测）

- 提示词权威版本落代码：七行级（角色＋环境描述＋任务＋长文件拆分提示＋完成判据＋全程中文）＋完成纪律三句＋工具使用说明三句（照 DeepSeek Harness 原文、只换工具名）。**不开放后台直改**——改提示词＝改内核＝开 issue。
- 工具四件：`write_file`（覆盖全量写、**自动建父目录**）／`read_file`（带行号、可分段、有上限）／`edit_file`（局部替换）／`bash`（180s 超时）。
- 循环语义（#590 定稿）：一轮不调工具即结束、不做做完后催促（首建迭代同一条规则）；到护栏上限不掐断、关工具如实汇报；同一工具同样参数重复调用第 3／5／8 次只提醒、绝不拦截；输出截断与空回复＝轮次结束＋收尾如实告知原因（用户说「继续」接着跑）；输出上限是每次请求的配置开关（默认 32768、可调）。
- 开发服务器由平台起、常驻，模型不杀不起；完成判据＝`pnpm build` 过＋`curl 0.0.0.0:8081` 有响应。
- 运营护栏接线：300 轮／45 分钟／60M prompt（非工作语义、不重新标定）。
- 执行体装配原样保留为发动机（agentscope 两装配点、会话状态存储、(userId,sessionId) 串行、内核重试关停、上下文压缩），subagent 半边随委派机制闲置。
- **供给链接线警示（#583）**：每次模型调用照旧经「模型配置→候选队列→通道行」解析，用量事件照旧落账，不得直连 API。
- 施工注意（#590 判决 6）：回滚重启须带 build 或统一开发服务器形态，不得拿旧构建产物（.next 残留）冒充回滚结果。
- 基准口径（#590 定稿配置实测）：首建 10.6–16.5 分钟、¥1.30–2.07／次、完成度 47 完成／0 部分／0 未做；输出上限调低可回到 7–11 分钟档（¥0.8–1.4），代价是完成度。

## 阶段二：旧栈清场（ADR-0055）

- 生成执行栈组：13 条执行协议、切片与切片计划、单会话态／切片机器态两开关＋并行波次、会话车道（双池／错峰准入／优雅排空）、修轮、空转片拒绝／产出证明、续跑机器、AGENTS.md 注入／预置件写保护、子智能体委派、按槽位工具面装配＋增强开关、推迟清单、旧失败语义（片重试预算／跳片／阶段 0 中断）。
- 配置键拆除：`generation-stripes`、`generation-admission-interval`（#580）。
- 死旋钮清理（#583）：模型路由六件、升档窗口的配置键与后台面（路由三信号消费者全灭，重启条件见 ADR-0055 组⑤）。
- 审查与收口组：片轻验／验证子智能体、整轨终验、核心旅程清单、预览哨兵、收口三运营开关、finish_edit 更新收口件、入口文件完整检查与 git 成版收口半边（8081 探活保留＝预览转可用的门）。
- 风格与设计资产组：风格方向库、风格方向→设计规范物化链、规范三件套（token 写入／协议注入／收口扫描＋调色板收窄）、栈规则集注入、golden／硬链种子（ADR-0046 终局判定既成事实）。
- 呈现面连带：计划区两级、update_plan 步骤清单部件、切片级多收尾卡、「正在创建首页」渐进占位、轮次计数、文件树面板、解说直播（呈现重建见阶段三）。

## 阶段三：生成过程呈现（ADR-0057；#578）

- 活性行＝唯一实时状态行（bash＝命令原值剥壳定宽截断、write_file＝「编写【文件名】」）＋生成时钟（时间戳单源＝生成起点事件、前端每秒渲染、终态定格）。
- 模型文本一律不直播；生成自然终止后取末次文本落收尾卡「内核自述」（markdown 渲染）。
- 预览窗三段：占位态→探活通过即转可用→跟随模式（默认开＋「固定」开关；write_file 路径纯前端映射路由、仅路由变化才导航；组件／库文件不切页；降级自担不加机制兜）。
- 收尾卡＝一次生成一张、五字段：用时／判据结果（build ✓＋探活 ✓）／变更清单（git 跑前快照 diff：迭代轮文件级 ±行数＋单文件只读 diff；首建目录级汇总可展开）／内核自述／预览入口。
- 落库三件套：过程明细不落库；SSE 断线补发窗口承担短回放；界面侧轻会话消息落库＋REST 水合。
- 失败呈现：红行（label＋错误首行）＋失败终态明确展示＋重跑即恢复。
- 智能体事件部件模型收窄重建：保留工具动作部件三面语义（直播播报／成功不留史／失败留痕）、叙事段守卫、脱轨信号部件；步骤清单部件出局。

## 阶段四：对话面·迭代·版本（ADR-0056；#577／#586／#582／#591；施工落定 #624–#630）

- 对话面引擎：轻会话两职能＝访谈式澄清（提问给选项→用户选→下一问→模型觉得清楚即动手）＋纯答疑（只答不改）；工作区只读（read_file＋只读 bash）；**写通道唯一**＝工作区一切变更只经生成内核。
- 修改指令：对话面把定型意见蒸馏成自足任务句（原文＋讨论要点、指代词解析成完整句）交平台派发一轮内核重跑；拿不准宁可追问不误发（软确认）。
- PRD 完整文档（#624 改记）：迭代时内核把本轮需求并入 `docs/PRD.md` 对应章节、不在文末堆积原始意见、不设固定「迭代节」末尾堆积节；平台不写 PRD、不追加原始意见。原因：用户要求 PRD 始终是一份完整、内容在正确位置的文档。在途意见追加即排队、当前生成不打断、界面轻提示「已记下，下一轮生效」。
- 跑前快照链：界面侧 git init＋ignore 权威集四件（`node_modules/`、`.next/`、`.pnpm-store/`、`data/`）＋每轮生成开始前自动 commit（实测首次全量 104–156ms、增量 121ms）；内核不知道 git。
- 自动成版：每轮生成探活通过后平台把当时工作区提交为**用户面版本**（git 提交，`Platform-Version`＋`Run-Id` trailer，主题＝用户那句话；版本序列＝按标记过滤的 git log、不新增表）；单轴时间线（时间＋用户那句话＋预览入口＋「回到此版」）。
- 旧双轴版本面退场（#628／#630）：Demo/PRD 版本表、双轴版本记录抽屉、「查看当时」快照容器与预览网关快照子域路由整条拆除；商业确认/订单改接用户面版本（「确认此版本」标记当前用户面版本，下单/合同冻结收敛为单版本号，#629）。
- 回滚：代码整回该版快照＋重启服务（带 build 或统一开发服务器形态）＋成新版本 vN+1（单线前滚不叉枝）；**活库不倒带**；破坏性 schema 变更导致旧版起不来＝明确展示＋建议回最新版或提修改意见。
- 新失败语义：明确展示＋重跑即恢复、不自动重跑。
- 成本口径：不设钱门（60M prompt 兜底即失控兜底）；收尾卡不加成本显示、运营面成本切片可见（deepseek-flash 峰时价：单轮迭代最坏口径 ¥6–9、实算个位数元以内；首建 ¥1.3–2.1）。

## 阶段五：底座修复（#588 移交 9–15 ＋ #590 顺带发现）

日志审计定案：技术坑不进知识库、直接修底座（各改一两行全体消除；坑合计仅占每 run 约 6–10% 轮次）。

- 提示词示例启动命令（`pnpm start -- -p 8081`）与模板 `start` 脚本对不上——改其一；改提示词须按准入标准补一次对照跑（#588-9）。
- 模板有 `lint` 脚本无 ESLint 配置——补 `eslint.config.*`（#588-10；run3 实证 10 轮／66s）。
- 镜像缺查端口的小工具——加 fuser／lsof（#588-11）。
- 镜像里有浏览器与 playwright、工作区解析不到——接通工作区可用（#588-12）。
- 内核运行时在服务器日志留一份工具调用记录（#588-13；新坑处置＝人看日志、开 issue 修底座）。
- write_file 自动建父目录＋输出上限开关——平台实现随内核四件落地，确认与实验脚本缺陷不重演（#588-14）。
- 「可靠的重启命令」「改文件方式」——已由 #590 定案：服务平台常驻、工具四件照给（#588-15 已结）。
- 追加修改重跑演示数据脚本会清掉用户录的数据（`TRUNCATE … RESTART IDENTITY CASCADE` 实证两次）——模板 seed 改幂等或可重入＋提示词纪律（#590 七·1）。
- 容器时区＝UTC、页面时间慢 8 小时——镜像设 `TZ=Asia/Shanghai`（#590 七·2）。
- 多数新应用 favicon 404——模板补网站图标（#590 七·3）。
- dev server 一次在 `pnpm build` 后消失（原因未查明、候选＝build 与 dev 目录冲突）——底座排查（#590 修订·六）。

## 阶段六：数据飞轮与技能清场（ADR-0058；#588；施工子票 #638／#639／#640／#641／#642／#643／#644）

知识侧：

1. 需求文档入库触发点从订单归档改挂成版动作：读工作区最新 `docs/PRD.md`、同项目只留最新一份、不审即可被找到、失败不阻断成版。——**已落 #640**（异步单线程队列挂成版动作，工作区读取／分块／向量／登记失败一律降级不阻断；停用状态跨重新入库存活）。
2. 事后提炼链：每出一个用户面版本，便宜模型读「自上次提炼以来新增的修改意见」提最多 3 条候选经验，带来源三件（项目／版本／原句）落待审表、过现有静态扫描；模型调用走供给链、用量落账。——**已落 #641**（refinement 边缘点、失败窗口由下一版本自然重试、无修改意见不调模型）。
3. 人审三键（激活／拒绝／改类别）补「来源回溯」（能点开看源项目与原句）。——**已落 #642**（队列行与详情返回来源四件；同步拆在途名额与序号约束，上限只由每次提炼最多 3 条保证）。
4. 两处小修：访客没填需求描述时不检索；命中块开头加「不要向用户提及其他项目」。——**已落 #639**（保护句与「非用户确认」限定语并存）。
5. 命中留痕（项目／时间／命中条目／检索是否降级），且命中块服务重启后可恢复（原为进程内缓存重启即丢）。——**已落 #639**（会话装配从最近一条留痕重建注入块，不重检索；项目删除级联清留痕）。
6. 向量小服务的存活状态在后台可见。——**已落 #639**（只读健康读面：可用／不可用、检查时间、耗时；探活失败不影响检索或入库）。
   - 生成侧不再收知识（拆生成执行体知识命中前置注入，生成只读当前项目需求文档）——**已落 #639**。

技能侧：

7. 清掉砍掉的件：技能预检端点与 `skillcheck` 边缘点配置；`propose_skill` 工具（全槽位）；`skl_skill_drafts` 的草稿／晋升／拒绝端点；`propose_sediment` 工具的 main 实例；`AgentProfile` 主智能体协议第 19／20 条与能力清单两句；`SEDIMENT_NUDGE_TAIL`。表与存量草稿的清理方式由本阶段施工 issue 定。——**已落 #638**（预检端点／应用服务／响应结构／`skillcheck` 边缘点全拆，V91 迁移删 precheck 配置与留痕；自荐两件连同提示与提醒退场；技能草稿表与四端点拆除；技能槽位收窄 main／executor 并删 subagent 指派行）。
8. 留着的件不动：内置技能「需求文档写作」、后台安装／启停／指派、使用计数。——**未动**（#638 原样保留）。
9. 主智能体首建问答链三处最小修正（⚠ 项，用户已单独点头）：两个自荐工具连同提示与提醒摘掉；加第 6 条限定语一句；加「未填需求不检索」判断。访谈编排、五问、需求文档写作技能零改动。——**已落 #638＋#639**（自荐工具与提醒归 #638；第 6 条限定语与未填需求不检索归 #639）。
10. 实证两步：上线前一次人工走查（现有需求文档入库、同类型新需求开／关命中各跑一次，人眼看相关性、问得更准、对话不提其他项目）；上线后持续看三个数（首次生成后提了几轮修改；其中几轮写明没做对；有命中与无命中项目的差）。——**由用户统一测试承接**（三个数读面由 #643 提供：按项目的修改轮数／没做对轮数、命中与无命中分组汇总）。
