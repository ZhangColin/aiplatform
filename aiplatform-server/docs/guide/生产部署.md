# 生产部署

> 平台生产部署统一入口。此前部署知识散落在各处（预览网关、各 compose、环境变量），
> 本档收口。两处「缺了起不来」的硬约束单独强调：数据库必须 pgvector（§2）、
> embedding 必须可达（§3）。
> **#386 起平台是共享基础设施（deploy/infra：nginx＋PG＋redis）的普通接入方**——
> 本档 §1/§2/§6 的历史形态（自建 PG/redis、手起网关容器）已被部署文档的新形态取代，
> 权威操作口径以 `deploy/部署文档.md` 与 `deploy/infra/README.md` 为准；本档保留
> 后端配置项语义（§7 环境变量）与预览机制架构说明（§6 上半）。

## 1. 拓扑总览

| 服务 | 端口 | 部署形态 | 来源 |
|---|---|---|---|
| aiplatform-server（后端） | 8888 | Docker Compose | `deploy/server.compose.yml`（#386 起，含 embedding） |
| aiplatform-web（前端） | 3333 | Docker Compose | `deploy/web.compose.yml` |
| 共享 nginx（semgravio-nginx） | 80 / 443 | infra 三件套 | `deploy/infra/`；平台 conf 经门禁装 conf.d（§6） |
| embedding（fastembed） | 9091 | server compose 同栈（#386 归位） | `deploy/embedding.Dockerfile` |
| PostgreSQL | 5432 | infra `semgravio-pg`（webnet 内 DNS） | `deploy/infra/`；**必须 pgvector**（§2） |
| Redis | 6379 | infra `semgravio-redis`（requirepass） | `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` |
| identity / app-registry | 10001 / 8088 | 外部（semgravio-identity） | OIDC + 机机签名 |

后端与前端走 `webnet`（external 网络）；预览路由在共享 nginx（双挂 webnet＋previewnet），
工作区容器走 `previewnet`。部署面**没有 compose 与配置文件之外的手工容器特例**
（旧 `aiplatform-gateway` 手起容器已随 #386 退役）。

## 2. 数据库（必须 pgvector）

平台库**必须带 pgvector 扩展**，这是硬依赖、不是可选：

- Flyway 迁移 `V1__baseline.sql` 第一步即 `CREATE EXTENSION IF NOT EXISTS vector`；
- `knw_chunks.embedding` 是 `vector(512) NOT NULL`，检索走 HNSW 余弦索引。

缺 pgvector 时 Flyway 在第一步就失败，**整个 schema 建不出来、服务起不来**（不是知识库
功能不可用，是连表都建不了）。

- 库要**预先建好**（Flyway 只建表、不建库）；表由 Flyway 启动时自动建
  （`baseline-on-migrate`）。
- 连接凭据走环境变量：`SPRING_DATASOURCE_URL` / `SPRING_DATASOURCE_USERNAME` /
  `SPRING_DATASOURCE_PASSWORD`（见 §7）。

### pgvector 安装（按实例形态选一条）

平台已验证 pgvector 0.8.x（`knw_chunks.embedding` 为 512 维 `vector` 列）。
扩展随 PG **主版本**锁定（18.x 互通、跨主版本不兼容），产物主版本必须与实例一致。

1. **Docker / CI（首选）**：直接用自带扩展的镜像 `pgvector/pgvector:pg{major}`
   （CI 先例见测试环境部署.md §CI），零安装。
2. **自装实例（如 EDB 安装器版，无服务端头文件、源码编译走不通）**：从**同主版本、
   同架构**的现成构建拷入三组文件（PG 扩展同主版本 ABI 兼容，直拷可用）：

   ```bash
   pg_config --pkglibdir --sharedir        # 目标实例的两个落点（pg_config 在实例 bin/ 下）
   # vector.dylib（或 .so，随实例 DLSUFFIX） → pkglibdir     ⚠ 不是 lib/，拷错位报
   #                                                        「could not access file "vector"」
   # vector.control + vector--*.sql        → sharedir/extension/
   ```

   装完验证（凭据按实例口径）：

   ```bash
   psql -d <目标库> -c "CREATE EXTENSION vector;" \
        -c "SELECT '[1,0]'::vector <=> '[0,1]'::vector;"   # 期望 1（余弦距离）
   ```
3. **有服务端头文件的实例**：源码编译 `make PG_CONFIG=<pg_config> && make install`。

> 实例升级 PG 主版本时，pgvector 产物须随版本重拷/重编，否则 `CREATE EXTENSION`
> 直接失败。本机开发实例（EDB 18.3，5432）即按途径 2 装的 0.8.6，详见
> 本地开发启动.md §2。

## 3. embedding（fastembed，9091）

知识库文本向量化依赖本地 fastembed（BAAI/bge-small-zh-v1.5，512 维）。服务脚本
`scripts/embedding_server.py`（零框架依赖），接口
`POST /embed {"texts":[...]} → {"vectors":[[...]]}`。

本地启动与验活（`/health` 200 不代表模型可用，`/embed` 才触发加载）：

```bash
uv run --with fastembed python scripts/embedding_server.py
curl -s -X POST localhost:9091/embed -H 'Content-Type: application/json' -d '{"texts":["验活"]}'
```

> **生产形态（#386 起）**：embedding 归平台部署物——`deploy/server.compose.yml` 与
> 后端同栈编排（`deploy/embedding.Dockerfile` 构建，模型离线预置），webnet 内 DNS 名
> `aiplatform-embedding:9091`；`EMBEDDING_URL` 由 `.env.production` 供给（见 §7）。
> 验活：`docker exec aiplatform-embedding curl -s -X POST localhost:9091/embed ...`
> （口径同 `deploy/部署文档.md` §5）。

模型缓存：首次 `/embed` 才加载模型，缓存缺失时加载失败、服务照常 200。连不上
HuggingFace 时用 hf-mirror 预置缓存后 `HF_HUB_OFFLINE=1` 启动（布局与命令见
`docs/guide/本地开发启动.md` §2）。

## 4. Redis

生产配了 `REDIS_HOST` / `REDIS_PORT:6379` / `REDIS_PASSWORD`（#383：deploy/infra 的
redis 起栈即 requirepass，eu-1 现网迁移前无密码、迁移窗口随 infra 起栈生效；
`REDIS_PASSWORD` 无默认值、与 `REDIS_HOST` 同口径 fail-fast——缺了启动即
炸，不静默回落无密码连接）。注意：平台核心会话是内存态、**不依赖 redis
持久化**；redis starter 是 cartisan-web 的传递依赖（防重提交等能力用）。本地 health 已
关（`management.health.redis.enabled: false`）。

## 5. 后端（aiplatform-server）

`deploy/server.compose.yml`（#386 起；原 `docker-compose.prod.yml` 两个 compose 是
更早期的遗物，勿参考）：`app` 服务 `build` + `env_file: .env.production` +
`SPRING_PROFILES_ACTIVE=prod`，挂 docker.sock（沙箱机制）＋seal-archives 卷，无宿主
端口映射（走 `webnet`），healthcheck 打 `/actuator/health`；`embedding` 服务同栈
编排（§3）。

`application-prod.yml` 关键点：

- `app.workspace.preview-scheme: https` + `preview-base: ${PREVIEW_BASE}`（无默认，缺省
  启动即 fail-fast）。
- `sso.cookie-secure: true`（生产 https 必须）。

## 6. 预览路由（共享 nginx，#386 起）

平台预览经 nginx 网关按子域路由到工作区容器，并在 HTML 注入圈注脚本。生产用
`*.preview.{domain}` + wildcard 证书；开发用 `*.localhost`（浏览器原生解析到 127.0.0.1、
关 TLS）。决议正本见 ADR-0014。

### 架构

```
浏览器 → https://{id}.preview.{domain}/
        ↓ (443)
nginx 网关（server_name ~^(?<wsid>[0-9]+)\.preview\.{domain}$）
        ↓ resolver 127.0.0.11（Docker 内置 DNS）→ 按容器名解析
ws-{id}:8081（工作区容器，previewnet 同网，无宿主端口映射）
```

- 路由：一条通配 server 块吃所有项目——`{id}` 从 Host 捕获，`proxy_pass http://ws-$id:8081`，
  零 per-app 配置、零 reload。
- 注入：`sub_filter` 把 `</head>` 换成 `<script src="/.aiplatform/annotation.js">` 引用；
  脚本资产由网关自持，不进用户源码、不在容器内。

### 生产（共享 nginx 接入，#386 起）

部署形态不再是独立网关容器：平台 conf（`deploy/nginx/aiplatform.conf`）与资产
（代理/注入块、标注脚本、提示页，`deploy/nginx/assemble-assets.sh` 装配）经 infra
门禁 `install-nginx-conf.sh` 装入共享 nginx 的 `conf.d/aiplatform.conf`＋
`conf.d/aiplatform.assets/`——撞车即拒/语法门禁/失败回滚，目录挂载热更、不重建容器。
路由/注入/提示页语义与本节上面完全一致（块文件单源共用）。发布流水线
（`deploy/release.sh`）每次发布自动重装；操作口径见 `deploy/部署文档.md` §6。

TLS（转正式）：平台 conf 的 server 块换 `listen 443 ssl`＋80 跳转，证书经门禁第三参
装入 `certs/aiplatform/`（海外机 certbot DNS-01 一张双名证书 `<域名>`＋
`*.preview.{domain}`，conf 里路径写 `/etc/nginx/certs/aiplatform/...`）。后端
`app.workspace.preview-base` 切 `preview.{domain}`、`preview-scheme` 切 `https`。

**wildcard 证书（certbot dns-01）**——DNS-01 校验签一张双名证书（主站 `<域名>`＋预览
wildcard，部署文档 §12 同口径）：

```bash
certbot certonly --dns-cloudflare --dns-cloudflare-credentials ~/.secrets/cloudflare.ini \
  -d 'example.com' -d '*.preview.example.com' \
  --non-interactive --agree-tos -m ops@example.com
```

证书部署进 infra 的 `nginx/certs/aiplatform/`（整体目录经门禁第三参拷入）；续期由
certbot 定时器自动完成，续期后重跑门禁安装（或 `docker exec semgravio-nginx nginx -s
reload` 热载）。

> `unavailable.html` 是网关/共享 nginx 自持的上游不可达自恢复提示页（#180）：代理
> 失败族 502/504（nginx 自产错误码）回平台风格提示页＋自恢复脚本，主预览与快照子域
> 同生效；应用自身回的错误原样透传不被替换（不开响应拦截）。缺装不会让 `nginx -t`
> 失败（不校验 alias 目标存在性），死子域会回 404 而非提示页——部署后用上面的死
> 子域验证一次确认页在。

验证（`42` 换成真实 workspaceId，工作区应用已在 8081 起服）：

```bash
curl https://42.preview.example.com/ | grep -o 'data-aiplatform="annotation"'
# 上游不可达（#180）：死子域/休眠中回 5xx＋自恢复提示页
curl -s -i https://987654321012.preview.example.com/ | grep -E 'HTTP/|系统暂不可用|no-store'
```

「查看当时」快照路由（#141）同网关承载：`snap-{viewId}.preview.example.com`（单层
子域，同一张 wildcard 证书覆盖），只逛不换——响应不含圈注注入：

```bash
curl -s https://snap-483920104737.preview.example.com/ | grep -c 'data-aiplatform'   # 0
```

开发启动与圈注协议、未来演进（Traefik 备案）见 ADR-0014。

## 7. 环境变量清单（.env.production）

| 变量 | 说明 |
|---|---|
| `SPRING_DATASOURCE_URL` | 平台 PG 连接串（**必须是 pgvector 库**） |
| `SPRING_DATASOURCE_USERNAME` / `SPRING_DATASOURCE_PASSWORD` | PG 凭据 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` | Redis（#383 起密码必填，缺省 fail-fast，§4） |
| `PREVIEW_BASE` | 预览网关基域名（如 `preview.example.com`），缺省 fail-fast |
| `SSO_ISSUER` / `SSO_CLIENT_ID` / `SSO_CLIENT_SECRET` | OIDC（identity 服务） |
| `SSO_REDIRECT_URI` / `SSO_SCOPE` / `SSO_APP_BASE_URL` / `SSO_COOKIE_SECURE` | OIDC 回调/作用域/基址/Secure |
| `VOLCENGINE_API_KEY` | 火山方舟通道 key（ADR-0031：迁移种子注入 `prj_model_providers`，库为唯一正本；`DEEPSEEK_API_KEY` 为 deepseek 官方备胎通道种子 key，可选） |
| `OPENAPI_APP_ID` / `OPENAPI_APP_SECRET` | 机机签名（cartisan-openapi） |
| `EMBEDDING_URL` | embedding 地址（**待补**，见 §3） |
| `RESEND_API_KEY` | 验证码真发信（#375/#376）：Resend API key，手工追加；不设则验证码回落服务端日志、登录流程照常 |
| `MAIL_FROM` | 发件地址（缺省 `no-reply@semgravio.com`，发件人名「Semgravio」固定），可选 |

> `SSO_*` 缺了会出「client_id 空」之类症状，属启动前的硬前置；`VOLCENGINE_API_KEY`
> 缺了则 volcengine 通道行种子 key 为空——服务照常起、首次模型装配明确报错
> （无静默回落），部署时随环境一并注入。
