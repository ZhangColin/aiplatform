# 对话区过程呈现：收口定格留驻取代清空（动作组折叠控噪 → 成功无痕·失败留痕 → 步骤清单·常驻活性行）

run 过程呈现改版（对标 Replit 2026-01 redesign 后实拍形态）：工作消息改为「解说短段 + 动作组折叠行」交替竖流，动作组默认折叠控噪；砍掉步骤分组头（引擎 ReAct 内部步数对用户无信息，part-step 呈现退役）与全部过程耗时（口径结构性失真：计时起点锚在工具参数流式生成而非执行、信封 ts 广播时打点、两端时钟混用——修不值，砍）；run 收口时工作消息**原地定格留驻、不再清空**，收尾卡随后入流——消灭「结束瞬间界面跳变」。动作明细仍不落库（对话史口径不变，刷新后不回放）。

## Considered Options

- **单行覆盖**（标题 + 一行活状态、后行盖前行）：最简但丢可回视性，解说只能活在当下一行，且非 Replit 实态——被否。
- **保留逐步滚动、修三宗罪**（真实计时、补步骤描述、结束不清屏）：计时与步骤描述要动事件模型才能修对，是在错误形态上打补丁——被否。

## Consequences

- 修订 #65「动作明细不常驻」裁决：从「收口即清空」改为「当次会话内定格留驻、不落库不回放」。
- 收尾卡「用时」保留（后端实测口径，属轮末统计），与过程耗时砍除不矛盾。
- Replit 实拍的其余要素（回合级 "Worked for X" 行、checkpoint 卡含 Rollback、对话内计划卡）本次不引入，留待对应能力（版本回滚已有、计划卡无对应物）需要时再议。

## 修订（2026-09，#225 工作消息直播进度卡）

**窄幅修订：恢复 run 级「已运行 mm:ss」时钟，逐步耗时维持砍除。** 时钟单锚 = run-start 事件信封时间戳，前端每秒渲染、run-finish / run-failed 定格——当初砍全部过程耗时的三条失真理由（计时起点锚在工具参数流式生成、信封 ts 广播时打点、两端时钟混用）在「单一 run 起点锚」下不成立：run-start 只发一次（#84 静默重试不换锚）、时钟只表达流逝时长不比对绝对时刻。逐步（动作级）耗时维持砍除——三失真在动作层依然成立。呈现主形态随 #225 改版为恒定高度直播进度卡（计划区 + 头部活性 + 混合坍缩，详见 #225 决定集）；定格留驻机制不变。

## 修订（2026-09，#227 动作直播化，第二次窄修订）

**控噪机制由「动作组折叠」改为「成功无痕、失败留痕」。** 成功动作不再留静态条目，「N 个动作」动作组折叠机制退役（连代码带词条删）——#119 解说放宽后「人话变稀、残骸变多」的副作用随之消解，解说成为唯一的史；失败动作破例留痕（红行＝label＋错误首行，常驻红显不进坍缩——破例展开与停滚语义沿用 #225）。滚动面直播命令原值（execute label 动态化：剥壳、定宽截断）。静态面＝解说段＋计划区＋自检行＋失败红行＋收尾卡；排障抓手＝失败痕＋收尾卡变更清单（下钻回看全量动作明细备案，触发器＝真实排障回看需求）。定格留驻、不落库不回放机制不变。

## 修订（2026-09，#233 过程呈现第三波，第三次窄修订）

**引入 agent 自产步骤清单，与播报分工；活性行收口为唯一实时状态行；「恒定高度」判据退役。** 平台注册 `update_plan` 工具，agent 开工自产步骤清单并随执行发全量快照（稳定 id、标题、✓●○ 三态；拆分策略归 agent 侧、平台不内置步骤数约束，不产就不显示、解说兜底），映射为 part-plan 快照事件——不走动作行、不留动作痕、变化不单独播报；已收口步骤不可变、变更只允许未收口段＝提示词纪律（平台 v1 不强制校验，实测出现回改再加 store 级守卫，触发器留档）；不落库不回放、收口定格留驻；步骤不设 ✗ 态（失败由活性行红字与收尾卡判定承载，清单内无上下文的 ✗ 无信息）。呈现两级：生成轨＝切片级＋当前片步骤级同卡共存、各自收口，更新轨只显步骤级。职责分工定谱：播报＝执行过程的播放（live tail），与计划／步骤不重叠；三史源分工＝步骤清单（骨架·做什么）＋解说（过程·怎么做）＋收尾卡（结果·做了什么）。解说只承载人话——机器语法原文（模型脱轨发射的工具调用标记）经叙事段守卫识别即丢弃，根因修复归 agentscope-java 线、守卫为映射层兜底。直播行升级为常驻活性行（唯一实时状态行）、run 进行中常驻：动作在跑＝命令原值滚动、间隙＝无字打字点、失败＝红字、收口保留末行至收尾卡入流后随定格沉没；独立「正在干活…」字样行退役。稳定判据修正：#225 引入的「恒定高度」说法退役，判据＝不闪、不跳、不无意义震荡、高度随内容长。

**口径变化留痕**：本 ADR 首版曾将 Replit 实拍「对话内计划卡」列为不引入、留待对应能力需要时再议——当年否的是「计划卡无对应物」（平台无计划承载），非计划呈现本身不该有；今以 agent 自产步骤清单引入，口径变化在此留痕。它也与当年砍除的引擎 ReAct 步数分组（#115，不复活）是两物：前者是 agent 对外承诺的计划骨架，后者是引擎内部循环步数、对用户无意义。被否备选：复活引擎步数分组（理由同 #115）；步骤 ✗ 态与逐步耗时（维持砍除，理由同前）；平台侧推断补偿 agent 忘推进（如实滞留，不代演——忘推进就显示忘推进）；part-plan 携带计划来源标注（备案，触发器＝skill 管理线开票）；过程明细落库回放（维持 #117 关闭）。
