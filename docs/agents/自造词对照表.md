# 自造词对照表（旧文档用词 → 白话）

从零重设（2026-11）期间用 AI 技能流程产出的文档里有一批自造词。**2026-11-22 起全局规则「不自造词」生效，新文档不再使用这些词**；读旧的 issue／决议／ADR 时对照本表。

| 自造词 | 白话意思 |
|---|---|
| 图／地图 | 指 #573 这张索引 issue——「从零重设」全部决策的目录页 |
| 票 | GitHub issue |
| 腿 | 实验组。四组对照实验中的第几组；「腿④」＝第四组（不给模型任何预设、裸模型直接生成） |
| 壳 | 平台自己的网页界面（首页／需求分析／Demo 体验三页），区别于沙箱里生成的那个应用的预览 |
| 缝／接缝 | 交界处、集成点。「输入接缝」＝需求文档交给生成内核的入口 |
| 过堂 | 逐项审查、决定去留 |
| 三态判决 | 每个机制的三种结论：砍掉／原样保留／重建成后采用 |
| 族 | 放在一起审查的一组机制（六族＝六组） |
| 勾销 | 清单里核对划掉，表示「这项审过了」 |
| 喂料／直喂 | 给某张票提供输入材料 |
| 毕业 | 「还没想清楚的问题」变清晰、可以正式开票了 |
| 雾区 | 还没想清楚、暂时开不了票的问题区 |
| 正本 | 唯一权威的那份记录（「决议正本」＝定论的正式记录） |
| 界外 | 划出本次范围（注意：不等于砍掉，只是这轮不审） |
| Δ／Δ 门 | Δ（delta）＝新平台在裸内核之上多加的机制；「Δ 门」＝新增机制必须实验证明严格更好才准进的标准 |
| 薄壳 | 平台只是包了层界面、没加价值 |
| 锚 | 基准数字（如「18min 锚」＝首次生成约 18 分钟的实测基准） |
| 落档 | 写进正式文档、归档 |
| 死亡名单 | 被砍掉机制的清单 |
| 连带 | 一个决定随之带来的另一件要定的事 |
| 车道 | 测试分类；「live 车道」＝要连真实环境（真模型／真 docker）跑的测试 |
| 活体 | 连真实外部环境的测试 |
| 前沿 | 当前没有阻碍、可以开工的票 |
| 认领 | 把票分配给自己（防止两个会话同时做一张票） |
| 协议 A／B | 迭代实验的两种方案（B＝生成完就收工；A＝完成后还有收尾动作，实测更慢） |
| 供给判据 | 判断后端基础设施去留的标准：有人用→保留／没人用→砍／用法变了→按新用法简化 |
| 催续 | 迭代实验里的「推进模型继续干」的机制（催续协议 B 为施工采用形态） |

产品自身的业务词汇（五问、岔路口、圈注、封存、休眠等）是平台正式词汇，见根级 CONTEXT.md，不在此表。
