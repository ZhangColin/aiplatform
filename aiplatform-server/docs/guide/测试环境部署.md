# 测试环境部署

> `mvn test` 连独立测试库 `aiplatform_test`（与 dev 分库），不再碰 dev 的 `5432/aiplatform`。
> 决议正本见 ADR-0015。本档收口测试库的一次性置备、跑测方式、以及未来 CI 接入。

## 1. 为什么独立库

dev 库与测试曾共用同一库（`5432/aiplatform`），project 等六域的 `@SpringBootTest`
teardown 用全表 DELETE，`mvn test` 会清空 `prj_projects` 等用户真数据（issue #132）。
测试改用同实例独立库 `aiplatform_test`，全表 DELETE 在测试库上就地变正确。

## 2. 一次性置备（本机）

测试库需**预先建好**（Flyway 只建表、不建库；缺库测试报
`database "aiplatform_test" does not exist`，属正常响亮失败）：

```bash
PGPASSWORD=truth createdb -U postgres -h localhost -p 5432 aiplatform_test
```

- 与 dev 同 homebrew PG 实例（`postgresql@18`，5432，postgres/truth），pgvector 已装实例级；
  V1 的 `CREATE EXTENSION IF NOT EXISTS vector` 会在测试库上自动装。
- 表与 Flyway 历史表由 Flyway 启动时自动建（`baseline-on-migrate`），无需手工。

## 3. 跑测

```bash
cd aiplatform-server
mvn test
```

测试经 `@IntegrationTest`（`@SpringBootTest` + `@ActiveProfiles({"local","test"})`）激活
test profile，`src/test/resources/application-test.yml` 只翻数据源 URL 到
`aiplatform_test`，其余与 dev 行为一致。

## 4. URL 缝（未来 CI / 协作接入点）

`application-test.yml` 的数据源 URL 是环境变量可覆盖的：

```yaml
spring:
  datasource:
    url: ${TEST_DB_URL:jdbc:postgresql://localhost:5432/aiplatform_test}
```

本地零成本；未来 CI 或协作只需设 `TEST_DB_URL` 指向另一 PG 实例，测试代码零改动。

## 5. 未来 CI（备案，现不建）

引入 CI 跑 `mvn test` 时，起一个 pgvector PG service，设 `TEST_DB_URL` 指过去：

```yaml
services:
  postgres:
    image: pgvector/pgvector:pg16
    env:
      POSTGRES_DB: aiplatform_test
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: truth
    ports: ["5432:5432"]
    options: >-
      --health-cmd "pg_isready -U postgres" --health-interval 5s --health-timeout 5s --health-retries 5
env:
  TEST_DB_URL: jdbc:postgresql://localhost:5432/aiplatform_test
```

零置备 / 每次全新隔离的 Testcontainers 备选与触发器见 ADR-0015「未来演进」。
