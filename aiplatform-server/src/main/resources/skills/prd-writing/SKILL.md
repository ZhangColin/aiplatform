# PRD 写作技能

平台替用户梳理的需求文档撰写规范：面向非技术用户可读，固定章节依序为——需求背景、目标用户、核心场景、范围边界、关键约束、清单章、推迟清单、验收与待确认（系统形固定八章节；设计形无推迟清单章、为七章节）。

补全呈现口径（#461 新访谈策略；#538 起试用轨五问额度收口同口径）：访谈期对非必答缺口平台以补全直接决定，补全集中呈现在 PRD——直接写进相应章节的正文叙述（专业身份直陈决定本身，如「登录方式采用手机号验证码登录」），是确定的专业判断，不用「假设/如果/我猜」字眼、不自问自答；PRD 全文不区分用户答的与平台补的，不另设补全清单或标记。

清单章按项目终点类型走形（终点类型用 query_project_facts 查询；平台请求切换时会直接告知）：

- 系统形（终点类型＝系统、系统＋设计）：章节名「功能清单」——系统生成的直接依据：编号列出系统的页面与功能点，每点附验收要点（做成什么样算合格）。系统＋设计项目不另立设计清单：设计范围＝本清单页面集（平台告知过作用域的以告知为准），设计硬约束（系统构建遵循本项目定稿设计）写入「关键约束」章。
- 设计形（终点类型＝设计）：章节名「设计物清单」——设计过程的直接依据：编号列出各设计物，每件附用途、尺寸、风格要点与验收要点。
- 终点类型变更后修订 PRD 时，清单章必须随改到新形态（其余章节按新终点的交付语境相应梳理）。

「关键约束」章的风格方向行（系统形项目，ADR-0052——纯系统形才写，系统＋设计项目的风格方向走设计过程、不写本行）：写 PRD 时从平台每轮随附的「风格方向库·目录」中选定一个方向，在「关键约束」章以一行「风格方向：<方向名>」呈现（如「风格方向：清新教育」）——只从目录选、可按领域气质在同句括号内微调参数、不从零自造配色；选取不占访谈提问额度、不为选风格单独提问。用户后续想换风格会直接说——按意见受理修订本行即可，平台随下次构建派发重物化。

「推迟清单」章（系统形固定章节，ADR-0050——清单章之后、「验收与待确认」之前；设计形不设）：显式列出本期不做的功能面，编号平铺，每条＝推迟项＋示意级边界（界面走得通、数据真落库、外部副作用为零的具体形态，如「支付：下单结算界面走通，停在不真扣款」「通知：站内信呈现，不发真实推送/邮件」）。默认集聚焦业务向：支付停在不真扣款、通知站内呈现、多角色降单角色；外部集成 PRD 明确涉及时按需列入；技术类条目（性能优化/安全加固）不预置——用户不可见的加戏由范围边界章的总句治理；访谈没问出来、信息量不足的功能进本清单而非臆想补做。没有任何显式推迟项则整章写「本期无」。本清单与 saveBuildPlan 的 deferredItems 同内容同批产出（协议约定非机器闸：执行体「清单内不做、不自行加回」，平台不校验拦截）。

「验收与待确认」章保留但不再拦门（#462 去确认门——确认动作整段退役，本章条目不拦任何动作，只作呈现）：只收补全后仍无法决定、又不挡核心流程的缺口——缺了会建错方向的缺口是访谈期必答题，应经 ask_user 问掉、不进本章；收敛令后的未决缺口一律按推荐补全，也不进本章。章内平铺编号列条目（#462 起不再分两级、不设拦截级分组子标题——存量 PRD 里的旧分组标题平台解析时仅作界标容忍），每条开头用【维度】标注所属维度，维度词表固定五个：目标与角色、主流程、功能与边界、数据与约束、验收，并写明所缺信息与建议口径（如「【数据与约束】列表默认排序偏好未确认，建议按创建时间倒序推进」）；没有任何缺项则整章写「暂无」。待定项按最小可用缺省实现（ADR-0050，够走通主径即可），收尾由执行体说明所做取舍。

全文用平实语言写给非技术用户读：不堆术语、不用技术黑话，用户能逐块看懂。
