# 本地开发启动（dev 环境）

> 开发环境「从零跑起来」的统一入口，与「生产部署.md」对称。此前 dev 启动知识散落
> 在 nginx.conf 注释、ADR-0014、生产部署.md §6、本机依赖启动.md 多处——本档收口，
> 原「本机依赖启动.md」的有效内容（embedding 启动、登录联调、验收脚本）已并入本档
> 后删除；其中旧环境口径（5434 docker PG、仓库根 `.env.local`）直接作废不迁。

## 1. 拓扑（dev 口径）

| 服务 | 端口 | 部署形态 |
|---|---|---|
| aiplatform-server（后端） | 8888 | `mvn spring-boot:run`（`local` profile） |
| aiplatform-web（前端） | 3333 | `npm run dev` |
| 预览网关（nginx） | 80 | `docker run`（手起，§4） |
| PostgreSQL | 5432 | homebrew `postgresql@18` + pgvector，库 `aiplatform` |
| Redis | 6379 | 本机，密码 `truth` |
| embedding（fastembed） | 9091 | 本机脚本 |
| identity / app-registry | 10001 / 8088 | 外部（aieducenter-identity） |
| 工作区容器 `ws-{id}` | 8081（容器内，无宿主映射） | 后端按需自动起 |

后端/前端同机直连；预览网关与工作区容器走 `previewnet`（后端起工作区容器时自动
`docker network create`，无需手建）。

## 2. 前置依赖（数据面）

- **PG**：homebrew `postgresql@18`（5432，`postgres/truth`，pgvector 已装），库
  `aiplatform` 预先建好、表由 Flyway 建。`application-local.yml` 已切到 5432；
  `docker-compose.dev.yml` 里的 5434 是旧口径，别用。
- **Redis**：本机 6379，密码 `truth`（会话内存态，仅传递依赖需要，health 已关）。
- **identity / app-registry**：`identity.localhost:10001`、`localhost:8088`，外部
  aieducenter-identity 自起，本平台只依赖其端口（登录联调纪律见 §7）。
- **凭据**：SSO 七项 + `DEEPSEEK_API_KEY` + `OPENAPI_APP_*` 落 `aiplatform-server/.env.local`
  （gitignored）。缺了出「client_id 空」「DEEPSEEK_API_KEY is required」——见 §3。

### embedding（9091，base.knowledge 依赖）

本机 fastembed（BAAI/bge-small-zh-v1.5，512 维），脚本已收进仓库
`scripts/embedding_server.py`（零框架依赖，`POST /embed {"texts":[...]} → {"vectors":[[...]]}`）：

```bash
uv run --with fastembed python scripts/embedding_server.py
curl localhost:9091/health                            # → {"ok":true}
```

**`/health` 200 不代表模型可用**——模型首次 `/embed` 才触发加载，缓存缺失时加载失败、
服务照常 200（症状：embed 挂死或报 `Could not load model`）。起完先打一发验活：

```bash
curl -s -X POST localhost:9091/embed -H 'Content-Type: application/json' -d '{"texts":["验活"]}' | head -c 80
```

连不上 HuggingFace（fastembed 走 hf-xet，直连环境常见超时）时，用 hf-mirror 手工预置
模型缓存后离线启动（**不预置直接起会连 HF 下载挂死**）。缓存根 `~/.cache/fastembed`
（脚本显式指定，`FASTEMBED_CACHE_DIR` 可覆盖），模型为**平铺目录**
`fast-bge-small-zh-v1.5/`，内放五个文件：

```bash
DST="${FASTEMBED_CACHE_DIR:-$HOME/.cache/fastembed}/fast-bge-small-zh-v1.5"
mkdir -p "$DST" && cd "$DST"
for f in config.json tokenizer.json tokenizer_config.json special_tokens_map.json model_optimized.onnx; do
  curl -L -O "https://hf-mirror.com/Qdrant/bge-small-zh-v1.5/resolve/main/$f"
done
# 之后带 HF_HUB_OFFLINE=1 启动（从缓存离线加载，不碰 HF）
```

## 3. 启动顺序（从零）

```bash
# 1) 数据面：PG / redis / embedding / identity / app-registry（见 §2）
# 2) 后端（会自动建 previewnet、按需起工作区容器）
cd aiplatform-server
set -a && source .env.local && set +a
mvn spring-boot:run          # local profile 是默认（application.yml），无需显式指定
# 3) 前端
cd aiplatform-web
npm run dev                  # next dev -p 3333，后端地址默认 http://localhost:8888
# 4) 预览网关（§4）
```

> **`.env.local` 必须 `set -a` 导出**：文件是裸 `KEY=VALUE`、不自动导出，直接
> `source` 后 Spring 读不到环境变量，症状就是 `sso.client-id` 空。`set +a` 恢复。

## 4. 预览网关（nginx）

dev 用 `*.localhost`（浏览器原生解析到 127.0.0.1）、关 TLS、监听 80；生产才用
`nginx.prod.conf.template`（`*.preview.{domain}` + wildcard 证书）。dev 直接用
`nginx.conf`：

```bash
docker run -d --name aiplatform-gateway \
  --network previewnet \
  -p 80:80 \
  -v "$PWD/src/main/resources/docker/gateway/nginx.conf:/etc/nginx/nginx.conf:ro" \
  -v "$PWD/src/main/resources/docker/gateway/gateway-route.conf:/etc/nginx/gateway-route.conf:ro" \
  -v "$PWD/src/main/resources/docker/workspace/annotation.js:/etc/nginx/annotation.js:ro" \
  nginx:stable-alpine
```

> `$PWD` 指 `aiplatform-server/`。三处挂载缺一即断：`nginx.conf` 是 dev server 块、
> `gateway-route.conf` 是路由/注入块（被 server 块 `include`）、`annotation.js` 是网关
> 自持的圈注脚本资产。网关必须在 `previewnet` 已存在后起（即先起后端），否则
> `docker run` 报 network 不存在。改网关配置后须重建容器生效（`docker rm -f
> aiplatform-gateway` 后按上命令重跑）：单文件 bind mount 绑的是 inode，编辑器原子
> 写换 inode 后容器内路径悬空，`nginx -s reload` 会 ENOENT。

## 5. 端到端验证

```bash
# 后端
curl -s localhost:8888/actuator/health                    # {"status":"UP"}
# 前端
curl -s -o /dev/null -w '%{http_code}\n' localhost:3333   # 200
# 预览：{id} 换成真实 workspaceId，工作区应用已在 8081 起服
curl -s -o /dev/null -w '%{http_code}\n' http://{id}.localhost/          # 200
curl -s http://{id}.localhost/ | grep -o 'data-aiplatform="annotation"'  # 注入成功
curl -s -o /dev/null -w '%{http_code}\n' http://{id}.localhost/.aiplatform/annotation.js  # 200
```

SSE 事件压缩被 Next 默认 gzip 扣缓冲、`curl` 不带 `Accept-Encoding` 抓不到——问答卡/
错误提示静默这类问题必须浏览器级验证（`next.config.ts` 已 `compress: false` 关闭），
API 级冒烟会假绿。

## 6. dev ↔ prod 差异（一处对照）

| 维度 | dev | prod |
|---|---|---|
| 预览 base/scheme | `localhost` + `http`（代码默认，无需配） | `preview.{domain}` + `https`（`PREVIEW_BASE` 必填） |
| 网关配置 | `nginx.conf`（80，关 TLS） | `nginx.prod.conf.template`（443 + wildcard） |
| 网关启动 | 本档 §4 | 生产部署.md §6 |

`app.workspace.preview-base` / `preview-scheme` 默认 `localhost`/`http`（
`WorkspaceProperties`），dev 不用在 `.env.local` 里设；生产必须显式设（缺省 fail-fast）。

## 7. 联调与验收

### 登录（identity OIDC + BFF）

认证走 identity（`identity.localhost:10001`）授权码模式，BFF 三端点（`/auth/login`、
`/auth/callback`、`/auth/logout`）+ `/api/me`。本地纪律：**全程 `localhost`，禁混
`127.0.0.1`**（cookie 按域隔离不分端口，host 不一致 cookie 带不过、identity 白名单
精确匹配会炸）；`sso.cookie-secure=false`（http 下 Safari/Firefox 拒存 Secure cookie）。

冒烟登录（cookie-jar 走完整授权码链，供后续 `curl -b` 验收；凭据从 `.env.local` 读）：

```bash
set -a; source .env.local; set +a
./scripts/login.sh                  # 默认 jar 在 /tmp/aiplatform-cookie-jar
curl -b /tmp/aiplatform-cookie-jar localhost:8888/api/me   # → {accountId, displayName}
```

- 无会话访问 `/api/**` → 401；`/auth/**`、`/api/backoffice/**`（HMAC 机机签名）、
  swagger、actuator 匿名可达。
- 服务重启 → 内存会话丢 → 再走一次 `login.sh`：identity 侧 SSO 会话仍在，免密码直通。
- 三个实战坑：① identity 本地未配 PEM 密钥，**每次重启换临时密钥而 kid 固定**，本服务
  JWKS 缓存 24h 只按「kid 未命中」重拉——identity 重启后本服务要跟着重启（先 identity
  后 8888），否则验签静默失败（`/?error=exchange_failed`）。② 去 app-registry 取 client
  凭证（POST credentials）**会重置 secret**——取完在跑的 8888 还持旧 secret，`/token`
  报 401 `invalid_client`；取完凭证必须 `source .env.local` 重启 8888。③ identity
  id_token 的 `aud` 灌其全局 `identity.token.jwt.audiences`，本地已在 identity 侧把
  本平台 client_id 追加进 audiences 兜底（identity 正修落地后可撤）。

### IDEA 启动注意

IDE 不读 `.env.local`——SSO 变量须加进 Run Configuration → Environment variables
（或 EnvFile 插件勾选该文件）。漏注入症状：BFF 302 出去 `client_id=` 为空 → identity
报 `unauthorized_client` 跳 `:10002/error`。
