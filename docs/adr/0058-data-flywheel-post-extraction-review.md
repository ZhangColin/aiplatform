# 数据飞轮新形态：事后提炼＋人审生效＋经验只在需求梳理步起作用

知识与技能机制的重设计定案（承 从零重设总索引 #573，决议见 #588「数据飞轮」，2026-11-22 三轮裁决；前置＝#582〔飞轮重建成后采用，判据＝跨项目复利〕、#575〔内核单一输入＝工作区 docs/PRD.md〕、#577〔工作区写通道唯一经生成内核〕、#587〔首建问答与需求文档产出链原样不动〕）。事实面：旧飞轮在本机库里零数据（知识库 0 条、技能库 0 个、6 份自荐草稿全待审）；真实访客数据为零，飞轮价值目前没有证据——本形态按「最省、可验证」设计，价值由实证口径检验。质量红线照总索引口径：飞轮活着、能迭代即可接受；长时间看不到差别、或比没有飞轮更差，才是问题——届时重新讨论，不靠加机制。

## 决策

**飞轮不碰内核**。别的项目积累的经验只在一个地方起作用：访客描述需求、平台提问并写出需求文档的那一步（主智能体开场找相似需求——现状动作原样保留：访客的初始需求描述作检索词、混检、最多 5 条、作背景参考不作约束）。经验要进需求文档，必须经过访客自己回答确认。三项明确不进：平台不经确认直接把经验写进需求文档；让内核查知识库或读经验文档；对话面（修改那一步）参考经验（重启条件各附在 #588 决议）。

**学习材料＝两样**：①最新的需求文档（迭代后的最新版）；②访客每一句修改意见（时间线已定要记）。不为采集新增记录。问答记录单独学习不进。

**提炼方式＝事后提炼**：每出一个用户面版本，后台用一个便宜模型读「自上次提炼以来新增的修改意见」，提出候选经验（每次上限 3 条），进后台待审。生成过程不参与、不碰速度门；模型在干活时自己提议（旧 propose_sediment／propose_skill）、做完问访客，都不进。

**技术上的坑不进知识库，直接修底座**：内核反复踩的坑修进底座（模板工程、镜像、工具行为、提示词示例命令）；以后发现新坑＝人看运行日志、开 issue 修底座。为此内核运行时在服务器日志里留一份工具调用记录（施工项）。依据：六次真跑日志审计——跨项目重复的技术坑存在但合计仅占每次生成约 6–10% 轮次、几乎全是平台侧造成；模型自身知识不足导致的每次不超过 4 轮。

**入库与把关**：需求文档每出一个用户面版本自动入库一份（同一项目只留最新一份；读工作区最新 docs/PRD.md；没做出过能打开版本的项目不进；不审、入库即可被找到；后台停用原样保留；失败不阻断成版）。候选经验人审后生效：类别照旧三类（需求案例／功能模块／业务规则），审三件事＝真伪、重叠、来源可回溯（能点开看是哪个项目、哪句原话），三键照旧（激活／拒绝／改类别）。

**给谁用**：公共池——所有项目的经验汇成一个池子，任何访客的新项目都能找到；访客无感知照旧；命中块开头加一句「不要向用户提及其他项目」。同一访客的多个项目单独互通不进（重启条件：实证出现，届时归属复用账号体系）。

**技能的新含义＝两种，通道由人走**：A. 提问方法指南——某类应用该怎么问、推荐答案怎么给，由人从验证过的知识里整理，走现有后台安装与指派；B. 固化进平台的东西——底座修正、必配工具、模板现成件，开 issue 实现。「知识总结成技能」由人做：知识是每次告诉模型一遍的参考，技能是整理一次、长期生效的做法。自动通道（候选经验激活后自动变技能）不进。

**旧件处置**：内置技能「需求文档写作」、后台安装／启停／指派、使用计数——留着不动；技能预检、智能体自荐技能与草稿晋升、主智能体上的两个自荐工具连同提示与提醒（用户单独点头，动到 #587 不动的首建问答链）——砍掉；表与存量草稿的清理方式由施工 issue 定。

**两处小修**：访客没填需求描述时不检索（现状拿固定开场白去检索）；找相似条目的做法本身原样保留（重启条件：上线前走查发现找得不准）。

**实证口径分两步**：第一步「能用」＝上线前一次人工走查（现有几份需求文档入库，拿同类型新需求走一遍问答，开／关命中各跑一次；人眼看三件事：条目相不相关、问答有没有问得更准、对话里有没有说出别的项目）；第二步「有用」＝上线后持续看三个数（每项目首次生成后访客提了几轮修改；其中几轮是写明了却没做对——事后提炼时顺手分类；有命中与无命中项目这两个数的差）。只看趋势，不是严格对照。两个施工前提：命中留痕（项目、时间、命中条目、检索是否降级，且重启后可恢复——现状进程内缓存重启即丢）；向量小服务的存活状态在后台看得见。

## Considered Options

- **经验直接写进 PRD／内核可查知识库**——否决：飞轮不碰内核；经验进文档必须经访客确认。重启条件：实验证明内核拿到经验严格更好。
- **生成过程中自荐沉淀（旧形态）**——否决：改事后提炼；旧库零数据、自荐从未被用过（主智能体 32 次运行零提议）。
- **坑知识进知识库**——否决：坑几乎全是平台侧造成，底座改一行全体消除，记经验覆盖面窄。重启条件：实证出现「底座修不了、模型被告知就能避开」且反复出现的坑。
- **候选经验自动合并／自动变技能**——否决：把关靠人审；自动通道无实证需求。
