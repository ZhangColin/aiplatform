# 付费轨首建 PRD 确认门恢复与首建派发分轨

商业化改版一期计费访谈域定档（承 wayfinder 地图 #510、决议正本＝#515）。ADR-0039 去确认门的**付费轨部分改判**：翻转后首笔大额消费＝整场首个构建（一切智能体调用走扣减，ADR-0047），继续讨论的访谈聊得深聊得细、PRD 经多轮修订——在未经用户点头的 PRD 上开跑烧钱不可接受，付费轨首建前恢复用户确认动作。恢复的是 #462 之前的**原确认动作形态**（PRD 文档面按钮＋端点），不是新机制。承 ADR-0047（付费状态、段间硬门）；承 ADR-0048（五问额度、岔路口卡、试用态派发门）。

## 决策

**确认动作恢复＝原形态回来、只管付费轨首建一次**：PRD 文档面确认按钮（「确认 PRD，开始生成」）＋确认端点，确认即派发首个构建。范围收窄为一处——试用轨不加（岔路口三选卡即点火动作、PRD 已照产可看，ADR-0048）；首建之后的迭代维持受理即派、不逐次确认（意见即确认信号，#450/#462 迭代口径不动；钱面由段边界检查管，ADR-0047）。付费轨快道同律：用户明确说「直接开始做」视同确认、直接派发（与试用轨收敛令快道对称，ADR-0048）。

**版本机制零改动**：确认不写版本行、不恢复「确认即成版」（#330 写表语义不复活）——版本表维持 ADR-0039 现状全域一致（构建基准序、Demo 类 run 起跑自动记行、同文幂等跳过）。确认与派发之间无 PRD 变更路径（派发同步），首行快照即确认内容的自然锚。试用轨（选择即建）与付费轨（确认后建）的唯一差异＝触发源，不进版本语义。

**自动派发两入口整体退役**：原 savePrd 自动派发两入口（首产回调 `dispatchFirstDemoOnPrdProduced`＋轮收口兜一轮）随两轨都改用户触发而退役——试用态＝岔路口选择/快道触发（ADR-0048 切片②）、付费态＝确认动作触发（本 ADR），全域不再有无条件自动路径。确认按钮呈现条件＝付费态∧PRD 在∧首建未派发；点击幂等（派发幂等既有）、失败重试走「继续生成」既有机制、确认不重复。

**岔路口三选（ADR-0048 两选的修订）**：试用态岔路口卡直接三个按钮——继续讨论（由我的账户付费）／继续讨论（由本项目付费）／立即生成。扣费源选择上卡（ADR-0048 切片③「登录→选源→按池判定」子流程压平为一步；源一次性选定口径不变，ADR-0047）：访客选付费项才走 M01 登录＋项目平移；所选池无余额→引导充值、到账即翻转回访谈继续（五问额度解除）；后台已充项目池的项目选「本项目付费」直接翻转、免登录（销售演示动线）。意见拦截卡同律（源选择＝用户的第一笔付费选择，翻转门②，ADR-0047）。

**两轨判定＝扣费域单源**：试用/付费判定不做第二份标志——扣费源字段未设＋未翻转＝试用（五问额度协议、岔路口、拦截闸）；扣费源选定＋翻转（钱的承诺事实）＝付费（原访谈协议、确认门、段边界检查）。存储与翻转机制归 ADR-0047 实施切片①（billing 底座），访谈协议选择、派发门、拦截闸三处消费同一读点。

## Considered Options

- **确认标记轻机制（不恢复 #330、发明「标记＋派发」新形态）**——否决（用户裁定）：比恢复原动作更复杂；原来有确认动作、上周刚退役，「恢复回来」最直白，不发明第三种东西。
- **付费轨也无门化（PRD 产出即自动建，访谈协议自然保证问到无疑）**——否决（用户裁定）：继续讨论聊得深聊得细，更需要一个确认步骤；翻转后首笔大额消费必须显式点火。
- **恢复「确认即成版」写版本表**——否决：与起跑记行形成双写点、确认行 run_id 空洞（版本行不可变不能回填）、两轨两套版本语义；确认只管派发、记行归起跑单点。
- **付费轨首建也走岔路口式选择卡**——否决：岔路口是试用态三岔（账户/项目/免费体验），付费态无免费岔可岔；确认按钮随 PRD 文档面（被确认的是文档）。
- **迭代期逐次确认（大改停派复活）**——否决：意见即确认信号；#334/#462 已裁，钱面归段边界（ADR-0047）不归派发门。
- **轮收口兜一轮保留为付费态兜底（未生成＋已确认即派）**——否决：确认按钮幂等可重点、卡面持久（未派发即在场），无需自动兜底；少一个自动路径少一类竞态。

## Consequences

- ADR-0039 加补记（适用面收窄：去门化维持于试用轨首建〔选择触发〕与两轨迭代期；付费轨首建确认恢复归本 ADR）；ADR-0048 加补记（岔路口三选、源选择上卡）；#450/#462 票内留痕评论。
- CONTEXT.md：「PRD 确认」词条回归（语义重立：付费轨首建点火动作，非旧确认门）、「岔路口」词条改三选、「扣减源」词条补岔路口选择点、「付费状态」词条补确认门、「PRD 版本」词条补确认不改版本语义、「对话区」词条「不设专设按钮」句补付费轨例外；「生成」词条触发机制句随实施切片改写（词条不超前于代码，ADR-0048 先例）。
- 实施切片（并入 ADR-0048 切片②③同栈、不建票）：② 岔路口卡与派发门扩为三态分叉（试用＝选择/快道、付费＝确认端点＋按钮、自动两入口退役）③ 引导流压平（三选上卡、M01 拉起、按池判定、到账翻转）；确认端点为前台接口，若实施牵动后台读面则走接口变更清单票惯例。
- 岔路口三选文案初稿随 #515 决议入票（可随实施票打磨）：继续讨论（由我的账户付费）／继续讨论（由本项目付费）／立即生成（按当前 PRD 生成系统、平台承担，想修改再付费继续）。

## 补记（2026-11-24，#604 首建失败后的重跑入口）

「失败重试走『继续生成』既有机制、确认不重复」一句随从零重设失败语义改判（ADR-0055／0056：失败＝明确展示＋重跑即恢复、不自动重跑；「继续生成」断点续跑入口随续跑机器退役）。现行口径：首建终态失败／用户停止收口时，平台清首建点火位（`generation_requested_at`）——岔路口卡与 PRD 确认按钮按「首建未派发」呈现条件复现，用户重走点火入口即重跑（在既有工作区重跑内核，已落盘成果保留、不携错误现场）。确认按钮在首建失败后复现、重确认即重跑：付费轨每次重跑前仍有一次显式点火，不构成自动重试；点击幂等不变（在途重复确认 409 PRJ_017）。优雅关停中断不清位（关停期不落库，ADR-0043），重启后由 `POST /generate` 重跑入口恢复。前端「继续生成」按钮件的拆除归 #608（呈现面清场）。
