# 技能自产线：库制技能草稿＋平台自建自荐＋后台人审单级晋升

技能自产线 grill（2026-09-28，#244，依据 docs/research/2026-09-22-skill-line-mechanism-and-benchmark.md §1/§3/§5.8 与两轮代码侦察）定案：智能体运行中自荐技能草稿、后台人审晋升入技能库——与知识沉淀（事实性）对偶，沉淀过程性能力。核心决策：**库制草稿**——草稿住平台库独立草稿表（skl_skill_drafts，带血统〔来源项目、run、槽位〕与扫描回执），不污染 skl_skills（「库行即正货」不变式保持）；晋升＝草稿行读出→skl_skills insert，SkillSource 列化加 SELF_PRODUCED（V15 注释预留的正缝）。**平台自建自荐工具**：入参照框架 schema（name/description/body）但不设 scripts 参数——自产内容面 a-only 结构性锁死（信任血统窄于管理员亲手挑的安装包）；校验照框架常量（name 正则/长度上限等）＋撞名拒（查库与在途草稿）；写入前跑 SkillSecurityScanner 静态件（DANGEROUS 拒写、findings 随草稿留档），定位廉价哨兵非安全边界；AgentTool 归骨架、不设开关。**三职能槽位皆可自荐**（run 执行体绑 run 收口前、子智能体绑任务回交前、主智能体不绑时刻；软指引住工作协议、不设硬步骤），连带把 subagent 槽装配一等化（哨兵换真视图，拉响既有备案触发器）。**单级晋升**：晋升即全局同权、内容原样入库（审核者不改稿）、操作者留痕、不自动指派——入池与生效分离，生效仍走人工指派＋skillcheck 预检。**拒绝＝终态**：内容留档可查、不再列活跃面、再提为新草稿。草稿不参与任何装配（同项目亦不可用）；项目删除清未终结草稿、晋升后即平台资产与来源项目脱钩；run 失败不回滚已写入的自荐；不设草稿数量上限（人审是天然瓶颈）。使用计数自建落库进后台观测面（安装技能一并受益）——框架 SkillUsageMiddleware 只计 agent-created 且写工作区 sidecar，不适用。治理自动化（stale/归档周期整理）与技能 TDD 机制化均备案。SKILLS_DIR（.platform/skills/）预留位因草稿库制落定失去用途，删除。

## Considered Options

- **框架 curator 闭环接入（enableSkillManageTool＋SkillPromotionGate＋SkillCurator）**——拒绝：整套是文件制世界观（草稿＝skills/_drafts 目录、晋升＝搬目录、sidecar 计数与整理），与平台库制正本（skl_skills＋查库视图装配＋disableDefaultWorkspaceSkills 显式关工作区层）正面相撞；晋升门三档（RejectAll/LocalApproval/NotifyAndWait）批准信号全靠宿主代码调 promoteSkill，与「后台人审＋操作者留痕」信任模型不合。可复用件收窄为：工具入参 schema 形态、校验常量、SkillSecurityScanner 静态调用。
- **草稿落工作区 .platform/skills/（SKILLS_DIR 预留位）**——拒绝：后台审核面需跨项目发现草稿，文件制要扫全部工作区或另设登记表；EXECUTOR 工作协议禁写 .platform/；lineage 与项目删除清理在 DB 侧才对齐知识素材先例。预留位随之删除（保留能力不保留结构）。
- **两级晋升（先项目内共享再全局）**——拒绝：「自产与安装同库同权同指派」已钉死单库语义；项目级技能库是第二个库概念，纯投机性复杂度。项目内草稿复用备案（触发器＝首个「同项目多轮想复用未晋升草稿」的真实案例）。
- **自产内容面与安装同权（可带 scripts/）**——拒绝：智能体写的任意 shell 晋升即全局生效，信任阶位远高于安装包；markdown 人审可读、脚本人审难读。备案触发器＝首个真实需要带脚本的自产案例。工具组绑定（b 面）维持留给平台自制技能线结构位。
- **技能 TDD 落地成平台机制**——拒绝：需要场景库＋带/不带技能 A/B 试跑的评测基础设施，投机性复杂度；进 docs/agents/skill-audit-guide.md 作软方法论（审核四要素：真伪、重叠〔skillcheck 预检复用〕、description 质量、血统可溯〔来源 run 的外部资料接触史必查〕）。备案触发器＝技能库规模大到人工审不动或需量化技能效价。
- **SkillSecurityScanner 当安全边界全面接入**——部分采纳：静态件在自荐写入路径接上（DANGEROUS 拒写、findings 供审核面）——已在依赖 jar 内、零建设成本、框架自身在晋升路径也是无条件硬闸；但定位是廉价哨兵，安全边界仍是人审门。升格备案（触发器＝首个真实注入案例或自产晋升量大到人审走不动）。
- **自产资格只开 run 执行体（主智能体/子智能体暂缓）**——用户改判否决：三槽位齐开；MAIN 轻技能面纪律由审核面把关（skillcheck 预检＋审核指引），subagent 槽装配一等化随本线落地（读侧视图已就位、只差换接线）。
- **草稿数量上限**——拒绝：限流属投机性复杂度。

## Consequences

- skl_skills 来源列化，「行在库即正货」不变式保持；草稿、废稿、审计都在独立表。
- 晋升不自动指派：入池与生效分离是刻意设计——不绕过指派预检纪律；审核员晋升后需自行去指派面勾选并跑预检。
- 执行体获得第一个直写平台库的工具（经适配器落库，先例是 MAIN 的 savePrd）。
- 拒绝终态意味着「改了再提」不存在——提出会话已结束、无人改稿（审核者代改是职责越界）；重提只能靠未来会话产生新草稿。
- 智能体自荐技能进入后台技能面，admin 仓库需通报新增面（草稿审核＋使用计数观测）。
- 备案清单（各带触发器）：项目内草稿复用、自产带 scripts、TDD 机制化、scanner 升格、stale/归档周期整理。
