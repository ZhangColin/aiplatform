# 数据飞轮采集层：沉淀草稿库制＋三槽位自荐工具＋轮收口轻兜底盘问

数据飞轮一期·采集层（2026-11-11，#460，承 #451 决策正本与 ADR-0022 技能草稿先例）。现状事实：跨项目知识沉淀只有「订单归档时 PRD 入库」一条被动通道——既晚（走完签约付款才沉淀）又窄（只有 PRD 一类），对话中 AI 判断值得沉淀的需求案例/功能模块/业务规则无处安放；知识线还缺人审质量闸（技能链有自荐→草稿→审核→晋升的人审闸，知识链没有）。定案——两层沉淀机制的第一层（采集层）：

**库制草稿**：新表 `knw_sediment_drafts`（V59，照 skl_skill_drafts 先例）——草稿与知识素材隔离：未审核草稿不参与任何检索，「素材行即正货」不变式保持。血统三件（来源项目软引用/run 标识/来源槽位）、扫描回执（SkillSecurityScanner 廉价哨兵，DANGEROUS 拒写不落库——安全边界是「数据标注」人审门）、status 整数码＋CHECK（1 在途/2 已激活/3 已拒绝）、终态四列（操作者两列/审结时刻/拒绝理由——库级 CHECK 锁死拒绝理由必填）、在途部分唯一索引。载荷 payload JSONB＋kind 库面开放（写入校验限定一期三类 CASE/MODULE/RULE）——「开放＋载荷靠自己生长」，新类别生长不动表结构。踩坑解法归技能链，不进本机制。

**在途上限＝每项目每 kind 3**（防单一项目淹没标注队列的辅闸；人审是主闸）：结构性承载＝`inflight_slot` 序号列（1-3，CHECK 锁定）＋在途部分唯一索引 `(project_id, kind, inflight_slot) WHERE status=1`——终态翻行即释放名额；应用层先查占用取最低空位，索引拦并发窗（DuplicateKeyException 归一为上限回执）。

**三职能槽位齐开的自荐工具** `propose_sediment`（入参 kind/title/summary/content 四件，无载荷参数——列随档生长）：main／executor 装配面直配、subagent 经 verify 子键视图挂子级面（声明 allowlist 接入，同名后写胜出——血统不串槽），照 propose_skill #263 先例。写链＝校验→扫描→在途上限→落库→可读回执（拒绝一律回执原因不抛，模型可读可修正重提）；run 失败不回滚已写入的自荐（ADR-0022 同口径：工具执行即事实落库）。权限自检恒放行——写入有扫描哨兵＋人审门，草稿不参与任何装配。

**触发＝协议软指引＋轮收口轻兜底盘问，不设硬步骤**：三处工作协议（主智能体/执行体/verify 子智能体正文）各一句软指引——不绑时刻、无经验不调用、不为凑数硬写。兜底盘问落「记账→次轮提醒」轻形态：轮收口观测点（主智能体合法收口三形——挂起问答在场/PRD 产出/迭代期受理）时查 `SedimentProposalFacts`（propose 调用事实登记，受理与拒因同记账）——本轮主智能体槽未提即记账，下一对话轮 system prompt 尾附一句软提醒（消费即清；本轮提过即撤记账——问答续跑里补提的循环也覆盖）。**刻意不派即时盘问轮**：每轮收口烧一次额外 LLM 轮与访谈成本姿态相悖（#453 每迭代开销专项同向），且即时轮要么落对话史（违反「用户无感知」——一期无告知面）要么需要静默轮新机制（投机复杂度）；次轮尾注零额外模型轮、用户面无扰动、不设硬门（不拦收口不播报）。

**授权口径＝用户无感知**：平台按自身需求直接使用，一期不做告知/授权面；采集埋点＝每次自荐的结构化日志行 `[sediment-propose]`（项目/类别/槽位/扫描判定/结果——受理与拒因两形都可统计）＋受理行本身即采集层留痕。

**生命周期**：项目删除级联清未终结草稿（采集层不留僵尸行，对齐技能草稿清理先例——只在途，终态留档）；激活后升格知识素材并与来源项目脱钩（孤儿沉淀＝知识独立存在——升格归 #465，审核面归 #464）。

## 补记（#464 数据标注审结面，2026-11-11）

后台「数据标注」面落地（机机签名端点，照技能草稿审核先例）：标注队列（项目/类别/状态过滤＋分页，自荐时间倒序）＋详情（任意状态——终态留档可查）＋激活/拒绝/改标签三键。三键终态语义＝ADR-0022 同口径：CAS 条件更新（WHERE status=在途，零行命中归 409 已审结）、已审结拒、拒绝理由必填（应用预检＋V59 库级 CHECK 双锁）、操作者必留痕（缺 400 KNW_006）。**激活本键只落审结终态——升格 knw_materials 归 #465**（激活与升格跨票分工：审结论与升格机制分离，seam 以「激活后 knw_materials 零行」钉死边界）。

**改标签语义（#464 落地时裁决，出处补记）**：在途内调类别，占目标类别在途序号最低空位（排除自身）——部分唯一索引 (project_id, kind, inflight_slot) 使改类别必须重排序号（序号是上限 3 的结构性承载，跨类别生效）；目标类别在途满 3 即拒（409 KNW_012，预检与并发撞索引归一为同码）——对齐 propose 侧「上限即拒」口径而非换出/对调（换出会把人审决定外包给队列顺序，满即拒把决定权留在标注员手里）。同类别幂等 no-op。不翻终态、不动正文——纯队列分诊修正，已审结拒同激活/拒绝。

**改标签操作者留痕面裁决**：留痕＝采集埋点日志行（[sediment-annotate]）——终态四列是审结语义、在途行终态列恒 null 的 seam 断言钉死该形状，改标签不落终态列；持久留痕如需独立列（V60 生长面）由后续票按需裁决。

## Considered Options

- **即时盘问轮（收口即发一轮微指令让模型补提，回复静默丢弃）**——拒绝：每轮一次额外 LLM 轮（访谈期逐轮翻倍主智能体调用，与 #453 成本姿态相悖）；静默丢弃需新机制（会话记忆仍积累该轮、ask_user/savePrd 副作用需专门护栏），投机复杂度。次轮尾注以零成本拿到同等「该提未提提醒」效果。
- **用户面告知/授权（对话区提示「已沉淀 X」）**——拒绝：#451 决策正本锁定一期无感知口径（告知面是独立的产品决策，二期再议）。
- **payload 一期开工具参数**——拒绝：一期三类载荷形态未定（「靠自己生长」），先开参数是投机面；列随档生长，未来票按需开。
- **在途上限应用层计数不带序号列**——拒绝：count 无结构性承载（并发窗内双计数同值各插一条即破 3）；序号列＋部分唯一索引让上限成为库级不变式，应用层只做友好回执。
- **拒绝理由只靠应用层校验**——拒绝：技能链先例即 app 校验，但沉淀票把「拒绝理由必填」写进验收的表级语义——库级 CHECK 锁死，app 层提前拒只为回执可读（与 CHECK 不矛盾，防绕写口）。
- **复用 SkillSlot 枚举表达来源槽位**——拒绝：knowledge 反依赖 skills 仅为一个键不值当；槽位在沉淀链全程以稳定键字符串承载（校验只查非空），读面（#464）需要时再议。

## Consequences

- 知识线获得与技能链对称的草稿隔离表＋人审质量闸（闸本体＝#464「数据标注」面）；「该提未提」有轻兜底，模型零自荐时采集面不至于整轮空白——但兜底是提醒非强制，采集密度仍靠协议软指引与模型自觉。
- 三职能槽位的工作协议各多一句软指引（主智能体正文第 20 条/执行体第 13 条/verify 正文第 10 条）——能力清单正本同步点名（装配↔提示词一致性测试钉死）。
- 采集埋点日志即一期观测面：自荐事件（受理/拒因两形）可统计；策略演化（问题模式数据驱动）是后续票，本层只立采集面。
- 后台「数据标注」面（#464）与激活升格＋混检注入（#465/#466）是第二层与本层的下游——本表终态列/状态码/在途序号为其预留写口，无新表。
- 项目删除链多一格清理（未终结沉淀草稿）；删项目不触已激活知识（孤儿沉淀语义与技能线「晋升即平台资产」同构）。
