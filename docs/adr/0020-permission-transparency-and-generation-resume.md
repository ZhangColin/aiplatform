# 权限确认透明面化＋生成断点续跑（#217）

生成 run 因「权限确认超时」判死、重新发起又走 minimalFallback 从头重来，形成死循环（企业官网项目卡死实例）。根子是自相矛盾：ConfirmingShellTool 注释自称「确认卡是过程透明面不是安全边界」（沙箱可随时销毁重建、卷外皆可弃），实现却是「阻塞等用户＋10 分钟超时判死整个 run」。对标六家（Replit/Lovable/v0/Bolt/扣子/Kimi）无一有「超时判死」先例；恢复的执行层一致是「新会话看现状脏续」，无一家做恢复执行。

决定：

1. **权限确认机制全删**（当前高保真 demo 阶段纯透明面）：ConfirmingShellTool 替位（注册回内核 shell）、DESTRUCTIVE_COMMANDS 封闭小表、PermissionDecision.ask 分支、RunPermissionAppService（超时＋waiting 表＋作答入口）、settlePermissions 挂起环、PermissionTimeoutException、前端确认卡与作答端点、词条「权限确认」。「向用户要答复并挂起续跑」的能力由问答机制承载，全删不丢能力。数据保护靠机制不靠审批（业界一致：回滚只回代码，数据靠备份/PITR 兜）。minimalFallback 连代码带概念删，计划缺失兜底＝重派主智能体产计划。
2. **生产面确认备案**（触发器＝平台拓展系统生产阶段、专业技术人员介入）：届时按新形态设计——工具级声明（非 shell 命令模式匹配）、确认对象是业务/交付决策（技术确认不给非技术用户）、超时挂起不判死＋召回通道（参照 Lovable「Paused work waits until you decide」、Replit 移动推送「Agent needs your help」）、密钥类用户亲手填（Replit 删库事件为反面实证）。
3. **贯穿原则：等待用户永不判死**。任何阶段的确认/问答挂起，用户回来必能从断点续。
4. **生成轨道持久化**：轨道表（切片计划＋每片状态）落平台库；计划生命周期跟 PRD 版本走（PRD 演进即重产，进程重启不丢）——给「run 无表、重启即清」口径开精确例外。项目生成态四态（从未生成/生成中/生成中断/已生成）由轨道表＋generated_at 投影；generated_at 完成语义不动（仍是确认下单门槛）。
5. **续跑＝全场景脏续**：非错误中断（崩溃/重启/沙箱死/未来确认挂起）新会话起手带现状盘点（工作区现状＋切片进度＋中断原因＋中断前摘要）；错误中断的静默重试对齐「原地修」（新尝试带错误现场）；耗尽 run-failed 后「继续生成」出口同样脏续。干净重做不设默认路径——用户要确定性走版本回滚（已有机制）后再续。会话级 resume 不做（cat_agent_state 地基不为此启用）。片内快照锚点（修错前/功能完成打点）备案，触发器＝脏续失败回退粒度不够。
6. **恢复出口单出口「继续生成」**（断点续跑，含 idle/中断态刷新后）；推倒重来不设按钮——走对话区提意见改 PRD→计划重产（PRD 演进即新计划，正是计划跟 PRD 版本走的另一面）。现有「重新发起」按钮与 restart 分支改造成「继续生成」。更新轨失败恢复（RestartFix）现状不动。

## Consequences

- 确认机制删除后，run 内向用户要答复的场景只剩问答；闲置口径照旧（挂起＝在途恒活跃），资源滞留风险备案、触发器＝首次真实滞留事故。
- 存量在途项目（无持久化计划）走计划重派：重派主智能体按 PRD 再产计划并对照 git log 标已完片——卡死的企业官网项目即首个真实案例（不做数据手术，机制修好后自然恢复）。

## 注记（2026-09，#227 动作直播化）

**动作播报语义收窄为「直播时播报、成功不留史」。** 工具动作在直播进度卡滚动面播报（当前动作行显命令原值），成功后不在静态面留条目——「改了什么」由收尾卡变更清单承载；失败留痕（红行＝label＋错误首行）。破坏性命令的权限确认主机制不受影响——确认是事前要答复的机制（本 ADR §2 生产面备案），不依赖事后播报复盘；demo 阶段「透明面不是安全边界」的删除依据亦不变（数据保护靠机制不靠审批）。
