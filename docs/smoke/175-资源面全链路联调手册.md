## 一、闲置休眠 → 自动唤醒（AC1）

**阈值调小重启**（闲置 3 分钟休眠、休眠满 5 分钟封存、扫描 40 秒一轮）：

```bash
# 杀掉当前 8888 后端后：
SPRING_APPLICATION_JSON='{"app":{"workspace":{"idle-threshold":"PT3M","seal-threshold":"PT5M","hibernation-scan-interval":"PT40S"}}}' \
  ./scripts/dev-backend.sh
```

| 步骤 | 动作 | 预期 |
|---|---|---|
| 1 | 打开联调项目、记数据点，然后放置不动 | — |
| 2 | 等闲置过 3 分钟＋一个扫描轮（后端终端见 `[workspace] <wsId> 闲置休眠：容器已删、卷保留、期望态置休眠`） | `docker ps -a` 无 `ws-<wsId>` 容器；`docker volume ls` 卷仍在；后台 `list` 该行 desired=2 休眠、实态=3 无容器 |
| 3 | 前端 3333 重新打开该项目 | 面板只见「**系统启动中**」（1013 待期口径），无其他报错；分钟级内预览回来 |
| 4 | 预览回来后核对数据点 | 数据在（卷保留，重建容器不动数据面） |

期间顺带看一眼后台清单全貌：`./scripts/backoffice-workspace.sh list`（期望态/实态/last-touch/卷大小各列如实）。

## 二、封存 → 深度恢复 → 再封存覆盖（AC2）

| 步骤 | 动作 | 预期 |
|---|---|---|
| 1 | 放置等休眠满 5 分钟（闲置 3+5=8 分钟起），或直接后台 `seal <wsId>`（RUNNING 起点也可） | 后端终端见封存三步日志（打包→置封存→删卷）；后台 detail：desired=3 封存、sealedAt/包大小有值、卷大小容缺 |
| 2 | `docker volume ls` | `vol-ws-<wsId>` 已删；封存包在工作目录 `seal-archives/` 下（记下文件名与大小） |
| 3 | 前端打开该项目（深度唤醒） | 仍只见「系统启动中」；分钟级（解包＋依赖重装）；预览与数据点完整恢复；detail 回 desired=1、卷重建 |
| 4 | 再封存（后台 `seal` 或再等满期自动） | `seal-archives/` 同名包被覆盖（mtime/大小更新，不留旧包）；detail sealedAt 刷新 |

## 三、后台观测 + 四动作 + run 在途拒（AC3）

```bash
./scripts/backoffice-workspace.sh list                 # 全量清单
./scripts/backoffice-workspace.sh list 1 3             # 捞漂移行（期望运行而实态无容器）
./scripts/backoffice-workspace.sh detail <wsId>        # 全量字段：期望/实态/卷大小/封存/中间件
./scripts/backoffice-workspace.sh wake <wsId>          # ① 唤醒（等就绪）
./scripts/backoffice-workspace.sh hibernate <wsId>     # ② 强制休眠
./scripts/backoffice-workspace.sh rebuild <wsId>       # ③ 强制重建（rm＋幂等重建）
./scripts/backoffice-workspace.sh seal <wsId>          # ④ 封存（之后再唤醒回来，留运行态收尾）
```

每个动作后脚本回动作后的观测详情（新事实即结果）；动作行 append-only 留痕——四动作带 `OPERATOR_ID=… OPERATOR_NAME=… ./scripts/backoffice-workspace.sh <verb> <wsId>` 即把 X-User-Id/X-User-Name 透传头落进动作行（缺省不带＝落空口径），库表 `wsp_workspace_actions` 可对账。

**run 在途拒**：在联调项目对话里发一条会触发编码 run 的消息（如「页面标题改成 X」），run 进行中（前端直播/过程可见）时：

```bash
./scripts/backoffice-workspace.sh hibernate <wsId>   # 期望 409，信封 code=1015（WSP_015）
./scripts/backoffice-workspace.sh rebuild <wsId>     # 同上
./scripts/backoffice-workspace.sh seal <wsId>        # 同上
./scripts/backoffice-workspace.sh wake <wsId>        # 唤醒不受限（不动数据面），应成功
```

等 run 收口后继续（强制动作要在 run 结束后各执行一次成功——上面四个命令各跑一遍成功态）。

## 四、后台下载两口径（AC4）

```bash
./scripts/backoffice-workspace.sh package <projectId> /tmp/a.tar.gz
```

| 场景 | 预期 |
|---|---|
| 项目**已封存** | 文件名 `{id}-archive.tar.gz`（Content-Disposition），整卷口径：含数据库与机密、排 node_modules/.pnpm-store/.next；`tar -tzf` 抽查目录结构与 DB 文件在 |
| 项目**未封存**（运行/休眠均可） | 文件名 `{id}-source.tar.gz`，交付口径（排 node_modules/.env，同订单源码包）；休眠中会先同步唤醒（分钟内）再打包 |

`tar -tzf /tmp/a.tar.gz | head` 抽查内容。

## 五、docker daemon 重启 / 后端重启（AC5）

**docker daemon 重启**（Docker Desktop 退出再起）：

```bash
osascript -e 'quit app "Docker Desktop"'   # 或 UI 退出；等 docker info 失败
open -a Docker                              # 等到 docker info 恢复
```

- 运行中的项目容器 `restart=unless-stopped` 自起，预览仍可用（**运行项目不受损**）
- 休眠过的项目容器**不自起**（已删就是已删，docker ps 无）
- 网关/PG/redis 等平台容器同自起；后端下一个扫描轮（此刻还是§一的小阈值实例，≤40 秒即一轮）无异常漂移动作（对账收敛）

**后端重启**（恢复默认阈值，正好验启动对账）：

```bash
# 杀 8888 后端，常规启动：
./scripts/dev-backend.sh
```

- 启动终端立刻见一轮扫描（ApplicationRunner 启动对账）：休眠项目保持休眠（不自起）、漂移行（若有）被收敛唤醒、封存残留（若有）被清
- 重启前在跑的项目预览不受损
