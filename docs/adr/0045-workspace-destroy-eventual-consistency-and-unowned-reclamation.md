# 工作区销毁终态一致与无主收编

#473 定档（2026-11-13；承 ADR-0016 休眠保卷、#179 孤儿容器清扫、#476 置备池与收敛互斥基建。诱因＝11-12 eu-1 磁盘 100% 人工清理实录：20 个删除项目 4 个 destroy 半途残留、7 个历史无主卷靠 SSH 对账收尾）。现状事实三件：① destroy 尽力而为吞错——物理级联失败仅 warn、注册行照删，三残留无告警无重试，只能事后人工对账；② destroy 不参加收敛互斥——唤醒/触碰与销毁并发，唤醒胜出即容器重建、卷被占用删不动（4/20 命中）；③ 无主判定只在手动脚本里——生产无对账通道，`docker system df` 的「可回收」把休眠卷一并计入、不可用作准绳。定案：

**删除最终一致＋销毁三清**：DELETE 对外语义＝受理即删（项目立刻消失、会话凭证即失效），不承诺受理即三清；销毁尾部对容器/卷/注册行做三清校验（尽力＋留痕），未清残留即无主资源、由收编通道回收。不设第四期望态（无墓碑）——desired_state 三态是 ADR-0016 语汇地基，注册表为唯一正本，「可重试状态」由扫描 diff（无主清单）承载而非行状态。

**destroy 并入收敛互斥**：销毁加入收敛模块进程内 per-workspace 互斥，与唤醒/休眠/封存/触碰收敛双向串行（destroy 先拿锁则唤醒重取见行已删自然落空——「等待唤醒完成后再删」的双向版）；触碰拨针补重取守卫作纵深第二层。单机单进程口径，不上 DB 锁/分布式锁。

**无主判定准绳＋双闸＋分级处置**：无主 ⇔ 不在注册表，或在册但项目行已删。双闸：新建宽限窗（10 分钟口径）＋注册表不可达宁可漏删整体跳过。真无主由既有扫描轮自动收编（容器侧 #179 先行、卷侧对称扩展——不是新开定时通道）；在册但现实不一致只标在册失联待人工裁决（机器不裁决用户数据），物理已空的空壳行直接删行做注册表卫生。

## Considered Options

- **墓碑制（第四态 DESTROYING，行本身挂可重试状态）**——拒绝：行照删后残留按命名锚点对账即可覆盖，待回收视图＝扫描 diff，与行状态等价；扩第四态波及三态语汇全部读面，换不来新能力。
- **同步删除（受理即三清、失败回滚）**——拒绝：唤醒占卷竞态本质不可同步消除，只能让位重试；用户可见预期（项目消失、凭证失效）最终一致已满足。
- **纯守卫不互斥**——拒绝：守卫只缩窗不消窗；进程内互斥成本≈0，正面串行。
- **在册失联也自动清**——拒绝：在册不等于无主，卷后可能是用户数据（ADR-0016）；自动删＝机器裁决用户数据。
- **全自动定时清扫动刀**——拒绝：无声定时任务出错没人看（demo 阶段单机）；动刀类（回收/清扫/裁决）走 admin 手动＋留痕。

## Consequences

- DELETE 契约变化：受理即删、资源面后台收尾（扫描轮 ≤5 分钟或 admin 手动清扫）；#473 票面「未清进可重试状态」重释为「未清→无主→扫描收编」。
- destroyWorkspaceQuietly 的「吞错即忘」口径退役为「尽力＋尾部三清校验留痕」；校验失败进 WARN 与观测面。
- clean-ws-residue.sh 退居本地开发工具，生产逻辑进 Java 扫描（同一准绳）。
- 域词四条入 CONTEXT.md：销毁三清、无主、在册失联、一键回收。
- 验收锚：并发 destroy×唤醒零三残留（live 类）；无主卷被扫描收编且宽限窗不误杀刚建；注册表不可达整体跳过；在册失联只标记不删（空壳行除外）；docker volume prune 永不进任何自动通道。
