# 问答挂起时消息通道拒绝而不代答

会话存在挂起问答时，`POST /api/projects/{id}/messages` 照常提交 converse 会被引擎按 ASKING 态拒绝——REST 返 200、失败只见于异步 error 帧，且该通道持续撞死（issue #40）。UI 侧指令区在挂起时已把输入改道为作答（问答卡答复走 resume 通道）。

决定：`/messages` 在挂起问答期间守卫拒绝——PRJ_024 / 409，纯码+定长文案指路（「请对问答卡作答后再发送新消息」），不对挂起问题代答、错误载荷不带 qid。作答需要 runId+toolCalls+qid 三样，前两样只在 SSE 问答卡里：载荷单带 qid 救不了非流式调用方，流式调用方又早已持有问答卡。判定事实读引擎 `cat_agent_state` 的 ASKING toolCall——谓词沉在 `base/agentscope` 层，政策在业务提交入口同步调用（必须在请求路径同步检查才有真 409：引擎拒绝发生在异步轨道，REST 已返 200）。提交口枚举结论：会话可能挂起的入口只有 BA 一处（ask_user 是 BA 的访谈/受理协议工具），守卫挂 BA `turn()` 即全覆盖——CODER 无问答/确认工具（「拿不准先 ask_user」是 BA 受理侧协议，挂起在 BA 会话；startFixRun 由 BA run 内工具触发，BA 挂起时走不到迭代提交）、生成入口被 PRJ_017 全拦且首见会话无状态、命名是一次性无确认工具的同步调用。

## Considered Options

- 守卫拒绝+文案指路（采纳：一次往返可自救，代价只是枚举加一码）
- 纯 409 不指路（出局：把「怎么走对」藏进文档，白扔自救收益）
- 路由作答——服务端把自由文本视为对挂起问题的作答、走 resume 续跑（推迟：需服务端落盘挂起问题事实，runId+toolCalls 现仅存于前端问答卡，为一条非 UI 路径引入状态持久化不值；记为延后项，不留结构性扩展点）

## Consequences

- 依赖 409 的调用方将固化此契约。
- 已知竞态边角：作答 resume 在途、ASKING 尚未清库时，紧随的 `/messages` 会得到一记可接受的 409（resume 自会续跑收口）；缓解手段会把检查挪进串行轨道、丢掉同步 409，得不偿失。
- 作答通道的对称防御（重复作答/过期 qid）不在本决策内，另行开票。
