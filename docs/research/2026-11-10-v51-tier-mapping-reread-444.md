## 结论速览

**复评结论：V51 映射维持 ["大"] 不变，本轮不做运营面改档。** 终裁 run 的 per-片 per-档数据
不支持「降档 −5~10min」的票面预估——收益上限实测只有 ~2-3min，且对测试类大片有
+10~20min 迭代爆炸的实证尾风险（负期望）；反向不匹配（最重片标「中」留 flash）
不是 V51 映射旋钮能修的面。验收铁律的「映射调整→发版→重触发对照」链路因映射未调整
**不触发**（与「不发服务器」约束自洽）。

## 二、单次延迟与收敛：两个平价证据

**单次延迟——pro 不吃亏，全局几乎平价**：

- 全 run 聚合：flash 307 次 / 22.1min ＝ **4.32s/次**；pro 356 次 / 25.5min ＝ **4.30s/次**。
- 同窗同段对照（stage0）：flash 尝试 25 次 @3.1K token ＝ 5.33s/次 vs pro 重试尝试 8 次 @3.5K ＝ 3.97s/次。
- 逐尝试 llmMs÷窗口调用数：片4 pro 4.55s/次、片5 pro 4.77s/次、片6 pro 3.45s/次、片3 flash 5.57s/次（@43.5K 重上下文）。
- 历史画像（11-06，条件可比口径）：flash 中位 **4.1s vs pro 5.2s**（flash 单次快 ~21%）。

即「pro 单次并不比 flash 慢」（终裁报告口径）在 run 内成立，flash 的 ~20% 单次优势
被 pro 片更轻的上下文结构吃掉大半。**降档的 llm 桶收益上限 ≈ 337 次 pro 调用 × ~1s ≈ 2-3min**，
达不到票面 −5~10min（该预估隐含「pro 单次更慢」的假设，被 run 内数据证伪）。

**迭代收敛——两档同量级，pro 无收敛优势**：

- 片3（flash，全 run 最重上下文 43.5K/次）：**161 次、单尝试零重试、verify 10 项全过**——
  flash 扛住了全 run 最大工作量，迭代数未爆炸。
- 片4 pro 125 次 vs 片6 pro 159 次 vs 片3 flash 161 次：同量级，pro 未减少迭代。
- 全 run verify 登记 30 项（片1×8/片2×7/片3×10/片5×5）**零失败**；除 stage0/片2 外零重试升档
  ——没有任何质量信号表明现 pro 片「需要 pro 才能过」，也没有任何 flash 片「快档翻车」。

## 三、为什么不降：尾风险是实证级，不是理论级

11-06 画像锚项目内对照（同 PRD/同基/同日，全库条件最可比的一组）：
**同型测试引擎片（双题型测试）flash 365 次迭代 / 38.3min，同项目 pro 片 79-92 次 / 8.2-11.7min**——
flash 大片尾部（38.3）超 pro 大片尾部（22.0）74%。片4（记忆曲线测试）正是测试类片。

- 降档收益上限：~2-3min（单次优势，前提是迭代数不劣化）。
- 降档尾风险：+10~20min（测试片迭代爆炸有旧实证；新上下文〔单会话+决策注入+厚基座〕
  暂无 flash 测试片对照可证伪该风险）。
- **负期望，不改。** 注意 V51 旋钮粒度也修不到点子上：映射只能整组选标签
  （[]＝连片4 的保护一起拆；["中","大"]＝6/6 片全 pro ＝ 实质「全强档」策略），
  没有「只降片1 这类 trivial 大片」的档位。

## 四、反向不匹配与真杠杆（映射修不了的面）

- **最重片留 flash**：片3 标「中」（fc 26）落在映射外，27.7min 为全 run 最大墙钟段。
  按 11-06 收敛证据，该片若 pro 化可能 ~15min——但这是「中→pro 全量升档」的战略级
  取舍（等于放弃 flash-first 的 Demo 档基调，token 成本同步上升），**超出本票边界，留 backlog 另评**。
- **计划器标签校准**：片1（2.3m trivial 片）标「大」、片3（27.7m 最重片）标「中」——
  规模标签自报的可靠性是映射上游的真问题，正主在主智能体计划协议，不是 V51 映射列。
  trivial 大片烧的 pro 时间仅 ~0.7min/run，量纲不构成改映射理由。
- **文件面信号的晚燃**（观察项，非本票范围）：片5（7.5m）/片6（21.8m）因 33/36 文件越阈
  升 pro，而 fc 26 的片3 反而留在 flash——30 阈在项目中后期近似「过半片必升」。
  该阈值重校属 #426 文件面信号自己的事，数据留档备用。

## 五、#437 偏差口径主动声明（承 #438 先例）

- **决策注入 hint 的档位依赖**：#437 分类器为**确定性规则族、零模型调用**（#438 已声明
  「分类器档」计划偏差——原拟 flash 模型分类器，落地纯函数规则），注入密度不随执行体档位变化；
  但 hint 的**作用对象**是执行体档——144 次注入（anti_mock 88 / parallel_tools 55 /
  context_economy 1）的密度与决策质量基数是在**现档位分布**（pro 337 次 / flash 307 次）下观察的。
  本票结论为维持现映射 → 档位分布不变 → 该基数继续有效；**若后续仍推任何降档**，
  被降档片须按 #437 口径复验注入密度与决策质量不劣化后方可落定。
- 本报告全部量化结论出自 eu-1 生产库只读 SELECT，未做任何写操作；未发版、未动运营配置。

## 六、处置

1. V51 映射维持 `routingEscalatingSizeLabels=["大"]` 缺省，**本轮不改运营配置**；
   「映射调整→release.sh 发 eu-1→锚需求重触发对照」验收链因映射未调整**不触发**
   （未发服务器，与 #444 执行约束自洽）。
2. 「中→pro 战略级升档评估」「计划器规模标签校准」两件进 backlog 备注（超出本票边界，
   不在本票内落地）。
3. 票面预估「−5~10min」经数据复评证伪：真实可收窄面不在这条映射上。
