# 模型供应商通道化：前缀即协议路由、档位语义键、凭证落库唯一正本

模型供应商接入裁决（2026-10-22，spec #364；承 ADR-0021 智能体运营配置〔配置落库、库值优先缺省回落、变更留痕〕与 ADR-0030 模型路由〔强档可配不发版〕）。动因：DeepSeek 官方 apiKey 耗尽不再充值，切火山方舟（一 key 通吃豆包＋火山部署的 DeepSeek）；现状供应商是代码硬编码白名单（仅 deepseek）、baseUrl 落依赖库默认值、apiKey 全走环境变量——换通道必改代码发版、换 key 必登机改文件重启。定案：

**域模型三层**：

1. **模型供应商＝接入通道**（键名、baseUrl、apiKey、启用态）。**键名同时是协议路由前缀**：OpenAI 兼容通道（volcengine）由平台按模型串正则代码注册模型工厂（SDK 公开 API，优先于内置 provider、不改依赖库）；SDK 内置前缀（deepseek/openai 等）走原生 provider，baseUrl/key 经创建上下文注入覆盖默认。Claude、Gemini 等原生协议经前缀路由天然留门——接入＝加通道行＋档位行，不动结构（本期不接不验）。
2. **模型档位＝语义键**（flash/pro/doubao-flagship 这类运营短名），档位行指向实际模型名＋所属通道。模型版本升级（方舟名带日期后缀、季度级更新）＝改一处指向、全部引用自动跟上。
3. **绑定＝智能体运营配置扩展**：三座智能体（systemPrompt＋模型档位）＋边缘四点（项目取名、上下文压缩、入口分类、技能预检，仅模型档位）统一同表同机制；模型路由强档同步改档位键引用；改档即时校验（档位键存在且启用——白名单从档位表来，替代硬编码 provider 集合与「错值靠回滚兜底」）。

**凭证落库唯一正本**：供应商行 apiKey 为唯一正本，**无环境变量回落**（缺失即报错、不静默兜底）；明文落库＋接口掩码回显＋日志脱敏；key 值经部署环境注入种子（git 永不含 key 字面）。种子两通道行——volcengine 主用（`https://ark.cn-beijing.volces.com/api/v3`）＋deepseek 官方备胎（后台一键可切回）；三档位行——flash→deepseek-v4-flash-ga-260731、pro→deepseek-v4-pro-ga-260813（火山 GA 对齐版：与切换前同代同档、行为漂移最小）、doubao-flagship→doubao-seed-2-1-pro-260915（备选档）。

**装配与生效语义**：绑定档位键 → 档位行 → 通道行 → 模型串（前缀:实际模型名）＋创建上下文（baseUrl、apiKey、enableThinking 显式关——方舟 DeepSeek V4 标深度思考，不传参时默认开/关未确证，冒烟实测开/关的延迟与质量后定终值）；**模型实例缓存键纳入生效配置指纹**——守「改配置即生效、进行中 run 不定格」承诺（否则改 key/地址后旧实例滞留缓存、新配置不生效）。

**模型清单手动同步**：后台从供应商拉取模型清单（OpenAI 兼容 models 端点）→勾选入库＋语义键人工命名——消手抄模型 ID 的抄错与过时；自动定时同步备案未来增强。

## Considered Options

- **供应商单表（baseUrl+key 全在通道行、档位仍存全串入配置）**——拒绝：供应商与模型耦合——模型清单无处维护、换模型动通道行；两实体分立后「通道行稳、档位行常动」各自演进，换通道不动档位、升版本不动通道。
- **档位直存实际模型名（无语义键层）**——拒绝：方舟模型名带日期后缀、季度级更新，直存则每次升级逐处改绑定（三座＋边缘四点＋路由强档最多八处）；语义键一处升级全局跟上，且 flash/pro 与既有运营话语（#341 Demo 阶段模型档、ADR-0030 路由强档）无缝。
- **env 回落链（DB key → 环境变量 → 报错）**——拒绝：变量名错位（ARK_API_KEY 是图片域名、DEEPSEEK_API_KEY 是官方名，对话线借用皆拧巴）、兜底指向不确定、双正本故障难定位（到底用了哪把 key）；DB 唯一正本缺失即报错，故障一眼可查。
- **key 留空上线、后台补填**——拒绝：代码上线到人工填 key 之间存在断档窗口；key 部署时从环境注入种子/直写（本机 dev 直写、生产部署机注入），开箱即用零手工，git 仍无 key 字面（单价表「种子脚本开行」先例）。
- **复用 SDK 内置 openai: 前缀接方舟（baseUrl 注入覆盖）**——拒绝：前缀语义错位——openai: 实际打火山，日志、计量、单价表按前缀归因即失真；volcengine: 前缀平台注册工厂，归属清晰且不动依赖库（新增 provider 类亦不必——工厂直构 OpenAI 兼容模型）。
- **apiKey 落库加密（主密钥 env）**——拒绝（本期）：主密钥又落 env 的套娃，内网后台＋机机 HMAC 签名＋掩码回显为当前最低线；备案触发器＝管理面对外暴露或合规要求入场。
- **自动定时同步模型清单**——拒绝：引入定时任务＋冲突策略（远端下架库内行怎么办、语义键归属谁定）复杂度跳档；手动拉取勾选已消最大风险源（手抄 ID 抄错），过时性由「拉取对照」解决。
- **供应商表加协议类型列**——拒绝：前缀即协议路由，加列即第二正本（列与前缀不一致时谁赢？）；真出现 SDK 未覆盖的协议再立适配器选择字段。
- **边缘四点维持 yml 缺省、只改缺省串**——拒绝：与「智能体与步骤选系统配置」的运营诉求相悖；复用 agent-configs 现成机制（同表同留痕同接口通道）零新表，收编成本低于维持两制的长期解释成本。
- **直接升级 agentscope-java 引入原生 volcengine provider（改依赖库）**——拒绝：平台侧注册工厂已足够（SDK 公开 API、优先于内置）；改依赖库引入版本协调成本，方舟是 OpenAI 兼容无需特化 formatter。

## Consequences

- 换供应商、换模型、换 key 从「改代码发版/登机改文件重启」变为后台维护——运营配置面的能力从档位扩到通道与凭证，全程留痕回滚、下一轮命令构建即生效。
- `DEEPSEEK_API_KEY` 环境变量随切换退场（对话线不再读取；.env 文件遗留无害）；图片生成四家与博查搜索的 env/yml 机制本期不动（供应商表结构通用，留将来收编扩展点）。
- 存量经 migration 一步刷成档位键（三座 model_id、路由强档、四个配置缺省串、AgentProfile 枚举缺省）——不留新旧两制；dev 库真数据走 repair 流程。
- 单价表需为火山模型开新行（provider+model 维度变化），平台成本观测跨切换不断线。
- 模型实例缓存键含生效配置指纹——改配置即生效的边界由缓存纪律守住（装配层守点，Seam B 测试锚）。
- admin 侧新增通道/档位两维护面＋绑定改档位下拉（跨仓交接，admin 仓库 issue）；demo-stage-model-tier.md 改档 SOP 更新。
- CONTEXT.md 新词条「模型供应商」「模型档位」，「智能体运营配置」词条修订（边缘四点入面）；本 ADR 与 ADR-0021/0030 构成模型选用三件套正本（谁调用〔运营配置〕、何时升档〔路由〕、打到哪家用哪家〔供应商〕）。
