# 生成无门自动发起（「开始做系统」按钮退役）

首次生成此前是唯一靠用户点「开始做系统」按钮触发的动作（客户端 POST /generate），与更新 run 的「轮收口自动派发」不对称。现决定：生成触发权交给平台——主智能体产出 PRD 后，平台在意见轮收口处观测「未生成 && 已产出 PRD」即自动派首次生成 run，无需用户确认或点击；「开始做系统」按钮退役。失败重发同口径：run-failed 后项目仍「未生成」，用户重提一句即再触发，不设常驻重试按钮。

## Considered Options

- 新增 `start_generation` 工具（主智能体判定「收敛」时调用，平台观测工具事实派发）——出局：生成前的「收敛」本就没有独立语义，「PRD 产出」就是够做系统的信号；为无门的动作再造一个判定点属投机性复杂度（与 ADR 0003 反投机性复杂度相悖）。
- 保留「开始做系统」确认门（先确认后建）——出局：与「先建后迭代」哲学相悖——迭代兜底，需求不清不影响先做，用户随时可再提意见改 PRD 与系统。

## Consequences

- 生成与更新 run 的派发机制收敛为同一条「轮收口 → 平台观测 → 自动派发」线（未生成派生成、已生成派更新），主智能体均无派发权。
- 生成失败（run-failed）后不自动重试（防空烧 token）：项目仍「未生成」，用户重提即再触发；系统面板保留「重新发起」兜底（异常态，非常驻门）。
- 词汇收口：CONTEXT.md「生成」「对话区」由「确认推进」改为「自动推进」，「开始做系统」入 Avoid。
