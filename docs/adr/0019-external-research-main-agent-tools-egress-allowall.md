# 外部资料能力：主智能体直挂只读抓取/调研工具，沙箱出网保持 allow-all

用户贴外部地址（GitHub/文档站/参考官网）是自然输入，但主智能体工具面无任何 web 工具，且模型会错误自述「平台没有联网能力」——而沙箱网络层实际全通（设计内路径：容器内 pnpm install 拉公网）。六家对标平台全部具备 web search / URL 抓取（取证见 docs/research/2026-09-18-benchmark-web-research-capability.md，#212），是基线能力缺口。决策：主智能体直挂只读抓取/调研工具（读网页≠读写沙箱代码，不破职责正典）；抓取纯 HTTP 自建、带四条安全底线（仅 GET、拒环回/内网/云元数据、响应大小上限、抓回内容标注不可信——六家均无公开先例，自主裁决）；沙箱出网维持现状 allow-all，与 v0 默认态一致；搜索做供数器接口＋平台配置实例化（博查首个候选）。

## Considered Options

- **Lovable 式只读研究子智能体**（六家中唯一此形态）——拒绝：破「委派是 run 内机制」正典，且其真实价值（上下文隔离＋并行）的压力未现。松动触发器备案：主智能体单轮研究资料量撑爆上下文/挤压 PRD 质量成实测痛点时，显式修订词条开委派位（加挂载位，非改结构）。
- **Lovable 式出网白名单**——拒绝：工程大且易误伤（漏一个域名用户的系统就装不了依赖），v0 的 allow-all＋可配证明是业界可接受默认。触发器：多租户规模化或真实外泄担忧。
- **JS 渲染抓取 / Firecrawl 三方**——备案：纯 HTTP 在官网参考场景高频拿空壳时再议，届时优先评估三方而非自建渲染。
- **agentscope-harness 内核放 web 工具**——拒绝：安全政策是平台裁决，塞内核把平台政策下沉成框架通用物；框架化留独立线。

## Consequences

- 「委派仅 run 内」不再是可被拿来堵设计的教条——松动条件已显式化于本 ADR。
- 四条安全底线无对标可抄，属平台自主承担的裁决面；出网 allow-all 意味着 run 执行体的 command 仍可 curl 任意目标（存量敞口，接受并备案）。
