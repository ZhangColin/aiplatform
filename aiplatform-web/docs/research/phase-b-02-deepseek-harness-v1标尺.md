## docs/11-business-v1.md §2 四门户能力表（v1 标尺）

| 门户 | 谁用 | v1 能力 |
|---|---|---|
| 需求端 | 普通用户 | ① 项目列表；② 对话建项目；③ 项目详情页（进度 + 问答卡 + 需求确认/Demo 确认/验收按钮 + 预览）；④ 验收反馈 |
| 开发平台 | 公司人员 | ① 项目列表（待处理/进行中）；② Replit 式工作台——SSE 直播、答智能体的问、下任务、审批门、发测试任务、确认任务、确认开发完成；③ 待办列表；④ 成员页 |
| 任务平台（OPC） | 外包测试员 | ① 我的任务列表；② 任务详情（描述+附件+预览地址）；③ 录 Bug 表单；④ 提交；⑤ 驳回返工提示 |
| 管理后台 | staff | v1 不建 |

前端形态：单应用，单账号走三工作台，`views/{user,dev,opc}` 分目录留拆分缝。

## §3 主链（七步四门，v1 固定模板）

```
对话建项目 → 需求梳理（BA 引导问答）→〔需求确认门·用户〕
→ Demo（原型）→〔Demo 确认门·用户〕
→ 开发（agent 干活 + HITL，Replit 式）→ 测试（OPC 外包循环）
→〔开发完成确认门·开发平台〕→ 验收（用户体验系统）→〔验收门·用户〕
→ 交付（源码包 + DELIVERY.md）→ 关闭
```

- 四扇门：用户拍板 3 + 开发平台拍板 1；approve 推进、驳回停留
- 期 = 显式实体但 UI 不展示（有二期才显示「第一期」）；下期想法池不自动开期
- HITL 与门不统一建模——HITL 是智能体层交互，像 Replit 一样跟智能体交互

## §4 测试外包循环

```
开发平台发测试任务（定向指派 OPC）→ OPC 执行 → 提交（Bug 清单 + 结果说明）
→ 开发平台确认｜驳回（退回返工）→ 确认后 Bug 入库、系统自动派开发智能体逐条修复
→ 修复完成 → 提示再发复测任务 → 循环至无未关闭 Bug →〔开发完成确认门〕
```

- Bug 三态：待修复 → 已修复 → 复测通过；字段含标题/描述/复现步骤/严重级/截图附件
- 可见性：OPC 最小上下文；需求端只见「测试中」；开发平台全量

## demo（platform/frontend/src/App.vue，~480 行）实际演示的功能块

1. **建项目区**：项目名 + **引擎选择下拉**（opencode/dsh）+ **项目类型模板下拉**（官网 4 阶段/电商 7 阶段，下拉直接显示阶段链）；项目列表 + 删除
2. **阶段条 + 审批门**：stagebar 高亮当前阶段；本阶段智能体角色 + 任务计数；✓ 通过 / ✗ 驳回重做；「没干活不能审批」409 提示；完成 🎉
3. **中间件卡片**：每项目独立 PG/Redis 连接串 + 端口 + .env 注入说明
4. **给智能体下任务**：输入框（阶段切换自动填建议任务）+ 计时器；**👁 预览按钮**新标签打开
5. **黄色问题卡（HITL）**：3s 轮询待答问题；多题、单选/多选（选项带 title）、自定义文本；**刷新/切项目后仍能找回**（轮询不随任务停止）
6. **Agent 直播画面（SSE 分色渲染）**：text / reasoning（截断 300 字）/ **patch（diff 预览）** / error / task-start/finish / step 边界 / **knowledge-retrieved（📚 来源 artifact + 项目名 + 命中条数 + chunk 摘要）**
7. **环境内执行命令**：命令输入 → stdout/stderr 终端块
8. **原始事件流**：最近 30 条 JSON（上限 200 缓存）

demo 没有的（= Phase A 补的）：对话建项目、详情页三按钮门、OPC、Bug 表单、待办、成员页、登录。
