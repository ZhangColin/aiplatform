# 双交付物平台定位：系统与设计资产同台交易

设计能力线定位裁决（2026-10-03，#272，依据 docs/research/2026-10-03 四路调研快照）定案：平台从「定制系统交易平台」扩展为「定制系统与设计交易平台」——同一套设计过程能力（多稿探索、挑选、渐进呈现）服务双终点：设计即交付（产物＝设计资产，走完整商业流）/设计服务系统（被选设计稿喂系统生成）。行业事实：六家对标平台无一把设计产物当交易交付物卖（stitch 纯免费零交易语义）——双交付物是**对标空位上的自主定位赌注**，非补标配缺口；赌注押在「非技术用户的一句话需求→访谈→设计交付」链路复用（访谈/PRD/对话区/迭代全不动摇）。核心决策：**一单一程**——每项目仍至多一单一笔支付，设计探索与挑选全部落在下单前（与迭代同性质、不产生中间交易），双终点项目＝系统单（冻结物在 PRD 快照＋源码包之上追加选定设计稿）、设计-only 项目＝设计单（冻结 PRD 快照＋设计资产包）；报价/改价/状态机/取消回迭代机制零改版，订单只加交付物类型维度（系统/设计/系统＋设计）——「支付完成归档即终点」的项目语义与图外条款（交易机制只做扩展接入）双双保住。**交付物包＝统一部件容器**：图、设计稿（HTML）、系统皆产物部件，打在一个包里、部件类型可区分；谱系不硬分，部件能力随出图档位/图片管道裁决生长（现在＝HTML 设计稿＋规范＋系统；图部件备案）。「平台止于支付完成」对设计交付物对称成立（无验收期、无免费修改承诺；要改归迭代-再下单既有口径）。词汇：产物主词「设计稿」、容器「交付物包」（源码包/设计资产包为类型称谓）；「原型」avoid 扩展到设计线——全平台用户面永远看不到「原型」；「设计即交付/设计服务系统」为图内工作词汇不入 CONTEXT.md。入口有选择（做系统 vs 做设计，呈现细节另票）；设计交互基调对标 stitch/figma（画布、直接操纵同族交互模式）。

## Considered Options

- **双单串行（设计单先行支付、系统单后起）**——拒绝：「支付完成归档即终点」直接挡死（设计单支付即项目归档，系统段无处容身）；除非改归档语义＝改交易机制，撞图外条款。
- **设计产物位图为主形态（logo/海报先行）**——拒绝为现在做：位图依赖图片模型与图片呈现管道（出图档位/图片管道两票未裁决），且设计稿主形态业界收敛于可交互轻量实现（六家无一以位图为主形态）、与一致性桥（规范级硬要求）同形态；图部件备案，触发器＝出图档位（#275）与图片管道（#276）两票落地。
- **按图/HTML/系统硬分交付物谱系**——拒绝：用户拍板「都是产物的一部分，打在一个包里，能区分是最好」——统一容器＋部件类型可区分，不硬分谱系。
- **设计线用户面沿用「原型」行话**——拒绝：「系统」词条 avoid 军规全平台统一；六家中「原型」仅扣子中文一例，不足以破例。

## Consequences

- CONTEXT.md 开篇改写为双交付物口径；新增词条「设计稿」「交付物包」，订单词条冻结语义随改（随交付物包交后台）。
- 后台订单运营面将出现第二类交付物订单（资产交付、报价素材呈现、设计过程成本观测）——独立裁决票已开。
- 入口需呈现「做系统 vs 做设计」的选择——独立裁决票已开。
- 图（位图）部件进包依赖出图档位（#275）与图片管道（#276）两票裁决；两票落地前设计线产物以 HTML 形态交付。
- AI 生成图商用授权口径（运营侧）随位图部件启用再裁（备案）。
