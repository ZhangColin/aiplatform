# #25 验收门：AgentScope × opencode 双路活体对照记录（2026-08-31）

> 票：[#25 片2-4 验收门](https://github.com/ZhangColin/aiplatform/issues/25)（母票 #13）。
> 性质：迁移验收门活体对照——同 PRD 分别走 AgentScope 新路径与 opencode 旧路径各一次真实生成 run，
> 五维对照（产出质量 / 收口率 / 续会话 / token 消耗 / 流式完整度），判定 AgentScope 可否作默认栈。
> 副作用均以真实状态（DB / 容器 / 文件 / HTTP）为准；全程单机本地环境。

## 2. 五维对照

### 2.1 产出质量（同 PRD 各一次完整生成 run）

| 项 | A 路（AgentScope，项目 D） | B 路（opencode，项目 B） |
|---|---|---|
| 收口判据·8081 | ✅ `curl localhost:8081` → 200（4.6ms） | ✅ 200（10.8ms） |
| 真实数据库 | ✅ 8 张业务表（pg，DATABASE_URL 落 .env） | ✅ 8 张业务表 |
| 种子数据 | ✅ 8 会员（含爽约/暂停态字段） | ✅ 11 会员 + 8 课程 + 4 教练 + 45 排期 + 56 预约 + 13 收款 |
| 页面覆盖（PRD 五模块） | ✅ Dashboard/Members/Cards/Courses/Bookings/Reports（vite SPA，dist 已构建） | ✅ 工作台/会员/办卡续费/课程排期/约课签到/经营数据（入口 HTML 直出六页导航） |
| 业务规则字段 | ✅ no_show_count / suspend_until（爽约 3 次停约 7 天） | ✅ 同左 |
| 经营报表 API | ✅ 月收入/新增/出勤（attendance 分桶） | ✅ 收入分桶/出勤率 92.1% 实测值 |
| 代码量 | 20 文件 / 3803 行 TS | 15 文件 / 2766 行 TS |

**判读**：同 PRD 双路都产出「真实可运行、带库、带种子数据、覆盖功能清单」的系统，A 路（AgentScope）代码量略多，质量**不劣于** B 路（opencode）。

### 2.2 收口率

| run | 结果 | 用时 | 备注 |
|---|---|---|---|
| A 路 run①（修复前） | ❌ 假完成 | 2.7 min | 无命令工具，模型道歉放弃；converse 无异常 → **generated_at 照落**（项目被 PRJ_017 锁死） |
| A 路 run②（仅 sandbox 修复） | ❌ 假完成 | 4.5 min | 12 次迭代被 maxIters=10 掐断；同样假标生成 |
| A 路 run③（双修复） | ✅ end | 36.8 min（2 试） | 首试 30m 墙钟超时 → **自动重试续同会话** 7 分钟收口；重试机制/话术/帧序全程符合 #22 设计 |
| B 路 | ✅ stop | 22.2 min | 单发单收；权限挂起 0 次（#30 §7-① 的 .env 读挂起未复现） |

**判读**：修复后双路都一次走通收口判据。A 路暴露的两处平台接线缺口（§4）不修则收口率为 0——这本身就是验收门的最大价值。残留风险：**run 无异常即落 generated_at、无 8081 可达核验**，假完成会把项目锁死（run①②实证），见 §5-③。

### 2.3 续会话能力

| 场景 | A 路（AgentScope） | B 路（opencode） |
|---|---|---|
| 跨 run 续同会话 | ✅ D 首试超时 → 重试**续同 coder 会话**（「从中断处继续」prompt）39 迭代 7 分钟收口——平台真实路径 | ✅ 同 session 二次 message：2.5 分钟完成「会员按卡状态筛选」修正并自验（11/9/1/1 计数实测） |
| 断点续作（半成品上接着做完） | ✅ C 项目（12 迭代被掐、只写到后端）清 generated_at 重新发起：25 秒即直入「编写前端界面」不重读 PRD 从零起跑，18.8 分钟 111 迭代单 turn 做完整套（8081 ✓ 8 表 ✓）；用量 2.43M tokens | （未单独触发同款半成品场景；同 session 二次 message 已覆盖「带完整上下文继续」同口径） |

**判读**：双路续会话能力同构达标；A 路（AgentScope）的 PG 状态存储在平台重启场景更稳（旧路径状态在容器内）。

## 3. 验收门判定

> 口径（#7 决议）：产出质量不显著劣于即过；不达标 = git 回退该切片、opencode 临时续命。

**判定：通过。AgentScope 作默认栈成立。**

- 产出质量：不劣于（§2.1，双真系统，A 路代码量略多）
- 收口率：修复后双路同达标（§2.2）
- 续会话：同构达标、重启韧性更优（§2.3）
- token：同量级且更低（§2.4）
- 流式完整度：A 路结构性胜出（§2.5）

附条件：**两处平台接线修复必须随本票合入**（§4）——不修则 AgentScope 路径收口率为 0，「通过」不成立。opencode 全套按计划随片 5（#31）删除，无需临时续命。

## 4. 对照中发现并修复的平台接线缺口（随本票合入）

| # | 缺口 | 根因 | 修复 |
|---|---|---|---|
| ① | 编码智能体**无命令执行工具**（装依赖/起服务/收口自检全部不可能，run① 道歉式放弃 3 分钟） | `DockerExecFilesystem` 只实现 `AbstractFilesystem`（文件面）；HarnessAgent 仅当 `instanceof AbstractSandboxFilesystem` 才注册 ShellExecuteTool（字节码实证） | 补实现 sandbox 接口：`id()` + `execute()`（docker exec、stdout/stderr 合并、100K 字符截断、超时按调用方秒数经 `ExecCommand` 三参重载透传）+ 3 个缝测试 |
| ② | 编码 turn **10 次迭代即被掐断**（run② exceed_max_iters 假完成） | `HarnessAgent.Builder` 构造缺省 `maxIters=10`（字节码 bipush 10 实证），平台工厂未覆盖；一次完整生成实测单 turn 需约 161 次迭代（D 首试 122 次撞 30m 墙钟未完 + 重试 39 次收口；C 续会话 111 次单 turn 完成） | `AgentscopeProperties.maxIters`（null=不覆盖框架缺省）→ 工厂下发；`application.yml` 定 `app.agentscope.max-iters: 300`（实测需求 ×2 弱取余量；失控保护以 30m 墙钟为主界，本上限只作次级护栏——属性注释为单点正本） |

回归：`DockerExecFilesystemTest` 24 绿 + `AgentscopeHarnessAgentFactoryTest` 6 绿（1 skip 为无 key 真构建断言，口径同 #44/#45）。

## 5. 遗留与移交（不阻断验收门）

- **② BA 续跑轮「自答泄漏」（高危，另开票）**：续跑重写的工具 input（含注入 `answer`）持久化进会话 → 模型学会往后续 `ask_user` 塞自答 `answer` → `checkPermissions` 见 answer 键即放行 → 访谈自演自答 9 问、DSML 文本工具调用退化、exceed_max_iters。本次 PRD 靠「催促收敛 + 补真实答案」救回。属片1（#19/#20）平台协议缺陷，与引擎选型无关（任何 LLM 都能钻该 schema 泄漏），不影响本门判定。
- **③ 生成收口无核验即落 generated_at（中，另开票）**：run 无异常 = 成功——run①②实证「道歉式放弃/被掐断」也会锁死项目（PRJ_017 禁止重新发起）。建议：markGenerated 前核验 8081 可达（收口判据的程序化对齐），或允许未过核验的重新发起。
- **④ 计量 reasoning 桶缺读（低，顺手）**：AgentScope 路径 reasoning 恒 0（B 路同模型 26K）——agentscope-openai 扩展的 usage 解析疑未取 reasoning_tokens，成本报表会低估，片5 前顺手核。
- **⑤ 生成首试 30m 墙钟超时偏紧（低）**：中等 PRD 单 turn 实测 161 迭代 37 分钟（超时被重试兜住）；更大 PRD 如常态超时可调 `app.generation.timeout`（迭代上限已取 300 余量，见 §4-②）。
- 环境清理：8890 实例、四个对照项目（A/B/C/D 容器与库行）、B 容器内 opencode serve——留档可查，收尾片随 dev 库重置一并清理。
