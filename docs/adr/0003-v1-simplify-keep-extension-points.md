# v1 简化边界：砍能力，不砍演进点

业务重定义裁掉大量旧能力（期、决策门、任务、待办、多门户……），v1 以核心功能——聊透需求、高保真系统、知识沉淀——为目标**坚决防过度设计**：业务目标里没有的概念不抽象、不包装（如多引擎适配层、运行时可配置的泛化机器）。但简化不允许堵死演进：扩展点取**最便宜的形态**保留——编译期薄缝（一个接口一个实现，不做运行时注册表）、workspace 文件资产（AGENTS.md/SKILL.md/tools.json，换实现不迁移）、加列加表即可演进的显式事件与数据步骤；不允许将来推倒重来。增强项（通知推送、结构化报价、支付深化、知识检索增强等）等平台能用后逐个开票，不预建空壳。

## Considered Options

- **运行时泛化机器（注册表/配置表/策略面板）留扩展点**：否——把「将来可能」提前实体化，恰是本决议要防的过度设计；薄接口与 git 历史已是足够的回退面。
- **一简到底、不留缝**：否——AgentScope Java 尚年轻（GA 约 2 个月）、业务方向仍会动，零缝意味着任何演进都是重写。

依据：GitHub issues #4 会话用户明示总则；#7 会话细化（AgentScope 单栈定调与删除清单）。
