# 生成加门：确认此版 PRD 并生成 Demo（首个构建 run 的唯一触发）

> 本 ADR 改写自「生成无门自动发起（『开始做系统』按钮退役）」——旧口径（主智能体产出 PRD 后平台在意见轮收口自动派首个构建 run）已由 #309（生成加门）推翻、#315（PRD 确认门与版本快照）确立新机制，spec #320 实施序③落地（#330 确认即成版、#331 两级门、#332 生成加门）。

首次生成此前是唯一无须用户操作、由平台在意见轮收口自动发起的动作。现改回一扇**门**：主智能体产出 PRD 后，平台**不再**自动起首个构建 run——用户在需求分析页过**确认门**（主 CTA「确认此版 PRD 并生成 Demo」）后，平台冻结该版 PRD 为不可变版本快照并自动派首个 Demo run。「确认此版 PRD 并生成 Demo」是首个构建 run 的**唯一触发**。判据（收口观测点）：**未生成 ＋ 存在已确认 PRD 版本 ＋ 用户触发确认**。失败重发同口径：run-failed 后项目仍「未生成」，用户重提（重确认或「继续生成」）即再触发，不设常驻重试按钮。

## Considered Options

- **保留「生成无门、PRD 出即自动起」**（旧 ADR-0008 口径）——出局（#309 推翻）：无门的自动起跑把「PRD 初稿」当作够做系统的信号，但初稿常有待定项与范围级未决；起跑即消耗整套生成轨道，返工代价高。把「用户确认」这一人工信号前置，让大额消耗（首个 Demo 生成）挂在用户明确动作上，与「商业价值挂在用户确认」（确认下单、付款）同构。
- **新增 `start_generation` 工具**（主智能体判定「收敛」时调用，平台观测工具事实派发）——出局（旧 ADR 0008 已否）：生成前的「收敛」没有独立语义，为无门动作再造判定点属投机性复杂度（与 ADR-0003 反投机性复杂度相悖）；判定应归平台代码、用户动作应显式。
- **保留「开始做系统」按钮（无版本快照的裸确认）**——出局（#315）：门若要立，必与「确认即成版」绑定——确认动作同时冻结当时的 PRD 全文为不可变版本，成为后续下单、生产承接的引用锚（「下单前置＝存在已确认 PRD 版本」）；裸确认门不产生可追溯版本，门失去挂点。
- **两级门硬拦所有待定项**——出局（#331）：只有**阻碍核心流程**的缺项硬拦（用户不可绕过，须先在对话区补齐）；仅次要未知放行成版，确认时两段式摘要层如实呈现未解决事项。解析缺失（章缺失/形态漂移，含存量旧「待定项」章）fail-open——误拦即用户死锁，漏拦可经迭代补救。

## Decision

- **确认门＝确认即成版（#330）**：确认动作把当时工作区 PRD（`docs/PRD.md` 活草稿）全文拷贝为不可变快照（＋确认时间＋项目内递增整数版本号 v1/v2/v3…）落平台库；工作区 PRD 仍是活草稿照旧覆盖写（草稿不编号，确认即分配版本号）。重复确认（无新草稿＝全文未变）幂等返回既有版。
- **两级门（#331）**：确认前解析「验收与待确认」章——有阻碍核心流程缺项即拦（PRJ_053，用户不可绕过）；解析缺失 fail-open 放行；仅次要未知放行、回执带未解决事项（两段式摘要层数据面——「已看过摘要」由呈现层承载）。
- **生成加门（#332）**：确认成版后平台自动派首个 Demo run。收口观测点判据（用户对话轮）改判为「未生成 ＋ 存在已确认版本」——未确认静默待确认（不派、不报错、不落轨道片行）。平台发起的需求侧轮（切片计划补产、终点切换重产）是「确认后派」「存量恢复」的达成机制，不经此门直接放行（否则确认/恢复的补产链被自己的门拦死）。设计类终点（含系统＋设计）分岔代码保留、触发律不改（未定稿起设计过程、全部定稿起构建；入口已收起、无上线面）。
- **门与呈现同票（spec #320 段间耦合红线）**：门机制（关闭自动起）与其呈现面（需求分析页确认按钮＋两段式摘要层）不留「门在机制上关了、呈现上没有开门按钮」的中间态——PRD 在场即出确认主 CTA。

## Consequences

- **行为变更（上线前复核口径变化最大处）**：生成无门 → 确认门。主链路从「PRD 产出即自动起」改为「用户确认后起」。
- 生成与更新 run 的派发机制仍收敛为「轮收口 → 平台观测 → 自动派发」一条线，但首个构建 run 多一层确认门；主智能体均无派发权。
- 生成失败（run-failed）后不自动重试（防空烧 token）：项目仍「未生成」＋存在已确认版本，用户重提即再触发；「继续生成」出口照旧兜底（异常态，非常驻门）。
- **词汇收口**：CONTEXT.md「生成」由「自动推进」改为「确认推进」（生成＝用户确认 PRD 后平台起首个构建 run，确认动作是唯一触发）；「开始做系统」（按钮称谓）仍在 Avoid；「确认门」自 Avoid 移出（旧「PRD 无最终版、唯一冻结点是下单快照」的表述随本决定作废——确认门是新冻结点）。
- **未决项已全部落地**：下单/合同冻结的「引用已确认 PRD 版本＋全文冗余拷贝」引用语义随 #335 落地；改需求回路（新草稿 → 确认新版 → 下一版 Demo）与差异摘要随 #334 落地（小迭代基准＝当前已确认版本，CONTEXT.md「迭代」词条）。
