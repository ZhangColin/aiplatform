# 机制去留总表：从零重设的全部机制审查结论

平台从零重设的机制审查归档（承 从零重设总索引 #573；审查对象＝机制总清单 #574——CONTEXT.md 全部 132 词条＋docs/adr/ 53 篇＋代码面机制〔13 条执行协议、装配、SSE、网关、置备链等〕全部归位；逐项判决、实验数据与 重新考虑的条件见各 issue 决议评论，本文档为结论索引与定案清单）。审查立场（用户裁决）：不遗漏——清单逐项给结论、逐项核对划掉；准入标准——每项新增必须实验证明严格更好才进，证据不足的宁可不进；决议语言——一律「进／不进＋什么条件下重新考虑」，不写「v0 先做、v1 再说」。

**判据分三类（用户裁决，#582）**：生成链上的机制＝实验证明严格更好（证据不足不进）；界面交互件＝体验好且不拖速度即可保留；知识／技能＝看跨项目复利。供给与载体类的集成点用另一把尺：有人用→原样保留，没人用→砍，用法变了→按新用法简化（#583／#584）。

## 结论二：重建成后采用

|---|---|---|

| 迭代受理 | 主智能体受理半边以对话面形态重建（轻会话＋访谈式澄清＋纯答疑＋只读工作区） | #577；ADR-0056 |
| 对话区过程呈现 | 工具动作流＋收尾卡＋预览跟随（活性行／时钟／定格沉没保留；计划区两级、解说直播出局） | #578；ADR-0057 |
| 智能体事件部件模型 | 收窄重建（工具动作部件三面语义＋叙事段守卫＋脱轨信号部件保留；步骤清单部件出局） | #578；ADR-0057 |

## 结论三：砍掉清单

**审查与收口组（#579）**：三硬底线（「能打开」归探活机器判据、好坏归六项人眼、「刷新不丢」由工作区持久结构性承接）；机器探活三件套收窄（8081 探活保留＝预览转可用的门；入口文件完整检查与 git 成版收口半边出局）；片轻验／验证子智能体；整轨终验；核心旅程清单；预览哨兵；收口三运营开关；finish_edit 更新收口件。

**生成执行栈组（#580）**：切片与切片计划；单会话态／切片机器态两开关＋并行波次机器；13 条执行协议；会话车道（双池／错峰／优雅排空；全局并发闸随 #589 一并不进、配置键 `generation-stripes`／`generation-admission-interval` 拆除）；修轮；空转片拒绝／产出证明；续跑机器；AGENTS.md 注入／预置件写保护；子智能体委派机制；按槽位工具面装配＋增强开关（增强件改走必配清单逐件准入）；推迟清单；旧失败语义（片重试预算／跳片／阶段 0 中断）。

**风格与设计资产组（#581）**：风格方向库；风格方向→设计规范物化链；规范三件套（token 写入／协议注入／收口扫描＋调色板收窄）；栈规则集（工作区 AGENTS.md 规则节）；golden/硬链种子（ADR-0046 终局判定既成事实，跨卷硬链内核语义不成立）。风格引导整体不进——「跨项目风格趋同」在本平台未被观察到，用户写一个风格词即强跟随且跨次稳定；PRD 风格词为准、零机制。重启条件：真实用户抱怨「做出来的系统都长一个样」且影响验收／演示。

**增值交付组（#582）**：Run-Id trailer；Demo 版本序 vN 绑 PRD vM 构建基准；快照构建基准义①②（PRD 版本起跑记行）；差异摘要（savePrd summary）；双轴版本记录抽屉（重建为单轴时间线）；时间旅行预览独立机制（回滚已覆盖）。

**模型通道计量组（#583）**：模型路由（三信号消费者全灭）；升档窗口（attempt 级概念随旧机器消失）。重启条件（同门）：实证出现「快配置稳定干不动、强配置干得动」且运营手动换档跟不上。

**迭代与呈现判决带出（#577／#578）**：迭代受理链（机制面）；派发；交接物（机制面——功能由对话面蒸馏产物承担）；在途意见排队合并编排；计划区两级呈现；update_plan 步骤清单部件；切片级多收尾卡；「正在创建首页」渐进占位（旧形）；轮次计数呈现；文件树面板；流式解说直播；平台通知消费（通道保留、零新发布点；离线召回＝发短信／推送级需求的重启条件）。

**数据飞轮带出（#588）**：技能预检（指派前重叠判定）；智能体自荐技能、技能草稿、晋升与拒绝；主智能体上的两个自荐工具连同提示与提醒。技术坑不建知识沉淀——直接修底座。

**多项目并发（#589）**：全局并发上限机制不进——零失败实例；新内核路径资源面组合＝项目内 FIFO（#577 施工自带）＋休眠＋封存＋失败语义＋Docker 硬边界，零新增。重启条件：并发资源劣化实例（速度门槛被挤破／容器 OOM／主机卡死），届时参考口径已附决议评论。

## 诚实结论

审查完。生成链内核本体上，**没有任何一项旧机制证明了「裸内核＋它＝严格更好」**——切片、协议、验证、风格层、路由、修轮、续跑，全部出局或自然消亡；这正是老索引的教训被实验证实（过去两年的机制全是理论推导、从未与裸基线对照过，单看都有道理，合起来净贡献是负的）。活下来的新增机制全部长在界面与基建上：版本时间线、圈注、过程呈现、供给链、计量、沙箱宿主、数据飞轮。所以平台今天的诚实形态＝**裸生成内核＋跑着的预览网址＋一句话迭代打磨**，加上把这套服务托起来的供给链与沙箱基建。若后续新增机制过不了准入标准，「平台＝裸内核套层界面」这个结论照样成立——敢写在这里。

## Considered Options

- **逐项为旧机制辩护式审查**——否决：准入标准取代（不重演逐件找存在理由的旧做法）。
- **保留验证层作为质量底线**——否决：四组容器实证零不可用＋用户质量容忍标准（活着＋可迭代＝可接受；迭代回路本身就是质量机制）；探活一件是唯一收口门。
- **全局并发闸防资源挤爆**——否决：零失败实例，Docker 硬边界＋休眠封存已构成资源面；真出问题重跑即恢复（失败语义）。
- **风格机制防趋同**——否决：问题在本平台未被观察到，不预支机制；头部竞品正在退出前置风格形态。
