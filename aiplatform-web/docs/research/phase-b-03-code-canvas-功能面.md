# Phase B charting 资产 ③：Code-Canvas 功能面盘点（2026-08-22）

> 三路盘点之三。CC 是用户认可的视觉与交互基准；本仓 v1 不照抄全量，按业务流需要取用。对既有调研 docs/research/code-canvas-frontend.md 的核实与三点修正：① `isAdmin` 是契约字段，Skill 市场 CRUD 有真实权限门控；② 交付阶段面板（生成/打包/校验/修复回环/下载）是前端最完整的「阶段专属功能」范例；③ 知识库 UI 与模板选择卡片属「设计有、前端无」。

## 产品形态

「人机协作工坊」：一句话建项目 → 需求澄清 → Demo 迭代 → 开发 → 验收 → 交付，5 阶段状态机 + 每步人类闸门；每轮智能体任务 = 一次 git commit = Checkpoint。

## 平台感五来源（做同类功能的对照镜）

1. **阶段状态机当全局骨架**：顶栏徽章 + 右栏时间线 + 闸门卡 + 需求变更回边
2. **双 HITL 统一「待我处理」**：工具审批卡（amber、入参预展、30 分钟过期告知、拒绝/允许 + 终止任务逃生口——防「拒绝≠停止，LLM 换形式重试」的审批循环）与阶段闸门卡（驳回必填意见且原样转给智能体）并列
3. **产物体系全闭环**：预览（安全 iframe，`sandbox` 故意不给 allow-same-origin；preview.updated 到达只提示不自动刷新）→ 文件（在线编辑即 commit，baseCommit 乐观并发）→ 文档（8 分类 + 版本链侧栏）→ 时间线（检查点/闸门/打回三类合并倒序）→ 回滚（AlertDialog 讲清 git revert 语义 + 数据库不回退警告）→ 交付包（生成→打包校验→逐项 ✓/✗ 报告→失败一键发回智能体修复→下载 zip，只留最近 3 包）
4. **SSE 直播 + 运行回放**：打字机/思考/工具芯片（「正在使用工具」→「已执行工具」）+ 每条消息检查点 hash 徽章 + RunReplayDialog（全量 run 事件回放，14 种中文事件标签）
5. **平台级周边**：成员（owner/developer/tester + 授权矩阵，前端只隐藏不算权限）、token 配额（进度条 + 用尽变红 + 硬拦截）、Skill 市场（平台级库 + 项目安装同步进沙箱）、模板体系、项目初始化状态机（pending→repo→db→ready/failed，2s 轮询 + 失败重试 + 未 ready 不可点入）

## 前端工程要点（可借鉴的实现约定）

- 每工作台一条 EventSource（按 conversationId）；`{runId}:{seq}` Last-Event-ID 补发 + 前端 Set 去重（上限 2000 清空）
- **SSE 事件只做 invalidateQueries，前端不合成持久状态**；流式气泡用本地 streams 表，任务终态即丢弃
- 轻轮询兜底：不在挂载树的查询 15s，usage 30s
- query key 工厂 16 组；处处重试按钮；`data-testid` 全覆盖
- 消息流内嵌「待我处理（N 项）」（pending 审批 + pending 闸门合计）
- 附件上传单请求原子发送（消息落库 + 文档归档 + 任务入队同事务）
- <1024px 折叠三页签的响应式三栏

## 设计有、前端无（引用时注意区分）

知识库 UI（knowledge_assets 表 + searchAssets 工具，openapi 无端点）、模板选择交互（只读展示）、多会话（hack 只用「主线程」）、通知中心、终端/日志查看（sandbox/logs 端点未实现）、计费账单（只有配额硬限）。

## 四端演进蓝图（docs/design/10 §10.1，与本仓三门户对应）

统一工作台（现状）→ 需求方门户 / 专业开发工作台 / 运营后台。核心原则：**前端只是过滤视图，权限始终在服务端强制**。
