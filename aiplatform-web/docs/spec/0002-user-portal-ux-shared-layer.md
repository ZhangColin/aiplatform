# Spec 0002 · 需求端门户 UX 与通用层/场景层架构

> 产地：wayfinder T5（[#7](https://github.com/ZhangColin/aiplatform-web/issues/7)，prototype 票）。
> 可点原型（primary source）：分支 `prototype/t5-user-portal`（cumulative：`shared/` + `user-portal/` + `workbench/` 等；`?variant=A|B|C|D`，D 为定稿，A/B/C 为被否的探索变体，留存供回溯）。
> 真实实现等后端 A3 对接 issue；对接时照本 spec 落地，面板内容分配到功能点再定。

## 1. 定稿结论：通用层 / 场景层

**菜单处理、智能体对话区、预览、工作台框架——这些本身与具体场景无关，是通用层；场景（门户/功能点）只决定放什么、放哪里、什么文案口径。**（用户原话收敛）

- **通用层（与场景无关，全平台一套）**：
  - 主 Layout：sidebar（菜单契约见 §2）+ SidebarInset（spec 0001 不变）；
  - 工作台框架：顶栏插槽 + resizable 三栏（左 Agent 区 / 中主面板 / 右呼出）+ 右栏显式开关 + `<md` 三页签退化；
  - 通用能力组件：菜单处理、Agent 对话区（消息流 / 系统胶囊 / 问答卡 / 门卡 / 输入条）、预览（手动刷新 + 独立打开）、文档面板、旅程呈现。
- **场景层**：需求端 / 开发平台 / 任务平台只是同一套壳的配置——面板挂什么、徽章与文案什么口径。
- 原型对应：`prototype/shared/shell.tsx` = 通用层同构参考（真实现 = app 级 layout + 工作台 layout 组件）；`user-portal/variant-d.tsx` = 需求端配置；`workbench/variant-d.tsx` = 开发平台配置（同壳消费者）。

## 2. 菜单契约（框架通用、内容场景化 —— T6 修订，详见 spec 0003 §1）

```
品牌位  门户切换 dropdown（需求端 / 开发平台 / 任务平台 = 场景切换：菜单 + 落地页一起换）
项目     项目项：FolderKanban + 阶段徽章（spec 0001 口径；点击进该项目工作台）
平台     项目列表 · 新建项目 · 待办中心(N) · 成员   ← 各场景按配置取用
footer   用户 + 主题切换
```

- ~~菜单不因门户而异~~（T6 作废）→ **菜单框架归通用层（切换器 + 分组结构 + footer），菜单内容归场景层**：每门户一份场景菜单配置——需求端 = 项目相关；开发平台 = 全量；任务平台 = 我的任务 + 待办中心。分配表与落地页见 spec 0003 §1。将来按登录角色过滤、或拆独立前端项目，场景配置即拆分缝。
- 项目列表页、新建项目 = 通用页面能力，按场景菜单取用（任务平台不入口）。
- 需求端的「等你」等用户侧状态出现在**场景内容**（列表卡 / 工作台顶栏徽章），不进菜单。
- 新建项目 → CC 框一句话创建（§3.1），有入口的场景同一形态。
- **需求方流程修订（2026-08-25 grilling）**：需求端场景菜单收为两项——「首页」（`/`，新建 hero 落地页）+「我的项目」（项目列表页）；项目直列与「新建项目」「待办中心」「成员」从需求端菜单去除（新建唯一入口 = 首页 hero；待办深链保留，「需要你」可见性靠首页/列表卡 amber 行 + 工作台徽章）。切换器增第四项「后台」（简易后台，见 CONTEXT.md）。收起交互修订：收起按钮归位品牌行右侧（各页头 `SidebarTrigger` 移除），收起态 = icon rail，点 Logo 或 rail 空白处展开；展开态品牌行 = 门户切换 + 收起按钮（收起态点 Logo = 展开，不弹切换菜单）。

## 3. 需求端三面

1. **新建项目**（门户首页/落地页，菜单项「首页」，无页头 Trigger，整页 hero）：CC 框复刻——渐变光晕（focus 加深）、大内边距卡式输入、圆角发送钮；下方「最近的项目」限 4 条 + 「查看全部」→ 项目列表页（项目数增长不受影响）。一句话提交 → 建项目直进工作台对话（顾问第一轮问答卡就位）。**修订（2026-08-25）**：表单收为纯一句话——名称输入（项目名由后端 LLM 从需求生成，禁止截取派生，aiplatform-server#39）、类型模板（单链服务端默认，#39）、引擎选择（后台全局配置，#42）全部去除；「最近的项目」排序口径落定 = 更新时间新→旧，卡片带「需要你」amber 行（无待办显安心态行）。
2. **项目列表页**（非工作台页同壳，页头 = Trigger + 标题 + 说明）：卡片网格 = emoji + 名 + 当初一句话 + 六步 mini 进度 + 「需要你：xxx」amber 行（或安心态行 + eta）+ 更新时间。列表过滤与归档（#20 落定）：
   - **Segmented 四态过滤**：全部（缺省，不传 `status`；响应中 `archived:true` 的项前端过滤不渲染——默认视图不见已归档）/ 进行中 `status=1` / 待处理 `status=2`（= 门就绪或有待处理等待点，对应卡上 amber「需要你」行）/ 已归档 `status=3`。Integer code（后端 #34 统一口径）；不依赖后端 all 的归档语义假设，防御性本地过滤。
   - **归档操作**：卡片下拉菜单「归档」→ dialog 二次确认（明示单向不可逆）→ `POST …/archive` → invalidate 列表/详情；重复归档 409 `PRJ_013` 走统一错误提示。归档成功的项目从「全部」消失，可从「已归档」找回（灰态卡）。
   - ~~**sidebar 项目列表** = 未归档口径（同「全部」）~~（2026-08-25 作废：需求端菜单不直列项目，见 §2 修订）。
3. **项目详情 = 用户工作台**（§4）。

## 4. 用户工作台（D 融合壳的需求端配置）

- **顶栏**：项目名 + 环节徽章（等你 = amber）+ 六步面包屑 + 浏览器打开。
- **左 Agent 区**（对话，单模式——需求端无直播/待处理模式）：顾问消息流 + 系统胶囊（项目动态）+ **问答卡 / 门卡嵌流底** + 安心卡 + 底部输入（补充需求/提问；改动必填说明口径写进 placeholder）。
- **中 主面板 tabs**：预览（浏览器铬 + 「有更新·点击刷新」+ 原型/系统 badge）/ 文档（**PRD**，2026-08-25 更名，原「需求纪要」；交付后切换为交付说明 DELIVERY）；工具条右侧 = 右栏开关；将来的工具/信息面板在此生长。
- **右 呼出面板**：项目信息（当初一句话 / 当前环节 / 更新时间 + **inline 改名**，2026-08-25 增，等后端改名端点）+ 旅程（六步竖排）+ 下一期想法池（输入 + 列表）。
  - **想法池 = demand-pool 对接（#20 落定）**：输入提交 `POST …/demand-pool {content}`（≤2000 必填，空内容前端校验拦截）；列表 `GET`（新→旧）。`kind`/`source` **前端一律不传**（缺省 = USER）、不暴露选择器（用户禁词口径；BUG/测试/验收侧入口 v1 不做）；展示用 `*Name` 字段。交付后保留。
  - **用量卡（#20 简版 → #24 升级落定，后端 #29 已收口）**：右栏项目信息区放 `GET …/usage`，自上而下——① 总 token description → ② **平台成本**行（`cost` 币种分桶平铺：ISO 4217 币种码 + 等宽数字固定 4 位小数右对齐，不相加不折算；空对象显「—」）→ ③ 未配价提示（`unpriced` 非空时 muted 一行「部分用量未配价（N 档），平台成本不含这些分量」，档位明细走 Collapsible 小列表）→ ④ `byRole` 主表 → ⑤ `byIteration` 折叠（按 seq 升序，null 沉底标签「往期」；表尾「期后修复」差额行 = total − Σ期桶的前端机械减法，仅差额 >0 时显，只有 token 无成本——cost 无按期维度不假装折算）→ ⑥ `byModel` 折叠。五档 token 数（input/output/cacheRead/cacheWrite/reasoning）。口径：金额一律标「平台成本」，禁「价格/费用/金额」措辞；`byRole` 中 roleLabel=null 的用途标记桶映射 FIX→「期后修复」、RESUME→「恢复执行」，未知 code 落「—」。
- **已交付**：对话区收尾卡指向「文档」页；文档页 = 交付说明 + 源码包 / 使用说明书下载；想法池保留（下一期）。源码包下载（#20 落定）= `GET …/source-package` 直挂 `<a download>`——binary 流**不走 ApiResponse 信封**（ADR-0001 修订例外），client 旁路统一解包。

## 5. 用户侧文案口径（票面红线：用户不懂技术）

- **六步**：聊需求 → 看原型 → 制作中 → 质检中 → 验收 → 交付；**三扇门**：确认 PRD / 确认原型 / 验收（2026-08-25：PRD 用词放开，第一扇门由「确认需求清单」更名）。
- **六段 ↔ 六步映射（A3 对接落定）**：主链只有一个领域模型——详情 `stages[]`（有序）按序 1:1 映射六步（第 i 段 ↔ 第 i 步；`terminal` 段 = 「交付」终态），映射表归通用层（旅程呈现组件消费），不硬编码段键名。开发平台场景直接渲染 `stages[].label`（stage 机口径，spec 0001）；各门户是同一数据的不同关注点呈现，不是各有一条链。
- **禁词**：阶段、状态机、智能体、期、OPC、HITL、Demo（对用户说「原型」）。称谓：顾问（需求梳理）、团队（开发）、质检团队（测试）。**PRD 放开（2026-08-25）**：PRD 可上界面（文档 tab / 门名 / 顾问话术），旧称「需求清单 / 需求纪要」收敛为 PRD。
- 开发完成门（开发平台侧动作）在用户视角折叠为「质检中 → 验收」之间，不单列。
- **安心态**：制作中 / 质检中 = 「不用你操作 + 预计时间」，弱打扰。
- **门驳回 / 需求变更**：说明必填且原样转给对方（CC 模式）；**新想法** → 下一期想法池（验收门卡内 + 右栏想法池双入口；v1 不自动开期）。
- 问答卡形状 = demo `pendingQuestions`（spec 0001 §5 不变）；门卡 approve / 驳回必填口径同 spec 0001。
- **访谈循环口径（2026-08-25）**：一句话创建 → BA 立即访谈（问答卡为主 + 输入条自由补充，两者都进访谈上下文）→ BA 判定无可追问 → 产出 PRD → 确认 PRD 门（驳回意见回流续谈、更新 PRD 后再确认）→ 通过自动生成原型 → 确认原型门（意见回流，语义相关的意见同步回写 PRD）→ 循环至确认。「需求明确」判定权 = BA 自主；用户可自然语言催促（如「直接出 PRD」）推进，v1 无专门按钮。

## 6. 数据与状态口径

服务端状态 / SSE→invalidate：ADR 0002；连接拓扑 / streams store / 重连：ADR 0003。A3 对接新增：

- **主链数据源**：`GET /api/projects/{id}` 的 `stages[]`（主链定义序列：`name`/`label`/`defaultRole?`/`gateActor?`/`terminal`，有序）与 `gate: {actor, ready}`（无门段/已收口 = `null`）——进度条按数据渲染、门按钮就绪点亮均以此为源（后端 #24 已收口进 swagger；原「先静态渲染六段」的过渡计划作废）。
- **预览（落定）**：`GET /api/projects/{id}/preview` → `{url}`；无 nonce（iframe sandbox 三允许、不给 same-origin 已隔离）；「有更新」信号 = SSE `preview-ready`，刷新 = 手动重挂 iframe 不自动。
- **驳回理由（展示性瞬时态）**：SSE `stage-changed`（`rejected:true, reason`）的载荷需页内呈现（REST 详情无此字段）——通知通道仍以失效为主，载荷展示走轻量 store 白名单（桥为唯一写入方，模式同 streams store；正确性仍以 REST 重查为准）。
- **周边面数据源（#20 对接，后端 #24 已收口）**：想法池 `GET/POST …/demand-pool`；归档 `POST …/archive`（详情/列表随附 `status`/`statusName`/`archived`）；列表过滤 `GET /api/projects?status=1|2|3`（1=开发中 2=存在待办 3=已归档；缺省 all）；源码包 `GET …/source-package`（binary）；用量 `GET …/usage`（`total/cost/unpriced/byModel/byRole/byIteration`，五档 token + 平台成本分桶；#24 升级，后端 #29 已收口）。
- **枚举口径（#20 triage 落定；#34 已收口）**：枚举 JSON 双向统一 **Integer code** + 随附 `*Name` 展示名字段（aiplatform-server#34 修正 swagger 失真，`gen:api` 已刷新）。前端纪律：**展示一律走 `*Name` 字段、提交枚举一律缺省不传**——枚举值本身不进消费逻辑，后端再调 code 表不影响前端。
- **PRD / 改名（2026-08-25 新增，等后端）**：PRD 数据源 = 后端产物端点（GET 当前版，v1 无版本链；BA 写出/更新时广播通知通道新事件 `document-updated` → 前端失效文档域 + 对话区提示胶囊，失效为主模式不变，aiplatform-server#41）；改名 = 后端改名端点（右栏 inline 消费，aiplatform-server#43）。配套：创建接口精简 LLM 取名 aiplatform-server#39、BA 访谈判定循环 aiplatform-server#40、引擎全局配置 aiplatform-server#42。
