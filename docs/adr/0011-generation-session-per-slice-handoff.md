# 生成会话按切片开新会话 + 摘要交接

生成轨道不再全部切片续跑同一 `coder-{projectId}` 会话：每片 run 开新会话，起跑携带 PRD + 切片计划 + 前片交接摘要。一鱼两吃——时长上砍掉「上下文逐片膨胀、越后的片每次 LLM 调用越慢越贵」；上下文管理上根治对框架缺省静默压缩的依赖（压缩摘要质量不可控、压缩与记忆抽取调用逃逸计量）。Replit 实证同路：自测子 agent 上下文隔离、主↔子只传最小上下文、回传只带摘要。

## Considered Options

- **续跑共享会话 + 依赖框架压缩兜底**（现状）：会话越长越慢，压缩在暗处烧 token 且摘要质量无人负责——被否。
- **Swarm 级并行**（ADR-0006 备案）：触发器（单 run 时长成为体验瓶颈）虽响，但切片间是增量依赖、天然串行，并行空间有限且伤筋动骨——暂缓，待阶段级耗时埋点（见后续优化票）数据出来再评估。

## Consequences

- 交接摘要的格式与产出方（前片执行体自产 vs 平台抽取）为实施细节，实施时定。
- 更新 run（迭代链）是否同法开新会话，实施时一并明确口径。
- 框架压缩在短会话内几乎不触发，但其缺省开启的事实仍需平台显式配置接管（见 ADR-0012）。
