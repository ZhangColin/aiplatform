# 生成系统基座技术栈固化 + 镜像内置基座模板

现阶段固化一套基座技术栈（TypeScript / Next.js / React 19 / pnpm / shadcn 全套 / PostgreSQL / Redis——清单可增删，以镜像内预装的基座工程模板为准），依赖在镜像构建期装好；阶段 0 = 模板就位 + 起服，生成跳过技术选型与初始化阶段。定位依据：现阶段交付物是「可用的偏 Demo 高保真系统」，该栈足够表达；初始化等待是纯粹的浪费。更复杂的技术栈是用户下单后专业人员交付阶段的事，不进生成阶段。

## Considered Options

- **npm 缓存预热**（不锁栈，只加速 install）：不解决「执行体每次重新选型/搭骨架」的消耗，且现状生成质量也受益于统一基座——被否（可作为非基座依赖的辅助手段，不互斥）。
- **不锁栈、维持执行体自由选型**：与「现阶段高保真 Demo 够用」的定位不符——被否。

## 未来演进（备案，带触发器）

不锁死技术栈是长期方向：中间件可不一致、可按需引入；演进形态 = **一个技术栈一套镜像**。任何技术/组件进镜像**必须经过反复论证流程**才上平台。触发器：出现基座栈表达不了的真实用户需求（或专业交付要求）时，论证并新增栈镜像。

## Consequences

- AGENTS.md 平台约定补「基座技术栈」节：执行体在基座上增量生长，不换栈、不重选型。
- 首个可预览时间（TTFF）随之大幅压缩：阶段 0 从「选型+install+起服」缩为「模板就位+起服」。
