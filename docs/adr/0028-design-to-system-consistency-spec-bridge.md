# 设计稿→系统一致性：规范双件、伴随提炼与遵守三件套

设计能力线一致性裁决（2026-10-03，#277，承 ADR-0023/0024/0025——定稿稿经起跑上下文或交接物稿引用喂系统轨已定、依据 docs/research/2026-10-03-design-code-consistency.md——业界共通架构＝物化＋每轮读＋接地＋扫描纠偏，无一靠单一机制）定案：**规范级桥（v1 硬要求）的完整机制**——

**规范载体＝双件**：机器可读 token 住消费侧生效位（基座 `globals.css` `:root`——shadcn 语义变量集为底＋品牌附加色扩展＋字体对＋radius；间距/版式/组件风格不入 token：Tailwind 默认 scale 天然收敛、无校验收益不 token 化），人读规则文件（DESIGN.md 式：组件风格与用法约束）落工作区、经 AGENTS.md 指路每轮读。**作用域＝项目级单一正本**，各设计物共用（品牌一致性即「规范」语义），随定稿刷新——新定稿覆盖项目规范并触发系统按稿对齐。

**提炼＝伴随产出＋确定性提取，不经模型判读**（「图片→结构化规范」业界无现成件＝最大空档，自研口径）：界面类＝设计执行体写稿协议保证 token 集中放稿的 `:root`（对偶基座约定），定稿时平台确定性直提（结构化直读，v0 Figma token 直读同构）；平面类＝设计执行体出图时本在 prompt 指定色板/风格参数，设计参数随稿物化为规范草稿、定稿转正（参数即设计意图正身，logo 类品牌色即由此进系统主题）。**多模态读图反推备案**（触发器＝伴随参数与实际位图色偏真实发生、用户圈注指系统色不对稿；多模态 LLM 维持非依赖项、key 用户自备）。

**遵守＝三件套组合**（单件均有官方自认上限）：①**结构物化**——首个构建在起跑上下文阶段由平台确定性写入规范 token 进基座 `:root`＋落规则文件（非模型动作，v0 starter app「规范以起手工程物化」同构）；中途更新＝平台先确定性刷 `:root` 值（语义 token 引用不变时刷值即全局换肤）、裸色残留交执行体修。②**提示词注入**——run 执行体协议与工作区 AGENTS.md 加短条目（token 优先、禁裸色、禁任意值、一致性见规则文件；短条目优于长段——Lovable 官方指引），走智能体运营配置面后台可维护。③**后处理校验**——@shadcn/lint 装进基座镜像（官方 agent-first linter、Tailwind v4 即用、规则面与 Lovable adherence 同款），run 收口加 token 合规扫描。

**调色板收窄＝仅带规范项目**：Tailwind v4 `--color-*: initial` 随规范写入（默认调色板工具类消失、只暴露语义 token，硬约束）；无设计路线项目零改变（主链路运转良好不动摇）。收窄（硬）＋lint（软）双保险。

**违规处置＝有限自动重试一轮＋如实标注**：扫描发现违规（裸色/任意值/inline style）喂回执行体修一轮（对偶置备重试/出图重试先例）；仍违规＝收尾卡列违规项如实呈现，不静默不假装达标。

**「像不像」＝用户人眼＋圈注，不做机器评分**：语义级视觉判定归用户（系统预览与设计稿并排可对照，不像就圈注提意见→更新 run 按稿对齐）；圈注只长系统预览面（系统是被改对象；设计稿是规范源不是被改对象，对稿意见走设计会话改稿产新代——两条路不混）。机器评分（VLM/CLIP/截图自评/分数入 UI）无产品先例且 Lovable 官方自认浏览器自测不可靠评视觉细节——备案（触发器＝用户人眼判不动的高频场景，如页面多到看不过来）。

**验收口径＝lint 进收口自测清单、判定侧零改**：token 合规是机器可判的自测事实，进收口自测；不新增「一致性」判定出口（分类跟职责走，#273 判定枚举零改口径）；感知面＝带稿 run 收尾卡「按稿对齐」叙事＋lint 结果＋圈注通道。

## Considered Options

- 只靠提示词注入做一致性——拒绝：Lovable 官方自认长会话漂移上限，业界无一靠单机制。
- 自创独立规范文件格式（自定义 JSON schema＋翻译管线）——拒绝：发明新载体；shadcn CSS 变量是事实标准（v0 训练级口径＋Lovable 检查面＋shadcn 官方三方一致）且基座 `globals.css` 已是该形态，桥的落点零新建。
- 全量 token 化（间距/阴影/动效进 token 集）——拒绝：无校验收益、为对称而对称。
- 多模态读图反推提炼 v1 即上——拒绝：加视觉输入依赖，伴随参数即设计意图正身、零新依赖；备案带触发器。
- 机器评分「像不像」（相似度分数/VLM 评判、分数入 UI）——拒绝：无产品先例、官方自认不可靠，把不可靠的机器判定写进机制是虚假保证；人眼是零基建现成判定器；备案带触发器。
- 全平台调色板收窄——拒绝：无规范收窄无语义（「只准用规范色」先得有规范），主链路行为零改变是阶段共识。
- 违规即 run 失败——拒绝：软约束当硬门炸主链路；只报告不重试——拒绝：丢掉 Lovable「发现即自动重试」唯一产品化实锤的纠偏机会。
- 一致性进判定枚举（新增判定出口）——拒绝：合规是自测事实不是语义分类，判定侧零改。
- 设计稿 tab 点看面也设圈注——拒绝：混「改稿/改系统」两个入口，稿上意见走设计会话。
- 每设计物各一份规范——拒绝：多份规范＝生成时不知听谁的；品牌一致性正是规范一词的语义。

## Consequences

- CONTEXT.md 新增词条「设计规范」（avoid：设计系统）、定稿词条微扩（刷新项目设计规范）。
- 基座镜像改动一处：@shadcn/lint 依赖（轻量、官方件）。
- 实现落点归实施：设计执行体写稿协议（token 集中 `:root` 条款）、出图工具件设计参数物化、起跑上下文/更新 run 的规范写入与刷值、收口扫描步骤。
- #278 原型票获验证对象（圈注×按稿对齐体验）；#279 收尾票受制减至 3 张。
- 设计资产包内容含规范文件（ADR-0023 已定）与本 ADR 的规则文件为同一物，零改。
