# aiplatform 部署文档（单机 Docker 全容器形态）

> 口径：一台干净 Ubuntu 服务器（建议 ≥4C8G、盘 ≥40G）从零到平台可演示。
> 形态（#386 起）：平台以**普通接入方**身份使用共享基础设施（`deploy/infra`，
> nginx＋PG＋redis 三件套）——compose 只剩 server（含 embedding）与 web 两个，
> **唯一对外口＝共享 nginx**（semgravio-nginx，绑 80/443）；预览网关（手工 docker run
> 特例）与平台 infra compose 已退役，主站反代与预览路由经门禁装进共享 nginx conf.d。
> 本档由 2026-10-29 阿里云 ECS（Ubuntu 26.04 / 4C7.6G）实际部署收口，所有命令实跑
> 过；踩过的坑收在 §9，**换新机器先读 §9 再动手**。
>
> 依赖前提：开发机（Mac 或 Windows Git Bash）上有本仓完整 checkout——jar 只能在
> 开发机构建（cartisan-boot 父 POM 只在开发机 ~/.m2，未发布远端）。打包/发布脚本
> （`build-bundle.sh` / `release.sh` / `server.sh`）跨两平台，源码树经 `git archive`
> 导出（恒 LF，不受 Windows checkout 的 CRLF 影响；要求工作区干净，见脚本头注释）。

## 0. 大陆机 vs 海外机（先看这个）

| 事项 | 大陆机（阿里云等） | 海外机（AWS 欧洲等） |
|---|---|---|
| Docker Hub 拉取 | **必须配镜像加速**：阿里云个人加速器对未缓存镜像 manifest 直接 404（实测），要再加 DaoCloud 兜底（§2） | 直连，跳过加速配置 |
| 域名走 80/443 | 未备案域名会被**异步拦截**（实测：先通、约半小时后被拦）；IP 直访不拦 | 无 ICP 检测，裸域名＋80/443 直接用 |
| apt/pip/npm/HF 镜像 | Dockerfile 已内置国内镜像（tuna / npmmirror / hf-mirror） | 同一套照用（均公网可达），非最快但零分支 |
| https 证书 | 拦截与证书无关，备案前别折腾 | certbot DNS-01 / 云商免费证书随便挂 |

其余步骤两种机器完全一致。**ICP 拦截跟「服务器在大陆地域」走、跟域名注册在哪/DNS 托管在哪无关**——域名指到海外服务器就不需要备案。

## 1. 前置清单

1. **域名（可选）**：DNS 加三条 A 记录 → 服务器公网 IP：`@`、`www`、`*.preview`
   （预览机制＝每工作区一个子域 `{id}.preview.<域名>`，必须泛解析；无域名走 §10）。
2. **安全组**放行：`22`（限源 IP）、`80`、`443`。**不要**放行 3333/5432/6379/8888/9091。
3. **打包**（开发机仓库根）：

   ```bash
   deploy/build-bundle.sh        # → dist/aiplatform-deploy-<时间戳>.tar.gz
   scp dist/aiplatform-deploy-*.tar.gz <user>@<IP>:
   ```

4. 服务器解包（以下命令均以解包目录为根，`$ROOT` 指它）：

   ```bash
   mkdir -p ~/aiplatform && tar -xzf aiplatform-deploy-*.tar.gz -C ~/aiplatform --strip-components=1
   ```

## 2. 服务器基座

```bash
sudo apt-get update && sudo apt-get install -y docker.io docker-compose-v2
```

**大陆机加镜像加速**（海外机跳过）：

```bash
sudo tee /etc/docker/daemon.json <<'EOF'
{ "registry-mirrors": ["https://docker.m.daocloud.io", "https://<阿里云个人加速器地址>"] }
EOF
sudo systemctl restart docker
```

验收：`docker run --rm hello-world` 能拉能跑。

内存 ≤4G 的机器加 swap：

```bash
sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile \
  && sudo mkswap /swapfile && sudo swapon /swapfile
```

## 3. 共享基础设施（infra 三件套）

基础设施是**自包含部署单元**（`deploy/infra/`，可整目录拷走单独用），平台与
其它服务一样按接入契约使用它。服务器上把该目录放到 `$HOME/semgravio-infra`（或
任意路径，发布脚本的 `INFRA_DIR` 可指）——目录来源＝部署包内 `deploy/infra`（§1.4
已解包到 `$ROOT`）：

```bash
cp -r $ROOT/deploy/infra ~/semgravio-infra
cd ~/semgravio-infra
cp env.example .env   # 全新机器可跳过——deploy.sh 自动生成随机凭据；
                      # 接管既有服务器必须手写现值（见 deploy/infra/README.md「凭据模型」）
./deploy.sh           # 幂等：docker/compose→webnet＋previewnet→卷→.env→起栈→健康检查
```

**既有服务器升级一次（#397 网络别名）**：infra 的 nginx（semgravio-nginx）自
#397 起在 previewnet 挂别名 `preview-gateway`（compose.yml 声明）——后端收口探针
从工作区容器内经它打到网关（与用户浏览器同观察点）。别名是容器创建期属性：
更新 `~/semgravio-infra` 目录后 `docker compose up -d`（配置变更会自动重建 nginx，
reload 无效）。**顺序硬要求：先重建 nginx 再发带 #397 的后端**——后端先行则收口
探针解析不到别名、判据如实待期（WSP_012），预览全红是提醒不是故障。

验收与运维口径全部见 `deploy/infra/README.md`（接入契约：入网 webnet、建库建号
ensure-db-user.sh、nginx 配置走门禁 install-nginx-conf.sh）。网络（webnet/previewnet）
与数据卷由 deploy.sh 幂等创建，**不要手工 docker network create**。
**接管既有服务器**（semgravio-eu-1）：停机窗口步骤序（数据文件级拷贝＋校验＋旧卷
保留兜底＋回退路径）见 `docs/deploy/eu1-migration-sop.md`；本批拆分的关键取舍
（同仓/双网/无 manifest/网关退役/接管式迁移）见 ADR-0033。

## 4. 环境变量（平台两份；infra 凭据正本见 §3）

```bash
cd $ROOT
# ① 后端（从模板复制填值；密钥从开发机 aiplatform-server/.env.local 取，
#    可直接 grep 管道追加、不在终端回显）
cp deploy/env.server.example aiplatform-server/.env.production
vi aiplatform-server/.env.production     # 填 infra 凭据分片/PREVIEW_BASE/各 key

# ② 前端（占位记录，见模板内注释）
cp deploy/env.web.example aiplatform-web/.env.production
```

关键项说明见 `deploy/env.server.example` 内注释。三条硬约束：

- DB/redis 密码＝infra `.env` 凭据正本的分片（`SPRING_DATASOURCE_*` / `REDIS_*`，
  redis 已启用 requirepass，`REDIS_PASSWORD` 缺了后端 fail-fast 起不来）；
- `VOLCENGINE_API_KEY` **首启 Flyway V44 迁移时必须在场**（种进 `prj_model_providers`）；
- http 形态必须带 `APP_WORKSPACE_PREVIEW_SCHEME=http`＋`SSO_COOKIE_SECURE=false` 两个覆盖。

## 5. 构建镜像＋起平台栈

```bash
docker compose -f deploy/server.compose.yml up -d --build   # 后端＋embedding（#386 归位同栈）
docker compose -f deploy/web.compose.yml up -d --build      # 前端（BACKEND_URL 构建期烤入；up 一并拉起）
docker build -f deploy/dev-image.deploy.Dockerfile -t aiplatform/dev:0.14 workspace/
```

dev 工作区镜像最重（apt 中间件＋chromium＋基座 pnpm install，首次 15–40 分钟，与机器
出口带宽强相关），**必须预建**——jar 运行形态下后端按需现场构建会抛异常（代码里写明
的既知缺口）。deploy 变体（跨架构通用）与仓内原 Dockerfile 的差异见其文件头注释（chromium 走 apt、
tuna 换源前置到第一层）。

**验收（embedding 必须真打一发，`/health` 200 不代表模型可用）**：

```bash
docker exec aiplatform-embedding curl -s -X POST localhost:9091/embed \
  -H 'Content-Type: application/json' -d '{"texts":["验活"]}' | head -c 80
```

## 6. 平台路由装进共享 nginx（唯一对外口）

平台 conf（`deploy/nginx/aiplatform.conf`：主站反代＋预览/快照动态路由）与资产
（`deploy/nginx/assets/`：代理/注入块、标注脚本、提示页，assemble-assets.sh 装配）
**只经门禁**安装——撞车即拒/语法门禁/失败回滚，conf.d 目录挂载热更、不重建任何容器：

```bash
cd ~/semgravio-infra   # infra 单元目录（§3）
~/aiplatform/deploy/nginx/assemble-assets.sh ~/aiplatform/deploy/nginx/assets ~/aiplatform
./install-nginx-conf.sh aiplatform \
  ~/aiplatform/deploy/nginx/aiplatform.conf "" ~/aiplatform/deploy/nginx/assets
```

换域名：`aiplatform.conf` 里 `semgravio.com` 全局替换（主站 server_name 一行、
预览/快照 server_name 正则两行）后重跑上面第二条命令（更新自己名下文件不受撞车限制）。

结构（与仓内 dev 预览网关同构，资产路径统一按共享 nginx 形态）：
主站 → `aiplatform-web:3333`；`{id}.preview.<域名>` → 工作区容器 `ws-{id}:8081`
（带圈注注入）；`snap-{viewId}.preview.<域名>` → 快照别名（不注入）。IP 直访/未匹配
域名归 infra 兜底 server（404）——网关形态里 default_server 兜 IP 直访的口子随
共享契约收口。

**日常发布不需要碰这一节**：release.sh 每次发布都会经门禁重装 conf＋资产。

## 7. 拉起后端与前端

§5 的 `up -d --build` 已一并拉起；首次起栈的验收：

```bash
docker logs -f aiplatform-server     # 验收：Flyway「Successfully applied N migrations」
                                     # ＋「Started AiPlatformApplication」；pgvector 缺失会在 V1 响亮失败
docker exec aiplatform-server curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8888/actuator/health   # 200
```

curl 冒烟（服务器上或外网）：

```bash
curl -s -o /dev/null -w "%{http_code}\n" -H "Host: <域名>" http://localhost/                     # 主站 200
curl -s -o /dev/null -w "%{http_code}\n" -H "Host: <域名>" http://localhost/api/projects          # 401（无访客 cookie 的正确信封）
curl -s -i -H "Host: 9876543210.preview.<域名>" http://localhost/ | grep -E 'HTTP/|系统暂不可用'  # 死子域提示页
```

## 8. 浏览器冒烟（必须真浏览器——SSE 类问题 curl 抓不到）

1. `http://<域名或IP>/` 首页一句话需求 → 进项目页、访客态刷新保持（cookie 方案生效）；
2. 对话梳理 PRD：问答卡/直播进度卡正常出（SSE 通）；
3. 「确认此版 PRD 并生成 Demo」→ 预览窗打开 `http://{id}.preview.<域名>/`，系统渐进长出
   （工作区容器首次置备要几分钟；后端日志可见 docker 置备过程）；
4. 版本记录 →「查看当时」快照子域可开；死子域回自恢复提示页；
5. （可选）验证码登录：`docker logs aiplatform-server` 里读码。

## 9. 坑点记录（2026-10-29 实跑踩过，换机先读）

1. **阿里云个人镜像加速器 manifest 404**：`/v2/` 活着但对未缓存镜像的 manifest 直接
   404，所有 pull 报「not found」。→ daemon.json 里 DaoCloud 放第一位、阿里云加速器
   第二位兜底。
2. **compose 镜像名撞车**：同目录多个 compose、服务都叫 `app` 且没写 `image:` 时，
   构建产物都叫 `deploy-app`——后构建的把先构建的**覆盖**（症状：aiplatform-server
   容器里跑着 Next.js）。→ 每个 compose 显式 `image:`（已写进各 compose）。
3. **compose 项目名撞车删容器**：同目录 compose 共用默认项目名 `deploy`，服务同名
   `app` 时，后一个 `up` 会把前一个的 app 容器**停掉删除**（症状：起 web 后后端容器
   消失、/api 全 500）。→ 每个 compose 显式 `name:`（已写进各 compose）。
4. **ICP 拦截是异步的**：大陆机＋未备案域名 80 端口先实测 200 可用，约半小时后被
   拦。别用「刚测通」当长期依据；IP 直访不受影响。
5. **dev 镜像第一层 apt 卡死**：原 Dockerfile 的 tuna 换源在渲染层才做，第一层走
   debian 默认源，大陆机上 apt 子进程挂 15 分钟+（开发机构建有层缓存从未暴露）。
   → deploy 变体（dev-image.deploy.Dockerfile，跨架构通用）把换源前置到第一层且不还原。
6. **embedding 镜像 sed 注入变量名不一致**（`HOST` vs `EMBED_HOST`）→ 启动即崩重启
   循环。→ 构建期加 `grep -n EMBED_HOST` 自检（py_compile 查不出运行期 NameError）。
7. **Ubuntu docker.io 无 buildx**：`DOCKER_BUILDKIT=1` 直接报 buildx missing，回退
   经典构建器可用（慢、串行）；`apt install docker-buildx` 可补。
8. 仓内 `aiplatform-server/.env.production.example` / `aiplatform-web/.env.production.example`
   是旧部署遗物且带真实形态口令（已进 git 历史）——**勿参考勿复用**，清污＋轮换待办。
   另：开发机 `aiplatform-web/.env.production` 同为遗物（BACKEND_URL 指向不存在的
   `aiplatform:8081`）——**本机 `pnpm build` 会自动加载它把错值烤进产物**（2026-10-29
   实踩：本地对照构建 API 全 500），开发机构建前先挪走。
9. **线上「样式不对」（输入框发黑、气泡看不见）＝主题跟系统深色走**：next-themes 原配置
   `defaultTheme="system"`——本地 origin 记住 light、线上 origin 跟系统深色 → `.dark`
   token 生效 → 输入框容器（bg-background）变黑、气泡淡色在错主题下不可见（应用其余
   大量浅色硬编码 → 半拉子深色）。**修复：layout.tsx 钉死 `forcedTheme="light"`**
   （2026-10-29 已改）。定位过程的排除法（可复用）：线上 CSS 与干净生产构建
   chunk hash 逐字节一致（排除打包漂移）→ 最新内核无头实测线上颜色正确（排除产物
   损坏）→ 深色偏好仿真复现（锁定主题）。工具：`deploy/style-probe.mjs`。
10. **next dev 对非 localhost Host 的静态 chunk 请求回 403**：容器内无头访问开发服
    务器会静默缺 JS（页面壳在、不水合）——经 socat 把 Host 伪装成 localhost
    （`socat TCP-LISTEN:9333,fork TCP:host.docker.internal:3333` 后访问
    `localhost:9333`），见 style-probe.mjs 文件头。
11. **bind-mount 单文件 inode 坑（旧网关时代）**：`docker run -v` 挂单文件绑的是
    inode——宿主文件被替换（解包/编辑器）后容器内看到旧内容，reload 无效，必须重建
    容器。→ #386 起预览路由改挂 conf.d **目录**（目录挂载无 inode 问题、热更即生效），
    手工网关容器退役；教训保留于此，别再给共享 nginx 引入单文件 bind-mount 特例。

## 10. 无域名 IP-only 方案（含预览）

预览机制需要「任意子域解析到服务器」的能力，没有自有域名时用 sslip.io（免费泛解析
服务，把 IP 嵌进域名）：

- `PREVIEW_BASE=<IP 划线形>.sslip.io`（如 IP 1.2.3.4 → `1-2-3-4.sslip.io`），**不带端口**；
- `aiplatform.conf` 里 `semgravio.com` 替换成 `1-2-3-4.sslip.io`（预览/快照两处正则＋
  主站 server_name 一行）后重跑 §6 的门禁安装；
- `APP_WORKSPACE_PREVIEW_SCHEME=http` 覆盖照旧；主站走 `http://<IP>/`。
- 预览 URL 形如 `http://42.1-2-3-4.sslip.io/`。sslip.io 是第三方免费服务，大陆解析
  偶有不稳——不可用时换自有域名泛解析（本方案就是它的降级备胎）。

## 11. 日常运维

**换版上线＝一条命令**（开发机仓库根，Mac / Windows Git Bash 通用；PowerShell 里
`bash deploy/release.sh`）：

```bash
deploy/release.sh        # 打包 → scp → 服务器 infra 前置检查 → 备份 → 解包 → 退役旧网关 →
                         # 重建重启（server＋embedding → web）→ conf 经门禁安装 → 冒烟
```

它做的事（手动等价流程如下，出问题时可逐步拆开跑）：

```bash
# 开发机重打包 → 传服务器 → 覆盖 → 重建重启
deploy/build-bundle.sh
scp dist/aiplatform-deploy-*.tar.gz <user>@<IP>:
ssh <user>@<IP> 'cd ~/aiplatform && tar -xzf ~/aiplatform-deploy-*.tar.gz --strip-components=1 && \
  docker compose -f deploy/server.compose.yml up -d --build && \
  docker compose -f deploy/web.compose.yml up -d --build'
# 注意：解包不含 .env*（打包排除），现网 env 不会被覆盖 ✓
# release.sh 额外补的（§6/§11 手动流程没覆盖的）：
#   ① infra 前置健康检查——semgravio-{pg,redis,nginx} 缺失/不健康即中止，提示先跑
#      infra 起栈（平台是接入方，不负责替 infra 起栈）；
#   ② 旧预览网关容器（aiplatform-gateway）幂等移除——#386 起部署面不再有手工
#      docker run 特例；bind-mount 单文件 inode 坑的旧解法（重建网关容器）随网关退役消失；
#   ③ 平台 conf＋资产经门禁 install-nginx-conf.sh 重装（conf.d 目录挂载＝热更）。
# 连接参数（主机/账号/密钥/远端目录/INFRA_DIR）与开关（SKIP_BUILD=1 复用现包、
# SKIP_BACKUP=1 跳过备份）见 release.sh 头注释。

# 服务器侧日常运维小工具（thin ssh 封装，子命令见脚本头）
deploy/server.sh status            # 容器概览
deploy/server.sh logs server       # 跟后端日志（web/nginx/ws-<id> 同法）
deploy/server.sh restart           # 秒级重启 web/server（不重建；nginx 配置热更走门禁）
deploy/server.sh dump              # pg_dump 备份
deploy/server.sh smoke             # 主站 200 / API 401 冒烟（经共享 nginx）

# 日志
docker logs -f aiplatform-server     # 后端（Flyway/生成 run/验证码都在这）
docker logs -f aiplatform-web

# 停机 / 清库（infra 数据卷 independent——平台 down 不动 PG 数据；infra 停机见 deploy/infra/README.md）
docker compose -f deploy/server.compose.yml down
docker compose -f deploy/web.compose.yml down

# 数据库备份（平台无内置备份，自备 pg_dump；容器名跨迁移自适应口径同 server.sh dump）
PG_C=$(docker ps --format "{{.Names}}" | grep -xE "aiplatform-postgres|semgravio-pg" | head -n1)
docker exec "$PG_C" pg_dump -U aiplatform aiplatform | gzip > ~/backup-$(date +%F).sql.gz
```

本地客户端（dbx 类）远程连生产库：PG 绑宿主回环 5432，走 SSH 隧道两种姿势，
见 `docs/deploy/prod-db-access.md`。

**本地全栈排练**（改 conf/块文件/compose 后回归）：`STUB=1 deploy/rehearsal.sh`（快，
假 web 替身）或 `deploy/rehearsal.sh`（全栈真构建）——断言主站/注入/纯代理/资产单源/
提示页/redis requirepass（#386 口径）＋浏览器头组合探针（#396：`/_next` 非 403、
网关剥 Origin/非 `/_next` 透传，沙箱回显可观测）。

## 12. 转正式切换点（演示 → 生产）

1. **TLS**：平台 conf 的 server 块换 `listen 443 ssl`＋80 跳转（证书经门禁第三参装入
   `certs/aiplatform/`：一张多 SAN 证书 `<域名>`＋`*.preview.<域名>`，
   或云商免费证书；路径写 `/etc/nginx/certs/aiplatform/...`）；照旧走门禁安装，热更。
   **必须全站同形**：Demo 面板（system-panel）与快照（version-view-dialog）都是 iframe
   内嵌预览子域——https 主站 + http 预览的混合形态会被浏览器按混合内容**整块拦截**，
   不能只给主站挂证书。免费泛解析证书＝Let's Encrypt/ZeroSSL 的 **DNS-01** 验证
   （DNS 服务商支持 API 则全自动续期；手动加 TXT 则每 60–90 天续一次），HTTP-01 免费
   证书只能单域名、盖不住动态预览子域。
2. **删两个 http 覆盖**：`.env.production` 里去掉 `APP_WORKSPACE_PREVIEW_SCHEME` 与
   `SSO_COOKIE_SECURE` 两行（回落 jar 内 prod 值 https/true）；`PREVIEW_BASE` 去端口；
3. **SSO / backoffice**：接 identity 服务时补 `SSO_*` 七项＋`OPENAPI_APP_*`
   （`APP_REGISTRY_BASE_URL` 机机验签凭据源已免配置——prod 缺省即 webnet 容器名
   直发 `http://semgravio-app-registry:8088`，详见
   `aiplatform-server/docs/guide/生产部署.md` §7）；
4. **大陆机**：域名走 80/443 前完成 ICP 备案（拦截跟服务器地域走，见 §0）；
5. 备份转常驻 cron、日志收集、监控——演示期未做。
