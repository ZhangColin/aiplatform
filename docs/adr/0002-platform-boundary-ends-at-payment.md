# 平台止于支付完成

平台主链为「一句话需求 → BA 访谈 → PRD → 沙箱系统 → 迭代 → 确认下单 → 后台报价 → 支付」，**支付完成即业务边界终点**：订单与项目一并归档，交付/施工不在平台内——线下交付团队经后台机机接口（`/api/backoffice/*`）取 PRD 快照与源码包后接手，平台不回显施工进度、不管理交付过程。理由：平台的价值全部在「把需求变成可操作系统」的交易闭环；交付是重人力线下过程，纳入平台只会把边界拖进不可控的运营深水区。

## Consequences

- 订单终态为已归档，无交付态、验收态；支付成功即订单落「已支付」，订单归档 + 项目归档是支付后的独立步骤（归档失败不抹支付事实，补偿归后续批次）。
- 后台只需四个机机端点（列表/详情/源码包/报价改价），不做交付管理面。
- 用户在交付后的新需求 = 新项目新订单重新进入，归档项目不续用。
- 将来若把交付纳入平台，另起 effort 重开本决议。

依据：GitHub issues #1（Destination）、#4（下单报价支付决议）、#7（本篇落定）。
