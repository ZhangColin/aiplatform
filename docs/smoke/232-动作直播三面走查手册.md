## 一、当前动作行闪现节奏（AC1）

任一走查 run（§二~§五的 run 顺带看，不必单独造）：

| 观察 | 预期 |
|---|---|
| 动作发起瞬间 → 参数落定 | 直播行 label「运行命令」（参数在途，数秒）→ 命令原值，**原位换装一次到位**：不跳行、不重排、不闪烁 |
| 换装后至终态 | 不闪回「运行命令」；行高恒定单行 |
| 命令完成 | 直播行被下一动作接管，或退回解说尾区——**不残留** |
| 写文件动作 | 「编写【文件名】」语义不变（不回归检查） |
| （若有）问答挂起后续跑 | 已具体化的 label 不闪回通用标签（#228 review 修复项，顺带观察） |

判定：闪回 / 跳动 / 残留 → 缺陷票回灌 **#228**。

## 五、自测子智能体同口径抽查（AC3）

任一走查 run 的收口段（执行体委派 self-test；更新 run 同样有——编码 profile 第 8 条〔AgentProfile.java〕）：

- **直播原值**：自测的 execute 探活/测试命令（`curl http://localhost:8081…` 之类）原值上滚动行——与主任务动作同一行同一形态，无角色分叉呈现
- **成功无痕**：自测命令跑完不留静态残骸（逐项 ✅/❌ 以解说段呈现，非动作条目）
- **失败留痕**：自测探活失败（服务未就绪的 `curl` 失败是常见自然样本）同样留红行 label＋error。若本轮自测全绿无失败样本：自测与主任务动作走**同一生产路径**（AgentscopePartsMapper 不分 source），§四已验的失败红行即同代码路径佐证——在§七注明「无样本、同路径佐证」即可，不硬造

判定：自测动作不进卡直播 / 留残骸 / 失败无红行 → 按面回灌（闪现/label #228、error #229、沉没 #230）。
