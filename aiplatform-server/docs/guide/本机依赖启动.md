# 本机依赖启动（dev 环境）

> dev 环境约定：一台 Mac 手动起服务。端口分配——本服务 **8888** · 前端 3333 ·
> app-registry 8088 · identity 10001 · 平台 PG **5434** · embedding **9091**。
> 平台自身不用 Redis（会话内存态；沙箱容器的 pg/redis 在各工作区容器内，与平台无关）。

## 一条命令起数据面（平台 PG）

```bash
docker compose -f docker-compose.dev.yml up -d
# PG：aiplatform / aiplatform / aiplatform-dev @ 5434（pgvector/pgvector:pg16，内置 vector 扩展）
```

PG 端口为什么不复用本机已有的：

| 端口 | 是什么 | 能否共用 |
|---|---|---|
| 5432 | 共享 aieducenter 库（Homebrew PG 18，无 pgvector） | 否——无 vector 扩展，且与其他业务库混放 |
| 5433 | 冻结 demo（deepseek-harness）的库 | 否——demo 是参考基准，不动它 |
| 5434 | **本服务平台 PG**（pgvector/pgvector:pg16） | 是 |

数据卷 `pgdata` 持久化；要重来就 `docker compose -f docker-compose.dev.yml down -v`
后重建空库（Flyway 会从 V1 重新跑；改已应用的迁移必 DROP SCHEMA 重建，见库重置口径）。

## embedding 服务（9091，base.knowledge 依赖）

本机 fastembed（BAAI/bge-small-zh-v1.5，512 维）。极简服务脚本已收进本仓库
`scripts/embedding_server.py`（零框架依赖，接口 `POST /embed {"texts":[...]} → {"vectors":[[...]]}`）：

```bash
uv run --with fastembed python scripts/embedding_server.py
curl localhost:9091/health                            # → {"ok":true}
```

**`/health` 200 不代表模型可用**——模型在首次 `/embed` 才触发加载，缓存缺失时加载
失败、服务照常 200（症状：embed 调用挂死或报 `Could not load model`）。起完先打一发
验证：

```bash
curl -s -X POST localhost:9091/embed -H 'Content-Type: application/json' -d '{"texts":["验活"]}' | head -c 80
```

网络连不上 HuggingFace 时（fastembed 走 hf-xet 传输，对直连环境常见超时），可用
hf-mirror 手工预置模型缓存后离线启动（**不预置直接起会连 HF 下载挂死**）。
当前 fastembed 版本的缓存布局（2026-09-01 实测）：缓存根在 `$TMPDIR/fastembed_cache`
（macOS 下非 `/tmp`），模型为**平铺目录** `fast-bge-small-zh-v1.5/`（非 HF snapshots
布局），内放五个文件：

```bash
DST="$(python3 -c 'import tempfile;print(tempfile.gettempdir())')/fastembed_cache/fast-bge-small-zh-v1.5"
mkdir -p "$DST" && cd "$DST"
for f in config.json tokenizer.json tokenizer_config.json special_tokens_map.json model_optimized.onnx; do
  curl -L -O "https://hf-mirror.com/Qdrant/bge-small-zh-v1.5/resolve/main/$f"
done
# 之后带 HF_HUB_OFFLINE=1 启动（从缓存离线加载，不碰 HF）
```

注意：`mvn test` 的知识语义命中测试（`KnowledgePortSemanticTest`）需要本服务**模型
可用**在跑——没起时该测试跳过（不失败）；起了但模型加载失败则**失败**（检索恒空）。
其余测试只依赖 PG。

## 起服务与验收

**凭据只落本地，不进 git**：`.env.local` 建在**仓库根**（已 gitignore）。SSO 四项之外，
**智能体模型 key 也随进程注入**（AgentScope ModelRegistry 读环境变量，缺了 BA/编码
run 首帧即报 `DEEPSEEK_API_KEY is required`——2026-09-01 实测踩坑）：

```bash
# .env.local（示例，勿提交）
SSO_CLIENT_ID=<app-registry 发放的 client_id>
SSO_CLIENT_SECRET=<app-registry 一次性发放的 client_secret>
SSO_ACCOUNT=<identity 测试账号 email>
SSO_PASSWORD=<identity 测试账号密码>
DEEPSEEK_API_KEY=<DeepSeek 平台 API key>
```

在 `aiplatform-server/` 下起服务（凭据在仓库根，`source` 注意相对路径）：

```bash
set -a; source ../.env.local; set +a   # SSO_* + DEEPSEEK_API_KEY 随进程注入
mvn spring-boot:run                     # 默认 local profile → 5434/aiplatform
curl localhost:8888/actuator/health
```

> **IDEA 启动**：IDE 不读 `.env.local`——SSO 变量须加进 Run Configuration →
> Environment variables（或装 EnvFile 插件勾选该文件）。漏注入的症状：BFF 302 出去
> `client_id=` 为空 → identity 报 `unauthorized_client: client_id 缺失` 跳 `:10002/error`。

swagger（前后端唯一契约，ADR-0001）：`http://localhost:8888/swagger-ui/index`，
分组按 BC（workspace / eventhub / knowledge / metering / project / order / identity
七组）；`/v3/api-docs` 供前端取契约（`pnpm gen:api`，需本服务在跑）。

交易环后台联调（报价/改价/源码包，机机签名无页面入口）：`./scripts/backoffice-quote.sh`
（凭据走本机 app-registry 8088，secret 未设时自动现取；用法见脚本头注释）。

测试：`mvn test`（语义测试依赖见 embedding 节）；**验证编译用 `mvn clean test-compile`**
——本仓增量编译会误报 "Nothing to compile"（假绿，改动未真正编译）。

## A2 登录联调（identity OIDC + BFF）

认证走 identity 服务（`identity.localhost:10001`）授权码模式，本服务 BFF 三端点
（`/auth/login`、`/auth/callback`、`/auth/logout`）+ `/api/me`。本地纪律：**全程
`localhost`，禁混 `127.0.0.1`**（cookie 按域隔离不分端口，host 不一致 cookie 带不过、
identity 白名单精确匹配会炸）；`sso.cookie-secure=false`（http 下 Safari/Firefox
拒存 Secure cookie）。

冒烟登录（cookie-jar 走完整授权码链，供后续 `curl -b` 验收；凭据从环境或仓库根
`.env.local` 读——**先 source 再从 `aiplatform-server/` 跑**）：

```bash
set -a; source ../.env.local; set +a
./scripts/login.sh                  # 默认 jar 在 /tmp/aiplatform-cookie-jar
curl -b /tmp/aiplatform-cookie-jar localhost:8888/api/me     # → {accountId, displayName}
```

- 无会话访问 `/api/**` → 401（统一信封）；`/auth/**`、`/api/backoffice/**`（HMAC
  机机签名）、swagger、actuator 可匿名可达。
- 服务重启 → 内存会话丢失 → 再走一次 `login.sh`：identity 侧 SSO 会话仍在，**免密码**
  直通回调（浏览器同理由 middleware 302 到 `/auth/login?returnTo=…` 弹回一次）。
- 登出：`curl -X POST -b jar localhost:8888/auth/logout` → 302 identity 清 SSO 会话后
  回 `http://localhost:3333/`（`post_logout_redirect_uri` 独立白名单）。
- identity 联调注意（2026-08-22 实测，③ 为 08-31 补）：① identity 本地未配 PEM 密钥，**每次重启换临时
  密钥而 kid 固定**，本服务 JWKS 缓存 24h 只按「kid 未命中」重拉——identity 重启后本服务
  **也要跟着重启**（顺序：先 identity 后 8888），否则验签静默失败（`/?error=exchange_failed`）。
  ② identity id_token 的 `aud` 灌的是其全局 `identity.token.jwt.audiences`（「按 client_id
  覆盖 aud」是其 Phase 2 未落项）——本地已在 aieducenter-identity 的 application-local.yml
  把本平台 client_id 追加进 audiences 兜底，identity 侧正修落地后可撤。③ **去 app-registry
  取 client 凭证（POST credentials）会重置 secret**——取完后在跑的 8888 还持旧 secret，
  `/token` 报 401 `invalid_client`（日志 IDN_003，页面仍 `exchange_failed`）。取完凭证必须
  `source .env.local` 重启 8888。
