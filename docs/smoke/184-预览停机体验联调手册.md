## 一、停留页面 → 闲置休眠回收 → 点刷新（AC1）

| 步骤 | 动作 | 预期 |
|---|---|---|
| 1 | 前端 3333 打开「轻简待办」项目页，确认预览活、标题「待办清单」 | — |
| 2 | 另开终端挂计时器 `./scripts/preview-wake-timer.sh <wsId>`，然后页面放着不动 | ~3 分钟＋一个扫描轮（≤40s）后计时器翻 **502**（闲置休眠发生）；后端日志见休眠行；预览区**还挂着旧画面**（iframe 不自己刷新——这正是体验线的问题起点） |
| 3 | 回到页面，**记下钟点**，点预览区刷新按钮 | iframe 重挂 → 网关提示页：「系统暂不可用，可能正在启动或休眠中」＋ 转圈（浅色平台风格）；**全程无需整页 F5** |
| 4 | 不碰页面，等着 | 后端日志见唤醒行；计时器翻 **200** 打「← 上游恢复」钟点；此后 ≤2s 提示页自轮询命中、iframe 自动重载回真系统 |
| 5 | 核对数据点 | 标题「待办清单」在（卷保留，数据不动）；把「触发钟点 → 可用钟点」记进§六 |

## 二、对话区提交触发恢复（AC2）

前置：§一结束后项目是运行态、页面继续开着。若已过 3 分钟又被休眠，先 `wake` 回来并**立刻刷新一次项目页**（拨 last-touch，否则下一扫描轮又睡）。

| 步骤 | 动作 | 预期 |
|---|---|---|
| 1 | `./scripts/backoffice-workspace.sh hibernate <wsId>` 秒级就位休眠（**页面保持开着**，预览区仍旧画面） | 计时器翻 502；`detail` desired=2 |
| 2 | **记下钟点**，对话区提交一条会改页面的消息（如「页面标题改成 待办清单 Pro」） | touch 先行异步唤醒（后端日志见唤醒行）；run 起动、过程区可见 |
| 3 | 不碰任何刷新，等 run 收口 | 预览区联动恢复：run 收口预览纪元驱动 iframe 重挂 → 显示新标题「待办清单 Pro」；期间若 iframe 先落提示页则就绪自动回来（与§一同机制） |
| 4 | devtools Network → EventStream（SSE 流） | 见 `preview-ready` 事件（#183 补推的首个真实验证——唤醒完成即推、非 15s 轮询兜底）；把提交钟点 → 预览显示新内容钟点记进§六 |

## 五、就绪后经网关的 502 窗口（AC5，DNS 收紧实效）

在§一/§二/§三任一轮顺带观察，不单独造场景：

- 口径：**后端就绪时刻**（devtools EventStream 的 `preview-ready` 时间戳，或后端日志唤醒收口）与**计时器翻 200 时刻**的差值
- 预期：**数秒级**（`resolver valid=5s`——旧值 30s 时这个窗口就是「后端好了浏览器还是 502」的元凶）
- 判定：≤5s 达标；≤10s 可接受（记备注）；>10s 开缺陷票回灌 #181
