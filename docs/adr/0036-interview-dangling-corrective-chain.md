# 访谈悬空收口纠偏链（ADR-0032 修订）

2026-11-10 生产定案（issue #445）：flash 档模型在部分新会话（近 14 天约 15%）开场不走 ask_user 工具、全程纯文本提问。ADR-0032 契约把这种格式失格与轮死同形观测为悬空并如实播报，但**无任何纠偏环节**：首轮坏示范被后续轮沿会话上下文自模仿延续（会话级锁定），用户说「继续」也救不回——新项目「所有问题都没有选项」、紧跟「上一轮没有正常完成」的体感均源于此。

决定：用户轮悬空命中时**不立即播报**——先走平台自动纠偏链，把格式失格在会话锁死前扳回工具轨道：

1. **纠偏轮①**（平台轮，不入 ADR-0032 契约、不递归）：主智能体生效档（flash 为主，库值优先缺省回落同对话轮）＋确定性微指令——提问形令「经 ask_user 重新提问」、savePrd 失败形令「重新调用 savePrd」。成功判据＝ADR-0032 合法收口形两形（挂起问答在场或 PRD 已产出）；
2. 仍失格 → **纠偏轮②升强档**：路由面生效值（`routingStrongModelId`，缺省 pro，运营可换不发版）＋同款微指令；
3. 双失格 → 才置悬空标记＋泛形/点名播报＋接管（ADR-0032 现行兜底原样）。

约束：封顶两轮防烧 token；`routingEnabled=关`（纯人工定档运营姿态）跳过②、①失格即播报；每轮新 runId、走会话执行器串行、回复照常落对话史。**轮失败（异常收口）不经纠偏链**——catch 侧 `remedyFailedInterviewTurn` 即时点名播报不变（环境性失败重试照样失败，ADR-0032 原 rationale 保持）。

同批两件护栏：**空问题护栏**——ask_user `input={}` 畸形挂起（内核未拦 required，生产实录空白问答卡）平台自动以错误结果答复该工具调用（metadata 通道同用户答复口径），模型当场重问、不渲染残卡，呈现面另有兜底文案；**协议明示条款**——MAIN 工作协议补「提问必须经 ask_user，禁止正文提问」＋规则复述（零成本降触发率）。

## Considered Options

- 主智能体直接改档 pro（出局：用户裁决 flash 为平台主档——速度快、体验好；且 pro 亦无法确保格式遵循，治本须结构保证）
- 纠偏轮只升档不加微指令（出局：纯换模型不告诉它错在哪，重犯概率高；微指令教规则＋令重问，确定性纠正信号同时打断会话自模仿）
- 无限纠偏直至合法收口（出局：烧 token 无界——ADR-0032 当年否决自动重试的核心顾虑；封顶两轮＋双失格播报即有界兜底）
- 命中即播报同时后台纠偏（出局：播报先于救回，用户先看到「上一轮失败」的坏体验；救回成功则不播报才符合「如实但不惊吓」）
- 平台重建问答卡承接正文提问（出局照旧：ADR-0032 已否决——问答卡语义绑 run 挂起，让模型自己重问更省机制面）

## Consequences

- ADR-0032 的「不做自动重试」结论被限定于**环境性失败**；格式性失格（纯文本提问、savePrd 未落成、空 input 畸形调用）由纠偏链结构性兜底。
- 「flash 为主、做不到升 pro」成为平台总姿态（与执行体路由 ADR-0030 同构）：pro 只在 flash 实证失格时被点名出场——②的救援率天然成为两档格式遵循差的对照量化口径。
- 悬空补救文案的出现概率从「失格率」降为「失格率 × 纠偏失效率」（两个小概率的乘积）；即便命中也不再是会话级死循环（接管机制原样兜底）。
- 正常路径（合法收口的轮）零新增延迟与成本——纠偏链只在契约命中时启动。
- 观测面建议（非本 ADR 阻塞项）：后台补纠偏轮触发率/救援率看板，长期量化失格率与档位差。

## 补记（#462 去确认门，2026-11-11）

**统一纠偏微指令（用户裁决）**：纠偏轮①②不再按失格形分形选指令——`CORRECTIVE_REDIRECT_PROMPT` 一条覆盖「正文提问」与「说可出 PRD 但未调 savePrd」两形（不解析自由文本，规则分类器非 flash 档的偏差口径由①②同指令抹平）；prdSaveFailed 事实不再选指令、只进最终播报文案分形（点名/泛形）。背景：平台无可观测「说可出 PRD」结构化信号（#450 决策正本＋协议文本双重确认），解析自由文本属投机面；统一指令与「产出即自动推进」的去门化姿态同向（救回路径指向同一合法出口两形：ask_user 或 savePrd）。
